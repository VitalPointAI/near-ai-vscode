# Platform direction research (2026-11-15 and 2026-11-16)

Source-level reviews of three agent projects, read but never run, and the recommendation the owner accepted on 2026-11-15. The decisions taken from them are recorded in `.planning/PROJECT.md` under "Platform direction", and the plan built on them is the v0.7.0 section of `.planning/ROADMAP.md`.

| File | What it is |
|------|------------|
| [Architecture recommendation source (HTML)](https://github.com/VitalPointAI/near-ai-vscode/blob/main/.planning/research/platform-direction/summary.html) | The accepted recommendation: keep our TypeScript engine, take IronClaw's capability and authorization design, Hermes's workflow ideas reshaped to pass a DID policy gate, and OpenShell as the sandbox; build order, what not to copy, and the Theia container appliance. |
| [ironclaw-analysis.md](./ironclaw-analysis.md) | IronClaw (NEAR AI, Rust): capability manifests, credentials injected at the boundary, staged authorization, restrict-only hooks, run guardrails, channel manifests and two-step pairing, and why a fork is not recommended. |
| [hermes-analysis.md](./hermes-analysis.md) | Hermes Agent (Nous Research, Python): delegation that only narrows, request-bound approvals, schedules, learned skills as proposals, the package lifecycle, and why its in-process plugins fail the single-gate test. |
| [openshell-analysis.md](./openshell-analysis.md) | NVIDIA OpenShell (Rust, CNCF): kernel-enforced sandbox, policy YAML and the policy prover, credential placeholders, OCSF audit, and how a DID's sandbox section compiles to an OpenShell policy. |
| [openshell-spike.md](./openshell-spike.md) and [openshell-spike/](./openshell-spike/) | The OpenShell spike approved on 2026-11-15 (OpenShell 0.1.8, Linux, rootless Podman): 20 of 20 escape cases against the key folder blocked, egress limited to the declared host, method and binary, a fake credential injected only on its bound endpoint, and the prover rejecting widened children (file paths come back `unsupported`, so policies use a fixed path vocabulary). Main finding: downloads keep symlinks, so the apply step must treat the copy's changes as untrusted. Also timings, platforms, GPU and arm64 notes. The folder holds the policies, draft DID documents (placeholder keys only), test scripts and logs. Phase 72 is planned from it. |
| [identity-research.md](./identity-research.md) | Identity, credentials, clearance and NEAR confidentiality (2026-11-15): what NEAR's Confidential Intents private shard can and cannot hold today (no third-party contracts or data), why `did:near` is not used, `did:key` for agents and machines and `did:webvh` for people and your organization, a narrow W3C VC 2.0 profile with `eddsa-jcs-2022` and Bitstring Status List on `node:crypto`, classification labels with clearance dominance and routing tiers, roots-only anchoring, offline verification at the edge, and twelve open risks. The owner approved the design built on it the same day (PROJECT.md, Platform direction decisions 8-13). |
| [calimero-evaluation.md](./calimero-evaluation.md) | Calimero Network as a private layer for identity and governance (2026-11-15). Result: not now. Calimero removed all NEAR integration (0.10.1-rc.9, 2026-03-25) and its peer-to-peer sync (1.0.0-rc.1, 2026-10-28); 1.0 is a release-candidate confidential cloud on Intel TDX servers with no LAN or offline groups, no NEAR anchoring, only an insecure dev mode on AMD Strix Halo and NVIDIA GB10, a TypeScript client with runtime dependencies and no independent audit. Revisit only if HQ moves onto Intel TDX hosting and Calimero ships a stable, audited 1.0 that supports our hardware. Also recommends encrypting Team Mode event payloads to member device keys over the existing git transport. |
| [agent-authz-prior-art.md](./agent-authz-prior-art.md) | Prior art for the agent authorization architecture (2026-11-16), web research only: capability and delegation systems (Macaroons, Biscuit, ZCAP-LD, UCAN 1.0, SIWE ReCap, Ceramic sessions), on-chain registries that gate off-chain access (Lit Vincent, NEAR Shade Agents, Hats Protocol, FairAccess, BlendCAC), NEAR function-call access keys and NEP-413, AI agent authorization standards and products (MCP authorization 2025-11-25, IETF drafts, KYA-OS, Entra Agent ID, OpenShell and IronClaw brokers), classification labels and model routing, what is standard practice and what was not found, what to borrow (UCAN invocations, receipts and revocation, ERC-7715 and ERC-7710, MCP audience binding, RFC 9421) and thirteen risks (public key lists, NEP-413 needing a full-access key, an empty method list meaning every method, key sprawl, revocation latency, the key-adding power, the broker as a single point of failure). The owner's decisions built on it the same day are PROJECT.md, Platform direction decisions 14-17: function-call keys for on-chain calls only, off-chain capabilities in private credentials. |
