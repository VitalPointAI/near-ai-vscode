## Consequences and notes

One identity per person (D-28, accepted by the owner). Each person has one Ed25519 device key per install, so one device fingerprint per person appears in the signed log of every team they join, readable by anyone who can read the project's remote. The same fingerprint therefore links a person across teams and projects. A per-team derived key was not added: it would change `team.json` and the roster. No sentence in the Enable flow says this yet, so L2 should add one plain sentence to the confirmation.

On a shared code-server one install can mean one identity for several people, because the identity is per install and the user profile of a shared code-server is shared. This is not solved in Phase 69. SHRD-02 (a recovery code that unlocks an encrypted backup of the person's device key and own NEAR AI key) and SHRD-03 ("Replace my device", where the lead accepts the person back as the same member) own it. Phase 70 must not assume one person per install.

The key becomes a `did:key`: PROJECT.md decision 10 (owner-confirmed 2026-11-15) makes the device key's Ed25519 public key the `did:key` identifier for agents and machines, and `did:webvh` is for people and your organization's root. There is no `did:near`. Phase 69 signs with the key and records its fingerprint; it does not publish a DID.

The per-team key name of the archive (`nearAi.team.deviceKey.<teamId>`) never shipped, so nothing migrates from it.

A local key rotation through the Phase 69 helpers binds the new key in no team roster, so the person is read-only in each team until L2's "Replace my device" flow (with Phase 71) appends a `device.rotated` event signed with the kept previous key, and revoking that previous key first leaves an owner-only team with no key able to sign that event, which L2's flow has to prevent or recover from (D-09, D-13).

`TeamLog.verifyAll` in `src/team/eventLog.ts` still reports each device as only `{ fingerprint, revoked }`, so a rotated key looks active in that report. Read `teamKeyStatus` (`src/domain/team/keyStatus.ts`) for the real state, which also reports `rotated` with the time and the replacing key.
