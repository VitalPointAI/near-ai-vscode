# Canadian English and French in SovAI

The Canadian profile requires English (Canada) and French (Canada) across SovAI. A user can change languages without leaving the Workbench or restarting a session. The display preference is user-scoped, persists across visits and defaults to Canadian English if no supported preference exists. Changing it leaves shared project and organization settings intact. The output language belongs to the product request and can be changed independently. Approved shared products have both language versions available to authorized readers.

## Product acceptance

| Surface | Required behaviour |
| --- | --- |
| Interface and setup | Switch between `en-CA` and `fr-CA` in Settings during a session. Apply the locale to native Workbench, extension panels, onboarding, administrator and hub screens, help and validation. Keep the current project, selected record and keyboard focus. Translate accessibility labels, errors, warnings and empty states. |
| Agent outputs | Let users request English or French drafts and view either rendition of a shared product. Canadian release workflows require equivalent approved versions. Preserve headings, tables, citations, accessibility content, figures, units, dates and meaningful qualifications. Record when one rendition is pending or outdated. |
| Documents, search and graph | Preserve the original and its exact source citation. Store a translation as a linked rendition with its own language, source revision, model version, glossary and review state. Enforce source access and retention on derived renditions, caches and search results. A source correction makes both affected renditions stale for current use. Retain the previously approved pair with a historical label and inherited access. Publish a current pair only after both new exact revisions are approved. |
| Approval and exports | Review the exact English and French revisions for equivalence and record the person who approved them. Require professional translation review for high-impact federal releases where applicable. Export the selected rendition or an accessible bilingual package. Preserve the revision links and all original evidence. |

The Official Languages Act addresses communications and public services in Part IV and federal language of work in Part V. Section 36 includes frequently used computer systems and work instruments within its prescribed scope. SovAI's Canadian product requirement applies across the Canadian profile. The institution determines its legal and policy obligations for the deployment. The Treasury Board's April 29, 2026 notice directs covered institutions to use GCtranslate for routine internal assistance on supported devices once available, up to Protected B. It also requires professional review for high-impact translations. Treat GCtranslate as a possible institution-approved route only where access and the workflow are authorized. ## Translation evaluation

Start with a Canadian English and French evaluation on a small set of public and fictional records. Use Google's Apache-2.0 MADLAD-400 3B translation model as the first offline benchmark candidate. Compare it with Cohere Command A Translate and North Small Translate only under suitable test terms. Both Cohere public weight releases are non-commercial. Command A Translate offers private deployment, and the published hardware for both Cohere translation models is datacentre-class. Confirm commercial terms, exact format and the approved host before selecting a deployable model. Compare only exact model artifacts admitted to the test environment. [Google MADLAD-400 model card](https://huggingface.co/google/madlad400-3b-mt) · [Command A Translate model card](https://huggingface.co/CohereLabs/command-a-translate-08-2025) · [Cohere private deployment](https://docs.cohere.com/docs/command-a-translate) · [North Small Translate release and licence](https://docs.cohere.com/v2/changelog/north-small-translate-1-0)

Use a bilingual professional to evaluate both directions on Canadian terminology, mandatory and discretionary wording, negation, names, numbers, units, dates, citation preservation and accessibility. Record critical errors separately from fluency. Inform the reviewer when a language pair or format lacks verified support. Keep a separate approved model passport for each selected version and record its exact artifacts, evaluated language pairs, permitted data level and deployment route. A protected source goes only to an approved deployment that can handle its classification. An unavailable approved model leaves translation pending for a person. [TERMIUM Plus](https://www.btb.termiumplus.gc.ca/tpv2alpha/alpha-eng.html?lang=eng) · [Model Factory roadmap](../ROADMAP.md#phase-98-model-factory-v1-first-specialist-from-chat-and-run-logs)

### First evaluation fixture

Four [fictional administrative pairs](canadian-translation-fixtures.json) exercise obligations and exceptions, dates and quantities, an original quotation with an exact source citation, and labels and assistance in a simple HTML form. Use each locale as a source in a fresh model session. A bilingual professional must review both source versions and the rubric before the trial. Freeze the reviewed revision, then use Model Factory evidence to hash the canonical source-only inputs and the separately held reference and rubric. Give each candidate only the source, target locale and approved glossary. Keep the reference and rubric out of tuning and candidate prompts.

Record meaning, Canadian terminology, fluency and applicable structure separately for each direction. Accept equivalent phrasing and locale formats. Require exact listed literals in their expected context, including the words of the original quotation in either direction. Parse the form as data and check the submitted field name, required state, label and help associations and submit control. Count omissions or changes to obligations, exceptions, negation, values, source references and required form behaviour as critical errors. Any critical error fails this first fixture. Record the number evaluated in each direction alongside the results. The fixture checks workflow readiness. A larger reviewed set is required before approving any language pair or format. Link the evidence from the existing exact-model passport evaluation field.

See Phase 102-10 for the exact legal and institutional policy fixture tests. [Special Staff duty catalogue](staff-teams/13-staff-personnel-resources-and-special-advice.md#personal-and-special-staff)

Reuse the translation service for authorized non-operational J2 document intake and reporting. Preserve the original language, individually cited source passages and uncertain wording. Expand beyond English and French by validating each offered language pair and document format. Route unsupported or uncertain material to a qualified reviewer. Translation remains a derived record under the original source's access and classification.

## Delivery order

1. Define the shared locale and translation contracts. Prove switching on one normal Workbench surface and an existing settings path. Build a bilingual glossary and an exact paired public or fictional acceptance corpus.
2. Roll out source-controlled interface and documentation translations to Workbench, setup, administrator surfaces and exports. Use a native bilingual reviewer and check the full Canadian experience on each supported platform.
3. Evaluate and approve translation adapters through the Model Factory evidence and passport process. Add versioned renditions and a human review loop to one existing staff draft, then extend that contract across eligible products and J2 document intake.
4. Verify branch and role coverage, offline use, policy denial and both-language equivalence before marking the Canadian deployment ready.
