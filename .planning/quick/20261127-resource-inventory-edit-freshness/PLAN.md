# Resource Inventory catalogue edit freshness

Base `49b305a5724a48818d66e005ff9943187ddc9816`. The offline Resource Inventory editor rereads the catalogue on Save but checks only its ETag. The FileService ETag can miss a same-length replacement with the same timestamp. The update then copies values from the stale dialog onto the newer entry. The existing work-area resource-link writer demonstrates the byte comparison used by its local write path.

1. Add focused coverage to the existing Workbench inventory test surface. Use a FileService fixture with fixed size, timestamp and ETag. Reproduce a same-length byte replacement after display and a replacement during save preparation. Require both to refuse with no write. Verify the unchanged source still accepts the edit and preserves unrelated properties. Keep the save logic on one path used by the widget and the tests.
2. Bind the dialog to the exact bounded bytes from which its visible record and catalogue snapshot were parsed. Retain that byte snapshot with the active connection and invalidate it whenever the displayed catalogue is cleared. Capture it on opening the dialog and keep it distinct from a later polling result. On save, compare the raw current bytes against that captured snapshot before using the file as the update base. Re-read and compare again at the guarded write boundary. Preserve the regular-directory, file type, size, current connection/trust and final FileService ETag/mtime checks. Preserve the existing cancellation, add, edit and archive/restore paths and unknown JSON fields. This detects stale edits within the existing write boundary. FileService provides no atomic byte-based compare-and-swap against another process after the last read.
3. Run only the focused catalogue and neighbouring resource-link checks plus Workbench type checks under the shared memory cap. Record independently reviewed verification in a quick SUMMARY.
