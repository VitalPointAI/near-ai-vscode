Written 2026-11-24 for the owner's rule that a release must not silently drop UI the owner reviewed in a local preview.

| | Owner's preview | Release candidate |

| Container | `sterling-theia-defence`, http://127.0.0.1:18878 | `sterling-candidate`, http://127.0.0.1:18881 |

Both were driven by the same read-only Playwright walk (the repository's `playwright-core` 1.65.0, Chromium headless, 1600×1000). The webview pass opened both at `localhost`, because Chromium serves the `<uuid>.webview.localhost` hosts from loopback. No Create, setup or link action was pressed in the owner's container. A second candidate container, `sterling-candidate-evidence` on port 18882, carried a readable copy of the same evidence projection the preview mounts, and trusted its workspace, to compare Compliance, Portfolio Room and Resource Inventory like for like.

Screenshots are in the session scratch directory under `shots/r0439-preview/` (`p39prev-*`) and `shots/r0439-candidate/` (`p39cand-*`), with a `*-notes.json` text record for each run.

**State differences that are not product differences.** The preview's workspace holds one work area, "Op CRAZY ANIMAL", so it shows "Open work area: …" on Get Started and a row under Planning's Local work areas; the candidate's workspace is empty. The candidate's status bar shows **Restricted Mode** and **Secrets are unavailable** because it runs with no secret store (46-07), which the older preview image predates.
