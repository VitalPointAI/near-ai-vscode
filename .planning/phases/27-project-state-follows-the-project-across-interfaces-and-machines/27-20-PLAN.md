<objective>
Close G-27-6a: in the real GitHub run the first push into the empty repository was near-ai/state, so GitHub made the encrypted sync branch the default and a plain clone checked out manifest.json and .bin files (src/services/onlineHome.ts:335-341; pushProjectCode never sets the default). Make the first branch an empty-of-data front branch (near-ai/home) whenever sync is turned on against a remote with no branches, and on the GitHub routes correct the default through the API: near-ai/state never stays default, and once the person's code is pushed their branch becomes default unless they chose another one.

Purpose: D-01 says the sync branch is never main and never mixed into work; D-14 says nothing of the person's code goes up without the separate checked step. The smallest safe mechanism that satisfies both without touching the person's history or forcing anything: a fixed one-file branch pushed first (it contains none of their code), and an API default change limited to moving away from branches the extension created.
Output: StateTransport.ensureFrontBranch and constants, StateSync passthrough, the call in finishTurnOn, githubApi default-branch read and setDefaultBranch, moveDefaultBranch in onlineHome.ts, COVERAGE.md rows, src/test/syncFrontBranch.test.ts and new onlineHome.test.ts cases.

Recorded choice (planner, within the owner's options for G-27-6a): the front branch is a separate branch named near-ai/home rather than the person's branch name, because a commit on their branch name would diverge from their own history and their later push would be refused unless forced; a separate branch needs no force and never touches their repository. It is left in place after their code is pushed (its README text stays true), because deleting it would be a repository change with no benefit.
