Once 0.4.20 pushes a bundle to a public repository, that ciphertext stays in git history for good, so its protection is fixed by these values. Changing them later means every machine must still read the old format.

Proposed contract:
1. Ref `refs/heads/near-ai/state` on the project's remote (D-01 working name), never `main`.
2. Recovery code: 160 random bits, 32 Crockford base32 characters, shown as 8 groups of 4 (`XXXX-XXXX-...`). Typing tolerant (case, spaces, hyphens, I/L as 1, O as 0).
3. KDF scrypt N=2^17, r=8, p=1, 16-byte salt, 32-byte key, recorded in the manifest as `kdf` so it can be raised later.
4. AEAD AES-256-GCM, 96-bit IV, 128-bit tag. Per-object key from HKDF-SHA256(data key, 16-byte object salt, info `near-ai/state/v1/object`). AAD `near-ai/state/v1|<stateId>|<class>`.
5. Object file: magic `NAS1`, version byte 1, object salt, IV, tag, ciphertext. Plaintext = 4-byte true length, brotli (quality 5) JSON, random padding. Padme buckets (8 per octave) with a 64 KiB floor, split into 8 MiB parts.
6. `manifest.json` is the only plaintext file. Its plaintext fields are `format` (1), `stateId` (random), `kdf`, `wrappedKey`, `sealed`. `sealed` opens to `{ seq, objects[], indexFile }`. The tree holds only `manifest.json` and `<32 hex>.bin`.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-01 | Information disclosure | recovery code vs public ciphertext | high | mitigate | 160-bit generated code; scrypt N=2^17 per guess (Task 2); code never user-chosen |
| T-27-02 | Tampering | objects and manifest | high | mitigate | AES-GCM tags, sealed list with sha256 and byte counts verified before decrypt (Task 3) |
