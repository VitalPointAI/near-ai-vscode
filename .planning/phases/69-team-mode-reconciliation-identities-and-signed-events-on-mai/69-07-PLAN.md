Then prove the whole Team Mode surface of PR 1 in a real VS Code window with an extension-host e2e test, which stands in for the owner trying a PR build (D-30).

Purpose: Phase 70's first policy bundle on a fresh install, Phase 71's one persistent identity per member and Phase 80's signed answers all need a person-level key (TMR-05). This lands in PR 1 so the per-team key name never reaches main or a release; see the recorded choice in 69-01-PLAN.md. D-07 stays a rule; D-28 (one fingerprint visible on the remote, shared code-server installs) is recorded by plan 14. The owner will not try Team Mode from a PR build (D-30), so the e2e test is what shows Enable (behind the preview) and Verify Team Log (name kept, D-31) work in a real window before PR 1 merges; it lands here because the commands and preview gate (plan 06) and the per-person identity (Tasks 1 and 2) are now all in place, and 08 and 06 already have three tasks.
Output: re-keyed `src/team/identity.ts`, Enable and session callers, adapted helpers and tests, new D-22 and race tests, and the Team Mode e2e tests with their test-only hooks.
</objective>
