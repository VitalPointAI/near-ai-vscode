`keyRecords.ts` (pure, D-09): the types and constants in artifacts_produced. `replayKeyHistory(file, head)` accepts only `{ version: 1, records: [...] }` with at most `MAX_KEY_RECORDS` records and walks them in order: `seq` counts from 1 with no gap; `prev` is `''` for the first record and otherwise `keyRecordHash` of the previous record; each record's payload `at` equals its envelope `signedAt`; each record must pass `verifyPayload(record, { purpose: 'key-record', status })` where `status` answers `active` only for the key allowed to sign that record and `unknown` for every other key. In this task implement `created` (allowed only when no key is active; `key` must equal the signer; the key becomes active). Any failure returns `{ ok: false, reason, lookup: NO_KNOWN_KEYS }` with a plain reason. A non-empty history with no head, a head that does not equal the last record's `seq` and hash, or a head with an empty history fails. The returned lookup answers from the replayed key states and gives `unknown` when the public key does not match the recorded one.

`keyHistory.ts` (I/O): `readKeyHistory` reads `<identityDir>/key-history.json` (absent means no records; larger than `MAX_KEY_HISTORY_BYTES` fails closed) and the head JSON from SecretStorage under `KEY_HISTORY_HEAD_SECRET`, and returns the replay. `appendKeyRecord` takes `withFileLock(identityDir, KEY_HISTORY_LOCK_FILE, ...)`, reads and replays (refusing to append to a broken history with a plain error), builds the next record (`seq`, `prev`, `at` from the clock), signs it with `signPayload(signer, 'key-record', record)`, replays the new file to prove it is valid, writes it with `writeFileAtomic` from `./teamFile` and then stores the new head, all inside the lock; it returns the new replay. `localKeyStatus` returns the replay's lookup. Order of locks wherever both are taken: `identity-create.lock` first, then `key-history.lock`.
