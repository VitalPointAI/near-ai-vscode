# Team Studio staff setup

The first screen keeps the project, available sections and the next action visible together. A user can add one section or review what a complete staff would require. Both paths use the same project profile and staff setup service.

## Entry and flow

| Screen | Content and behavior |
| --- | --- |
| Studio library | **Set up staff** opens Studio's setup view. Keep **New team** for a general-purpose agent group. An existing staff team still opens its normal roster or the Staff Room. |
| Choose a project and scope | Show the actual target project at the top. Select a folder explicitly when several are open. Offer **One section** and **Complete staff**. Show the saved profile and supported level when valid, with **Change** beside each. |
| Choose a section | Source available choices from the host's template registry. J2, J3, J4 and J5 are currently available individually. Show a short purpose and the named human decision role with each. **Continue to section setup** starts confirmed setup for that selected project and section. |
| Review a complete staff | Show the sections appropriate to the charter, the existing agent teams that can be retained, new teams to create, any replacement and the sections requiring an appointment or implementation. Show who owns review for each section. Keep the preview readable while generation is pending. Enable whole-staff setup only once the host can preview, authorize and apply one complete plan. |
| Review changes | Show one profile and the read-only model location from the project's policy. Show the roster, shared file updates and team replacements. Allow **Back** to change selections. Use **Set up this section** or **Set up this staff** for the permitted action. **Leave setup** closes the preview. Confirm replacements and the exact destination project before writing. |
| Result | Summarize created and retained teams with a direct link to each team or the Staff Room. Show a short status while preparing the roster. If preparation fails or a section is unavailable, explain the reason and keep the selections for correction. If the project or reviewed files changed, hold every write and reopen review with the current plan. |

The initial section flow uses the registered Staff Setup command and its existing roster confirmation. A host-provided section choice must come from the current supported registry. Pin the project selected by the user, recheck it at confirmation, and filter malformed or unsupported messages. Keep existing Staff Room and Chat entry points working. Reuse the Get Started preset and project model policy as they land under GUIDE-08. Setup can use a valid stored profile as a starting point.

The complete-staff preview is explicitly a preview until the batch planner can reconcile saved links and approved scope at the selected level. The existing strategic, operational and tactical selectors are separate from unit L4, brigade L3, division L2, joint L1 and strategic L0 assignments. Confirm required appointments against the organization profile. An apply operation needs one composed plan, conflict checks and tested recovery across `PROFILE.md`, `project.json`, `AGENTS.md` and the team library. Keep the institutional authorization and confinement conditions G17 and G62 open. Test-only roles never populate ordinary setup.

## Presentation and accessibility

Use the existing Team Studio panel, choice grid, roster, action and focus styles without adding a component registry. Use one primary action per screen. Show selection in text and shape as well as color. Use 4px between icon and text, 8px between related controls, 16px panel padding and 24px between sections. The editor surface is dominant and Studio panels use the secondary theme surface. Reserve the accent for the selected choice, primary action and keyboard focus. Use the editor font with equivalent sizes of 13px body, 16px card heading and 20px screen heading. Use 1.45 body and 1.25 heading line heights. List cards at wide widths and stack at 520px or narrower. Long French labels and zoomed text may wrap. The work area should have no page-wide horizontal scrolling.

Headings describe the decision on the current screen. Keyboard order follows project, scope, choices, Back and Continue. Move focus to the heading when the screen changes. Restore it to the selected section or the Studio entry when a question closes. Announce any handoff to the editor's questions and completion or failure once. A cancelled preview makes no writes.
