## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| site ConfigMap -> session | the site release file is read by every running session |
| session -> Theia Cloud service | the session stops itself with the person's token |
| Release workflow -> sites | the signed release file tells each site what a release reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-46-35 | Tampering | a changed site file making sessions stop | medium | mitigate | the ConfigMap is written only by the site install from a verified signed file (47-32); a session moves only at sign-in with nothing unsaved, once per site release; a malformed file changes nothing (Tasks 1, 2) |
| T-46-36 | Information disclosure | the person's token sent to the service | high | mitigate | sent only to `THEIACLOUD_SERVICE_URL` from the operator's variables, over HTTPS with the site CA, never logged; no broader token is ever used if the service refuses it (Task 2) |
| T-46-37 | Denial of service | a stop loop when the site file flaps | medium | mitigate | at most one move per site release per session; failures leave the session working (Task 2) |
| T-46-38 | Spoofing | a release file not made by your organization's release | high | mitigate | signed with your organization's cosign key in key mode in `container-release`; sites verify before use (Task 3, 47-32) |
| T-46-39 | Repudiation | a move nobody can trace | low | mitigate | the watcher logs each state change and each stop request result without the token (Tasks 1, 2) |
| T-46-SC | Tampering | npm installs | high | mitigate | No package is installed in this plan |
</threat_model>
