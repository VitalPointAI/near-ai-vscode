# Phase 74.3: Validation Strategy

> Per-phase validation contract for 14 plans in 9 waves. Every test uses fictional content and people (Example Organization, Exercise NORTHERN EXAMPLE, `did:webvh:...:example.org:people:alex`), a loopback fake model server and fake OpenBao; no real model and no real document in any automated test.

`nyquist_compliant` stays false: every task has an automated check written first, but 74.3-02 Task 1 is a licence research task checked by its verdict lines, 74.3-14 ends in the owner's gate approval, the workbench suite runs whole rather than per file, and each test file is created by its own task (tests first) rather than in a separate wave 0.

## Sampling Rate

- **After every task commit:** the task's own `<automated>` command.
- **After every wave:** every new test file of the wave, `architecture.test.js`, `copyLint.test.js`, and the workbench, hub or deploy run when the wave touched them.
- **Blocking in every wave that touches them (security, authorization, data integrity):** the runner's route and system-high choice, the closed answer and person-attribute refusals, the asymmetric rule through `assess`, `mayLower` and `verifyLowering`, Set Label's lower path, the affirmation checks, the spill freeze and report bytes, the OpenBao policies and their key inventory rows (`compliance/test/hostedKeys.test.ts` once 48.1-08 is on main), the cell cover rule and the hub's check, the resource check, and the gap register's road to production check (74.3-14).
- **Before `/gsd-verify-work`:** 74.3-14's full suites green once.
- **Browser checks:** none blocking. The panel and cards are covered by workbench tests with fakes; a real local model in the built image is the owner's diagnostic run (74.3-14 Task 3).
