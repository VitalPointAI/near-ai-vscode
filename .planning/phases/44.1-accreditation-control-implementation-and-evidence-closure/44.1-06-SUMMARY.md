## What was built

- **Generator** (`compliance/src/applicability.ts`):
  - `mapLevels`: claim-true levels, without overlays.
  - `mapControls` and `levelMapControls`: product or shared families, plus whole-control exceptions.
  - `mapProblems`: names an uncovered control with its profile, and a component with no rule entry.
  - `buildLock`: throws on any problem. Each component gets its section SHA-256 and one line per facet and per in-scope control.
  - `statementsOutsideMap`, `levelSummaries`, `renderPage`, `lockText` and `STAGE_LEVELS`.
- **Command** `node compliance/src/cli.ts applicability --write | --check [--root]` (`compliance/src/commands/applicability.ts`). `--check` prints the first differing line and exits 1.
- **The bundle** passes the map's in-scope controls to `loadApplicability`, so the dashboard checks a review against the same hash the lock shows.
- **Rules** (`compliance/applicability/rules.json`): 46 facets; 302 component facets across 18 components, each with a basis that names its definition text, `resources.json` entry, exchange or code path; 305 control rules; no overrides.
- **Generated**: `compliance/applicability/map.lock.json` and `docs/security/component-applicability.md`.

## Deviations from Plan

**1. [Rule 2] Section hashes cover the map's in-scope controls**
- **Found during:** Task 1
- **Issue:** 44.1-05's hash covered only the controls the rules name. An enhancement newly selected by a profile, and inheriting its base control's class, could therefore change cells without changing the signed hash (D-11).
- **Fix:** `componentSection(rules, component, controls)` and `buildApplicabilityIndex(..., controls)` take the in-scope controls. The bundle and the lock both pass `mapControls(levels, table)`. `levels.test.ts` now loads the map as the bundle does.
- **Commit:** ade5fb44
