# Phase 44.1 — Validation Strategy (coverage amendment, plans 44.1-05 to 44.1-24)

> Per-phase validation contract for feedback sampling during execution. The map below comes from the plans; each code plan's first task writes its new test and sees it fail. The statement plans (44.1-09 to 44.1-21) add no compliance test files of their own: their checks are the existing target and limitation tests, the acceptable-rule check and the coverage ratchet, so a statement cannot land without evidence a CI job reports. Status stays draft until `/gsd-validate-phase` runs after execution. Plans 44.1-01 to 44.1-04 keep the checks their own text names.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `node:test` through `scripts/run-tests.mjs` (TypeScript by Node type stripping in `compliance/`; `.mjs` in `scripts/test/` and `docs-site/test/`) |
| **Config file** | none; `npm --prefix compliance ci --ignore-scripts` once per checkout; `npm --prefix docs-site ci --ignore-scripts` for the drawer test; `gh` authenticated for the tracers' `gh run download` of main's test reports |
| **Quick run command** | `systemd-run --user --scope -q -p MemoryMax=4G -p MemorySwapMax=0 choom -n 1000 -- timeout 300 node scripts/run-tests.mjs <the one mapped test file>` |
| **Full suite command** | the same wrapper on `npm --prefix compliance test`, then `scripts/test/*.test.mjs`, then the docs-site tests; plus `node compliance/src/cli.ts applicability --check`, `node compliance/src/cli.ts coverage --check`, `node compliance/src/cli.ts validate`, `node scripts/build-road-to-production.mjs --check` (one heavy run at a time) |
| **Estimated runtime** | ~240 seconds |

Where a check blocks: `applicability --check` and `coverage --check` in the required `docs` job from 44.1-07 (with the compliance package installed there); `build-road-to-production.mjs --check` already in the docs job; the workflow and gate-path tests in the root `test` job (`scripts/test`). The `compliance` job runs the compliance tests (not a required check, but a failing step fails the job and the merge gate refuses any failed check, Phase 44 D-41); its coverage summary step is report-only.

---

## Sampling Rate

- **After every task commit:** the single mapped test file, and `coverage --check` once statements or the map changed
- **After every plan wave:** the full suite once on the wave's integration branch before its pull request
- **Before `/gsd-verify-work`:** full suite once, a local bundle from main's real reports, and the coverage table compared with `44.1-RESEARCH.md` section 4
- **Max feedback latency:** 300 seconds
