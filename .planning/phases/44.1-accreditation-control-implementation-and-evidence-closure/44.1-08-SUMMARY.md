# Phase 44.1 Plan 08: Evidence invariant, gate paths and the display of excluded cells Summary

A statement now needs a rule backed by evidence some CI job or collector actually reports. The map's review and baseline folders need the owner's approval to change. An excluded component explains itself in the assessor SSP and the docs drawer.

## What was built

- **`compliance/src/rules.ts`**, as written:
  - `REPORTED_TEST_ROOTS = ['src/test', 'scripts/test', 'relay/test', 'hub/test', 'workbench/test', 'deploy/test']`
  - `ACCEPTED_OBSERVATION_COLLECTORS = ['tests', 'ci', 'secret-scan', 'documents', 'crypto', 'audit', 'sbom', 'release', 'attestation', 'settings', 'review-trail', 'code-scanning', 'deployment']`: the same ids as `bundle.ts COLLECTORS`, and a test keeps the two equal.
  - `isAcceptableRule(rule)` and `statementsWithoutAcceptableRule(components, rules, levels)` return `{ component, control, statement, reason, exempt }`. The reason is one of "no rule", "not in a reported test job" or "not from a known collector". `exempt` is true for a component assessed only at claim-false levels.
- **Over the real sources** the function returns exactly one entry, `appliance ac-03`, marked `exempt: true`. 44.1-07's `coverage --check` fails on any entry that is not exempt.
- A test reads `.github/workflows/ci.yml` and checks that each accepted folder maps to a job that sets `NEAR_AI_TEST_REPORT` and uploads `test-report-<job>`: `test` for src and scripts, then `relay`, `hub`, `workbench` and `deploy`.
- **Gate paths**: `/^compliance\/applicability\//` and `/^compliance\/coverage\//` are in `GATE_PATHS`. `/compliance/applicability/` and `/compliance/coverage/` are routed to the owner in `.github/CODEOWNERS`.
- **SSP** (`oscalSsp.ts`): a by-component whose reason is `component-not-applicable` takes its `reasonText` as description and implementation status `not-applicable`, with no export block. The SSP still validates against OSCAL.
- **Docs drawer** (`ControlDrawer.jsx`): each component section has a heading with the component id and its `StateBadge`. It shows the applicability ("Implements", "Supports", "Not applicable to this component") when present, then `component.statement ?? component.reasonText`. The row's reason no longer stands in for a component's.

## Deviations from Plan

**1. [Rule 3 - Blocking] The drawer test reads the component source; it does not render it**
- **Found during:** Task 2
- **Issue:** The docs-site tests have no JSX renderer. `ControlDrawer.jsx` imports `@docusaurus/useBaseUrl` and a CSS module, which do not resolve outside the Docusaurus build.
- **Fix:** Following the existing `pages.test.mjs` pattern (it already reads `ResponsibilityMatrix.jsx` and `PackageInfo.jsx` as text), the test isolates the per-component section and checks four things in it: the component id, `<StateBadge state={component.state} />`, `component.applicability`, and `component.statement ?? component.reasonText`. It also checks that `row.reasonText` is absent. The JSX was checked by an esbuild transform. The plan's `npm --prefix docs-site ci` was not needed.
- **Commit:** 038de580
