## Task 1: the generator and its drift check (done, `cb77f946`)

- **`compliance/src/supplyChainStatements.ts`**:
  - `generate(sources)` works on every component file.
    - It drops the file's generated control implementation, which has a fixed UUID per component.
    - For each of the 17 supply-chain controls of D-15, it writes a `<control>_smt.inventory` statement only when all of these hold:
      - the inventory lists resources of that component;
      - the applicability map gives the component a part in the control;
      - no reserved pair (`RESERVED`, mirroring `44.1-HANDOFFS.md`) and no hand-written requirement covers it;
      - an evidence entry covers the component.
    - Each statement names the component's own items with the pins the inventory lists, and has one rule `<component>.<control>.inventory`.
    - Every pair it skips is listed with the reason.
    - The output is deterministic, with UUIDs taken from a hash. A file that gets nothing keeps its bytes.
  - `driftProblems` and `mapApplicable` are built on `coverage.ts` `cellClass`, with statements left out of the count.
- **Evidence** (`EVIDENCE`), one rule per statement, every rule an acceptable D-18 test rule:

  | Control | Rule | Scope |
  |---|---|---|
  | cm-08 | `scripts/test/resource-check.test.mjs` "the repository itself passes the check, against the real catalogues and components" | the component's non-test register entries |
  | sr-03 | the same test | the same entries |
  | si-07 | `deploy/test/bundle-verify.test.mjs` "a store item that is missing, extra or has another digest is refused" | entries the offline bundle carries: image lock, chart lock, or a tool in `build.mjs` `SITE_TOOLS` |
  | sr-11 | `deploy/test/bundle-verify.test.mjs` "a manifest signed with a different key is refused" | the same entries |

  A collector subject of the component's own can be added as `scope: { component }`.
- **`node compliance/src/cli.ts supply-chain-statements`**:
  - With no option, it prints a report: the controls generated and the pairs skipped, per component, with reasons.
  - `--check` exits 1 when a component file or `compliance/evidence-rules/supply-chain.json` differs from the generator's output.
  - `--write` writes both.
  - It reads `SITE_TOOLS` from the text of `build.mjs`. Importing `build.mjs` would pull in esbuild, which the docs job does not install before this check.
- **`coverage --check`** adds `supply-chain: <file>: …` problems from `supplyChainProblems`, so drift fails the required docs job once the statements are adopted.
- **Tests:** written first. RED: the module was missing.
  - 6 new tests in `compliance/test/supplyChainStatements.test.ts`:
    - a cm-08 statement for a component with an image lock entry naming its own pins, and none for a component with no inventory entry; a test-only resource backs nothing; every generated statement has an acceptable rule and passes the word lint;
    - a hand-written statement kept byte for byte, a reserved pair (image-registry si-07, 48-08) skipped, and a pair the map excludes skipped;
    - with no subject of its own, a component gets only si-07 and sr-11 from the import tests, never ra-05, and the import statement claims no SBOM or scan;
    - a second run gives the same bytes, and changing one pin changes only that component's file;
    - every real evidence test name appears literally in its file;
    - `supply-chain-statements --check` and `coverage --check` exit 1 after a generated statement is edited by hand, on a scratch copy of the repository.
  - Verify (capped): lint passed; supplyChainStatements, coverage and components ran 25 tests, all passed.
