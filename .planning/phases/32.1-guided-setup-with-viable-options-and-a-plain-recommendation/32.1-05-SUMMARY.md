# Phase 32.1 Plan 05: Announced server discovery Summary

**The setup guide can discover announced HTTPS server candidates on listed networks through one-shot mDNS and DNS SRV. The DNS wire decoder bounds untrusted replies before they reach candidate selection.**

## Performance

- Started 2026-11-22T21:10:26Z and completed verification around 2026-11-22T21:21:02Z.
- Implemented 3 tasks across 5 source and test files.

## Accomplishments

- Encodes PTR questions with the unicast-response bit. Decodes compressed PTR, SRV, TXT, A and AAAA records with bounds on packets, sections, labels, names and pointer jumps. Skips unrelated record types by their wire lengths.
- Browses through an ephemeral socket and follows the PTR, SRV and address chain within a single reply. The socket closes at the candidate cap, deadline, abort or socket error.
- Queries SRV once for the current policy-listed suffix. Validates hosts and ports, sorts by priority and weight, deduplicates endpoints and stops waiting after three seconds. Both discovery paths return only HTTPS candidates for the signature request.

## Decisions Made

- Keep the public transport seams structural so the extension host can supply Node built-ins directly. The SRV module imports the shared service name and candidate cap as values. The DNS resolver itself remains injected.
- Use the DNS-SD label boundary when matching instance names. Preserve escaped dots during matching, remove control characters from display names, and reject SRV names that URL parsers could interpret as numeric IPv4 aliases.
- Use RFC 1035 for the wire format and RFC 6762 for ephemeral, one-shot mDNS. The phase research compared the MIT-licensed `dns-packet` codec and `multicast-dns` socket library. Both were design references, with no dependency added. [RFC 1035](https://www.rfc-editor.org/rfc/rfc1035.html), [RFC 6762](https://www.rfc-editor.org/rfc/rfc6762.html), [dns-packet](https://github.com/mafintosh/dns-packet), [multicast-dns](https://github.com/mafintosh/multicast-dns)
