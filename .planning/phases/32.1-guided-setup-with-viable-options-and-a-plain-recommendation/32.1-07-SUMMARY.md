# Phase 32.1 Plan 07 Summary

Setup writes private, tamper-evident JSONL records with a SHA-256 chain that spans rotations. An independently kept local head lets verification detect a missing tail.

## Accomplishments

- The writer uses the committed event registry, serializes appends per project across windows, limits each record to 32 KiB, and keeps up to four rotated files. The log and head are created with mode `0600`. A failed write reports once per writer and returns a failure result to its caller.
- The Apply and abandonment builders retain answer IDs and omit raw probe details. The Apply record includes viability facts, policy hashes, decision IDs, outcomes, and capped redacted text. Scan ranges follow the policy parser's CIDR limits.

## Issues Encountered

- The local head detects tail loss while it survives. If the tail and head both disappear, verification can check links only through the last remaining line. ADR-011 covers independently authenticated heads.
- A process interruption after a line is written and before an existing head is replaced can leave a head mismatch. The writer refuses to extend that chain. Reported write failures attempt rollback while holding the lock, and an interrupted rotation before the next append is recoverable.
