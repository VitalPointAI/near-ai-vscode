# Phase 45.2 Plan 14: One hardened archive reader Summary

**Every ZIP container from outside (a partner's TDF object or an attached Office file) is now read by one domain reader that refuses zip bombs, crafted names and damaged entries as data, and an architecture rule keeps that reader and the inbound adapters away from disks, the network and release keys.**

## What was built

### `openArchive` (src/domain/archive/zip.ts, 214 lines, pure apart from `node:zlib`)

```ts
interface ArchiveLimits { maxEntries; maxEntryBytes; maxUnpackedBytes; maxRatio: number | undefined; checkCrc: boolean }
openArchive(bytes: Uint8Array, limits: ArchiveLimits): OpenedArchive | ArchiveRefused
OpenedArchive = { ok: true; entries: { name, size, compressedSize }[]; read(name): { ok: true; bytes } | ArchiveRefused }
ArchiveRefused = { ok: false; reason: ArchiveRefusal; message: string }
writeZip(entries: [name, Buffer][]): Buffer
```

| Limits | maxEntries | maxEntryBytes | maxUnpackedBytes | maxRatio | checkCrc |
|---|---|---|---|---|---|
| `EXCHANGE_ARCHIVE_LIMITS` | 4,096 | 256 MiB | 512 MiB | 200 | yes |
| `OFFICE_ARCHIVE_LIMITS` | 65,535 (the format's own) | 0xFFFFFFFE | no limit | none | no |

Checked from the central directory when the archive is opened, before any entry is inflated: the end record, ZIP64 (locator, end record, 0xFFFF counts, 0xFFFFFFFF sizes or offsets), split archives, directory bounds and count, entry count, names, duplicates, the encryption flags, the method, the declared entry size, the declared ratio and the declared total. Checked when an entry is read: the local header (signature, name, method, bounds), inflation with the declared size as the output cap, the unpacked size, then the CRC-32.

`ARCHIVE_REFUSALS` ids (45.2-15 and 45.2-16 cite them): `not-an-archive`, `directory-damaged`, `split-archive`, `zip64`, `too-many-entries`, `duplicate-name`, `unsafe-name`, `encrypted`, `unsupported-method`, `entry-too-large`, `ratio-too-high`, `total-too-large`, `entry-damaged`, `size-mismatch`, `crc-mismatch`, `no-such-entry`. A name is unsafe when it is empty, starts with `/`, holds a backslash or a NUL, starts with a drive letter, or has a `..` segment.

### `src/agent/zip.ts` (now 36 lines)

`readZip(bytes, name, maxUnpacked = 50 MiB)` opens with `OFFICE_ARCHIVE_LIMITS`, checks each entry's declared size against the remaining budget before reading it, and turns refusals into the ToolErrors the tools have always raised ("... is not a valid Office file.", "... is too large when unpacked (over N MB)." and "... or damaged."). `writeZip` calls the domain writer (byte-identical output). No inflation remains in the agent layer.

### The architecture rule (src/test/architecture.test.ts)

`IO_MODULES_REFUSED` names `fs`, `net`, `http`, `https`, `http2`, `dgram`, `undici`, `dns`, `tls`, `child_process`, `worker_threads` and `cluster`, each with its reason; `node:` prefixes and sub-paths (`fs/promises`) are normalised. Under `src/domain/exchange/inbound/` and `src/domain/archive/` (test files skipped, comment lines blanked), every import form the scanner reads (static, type, side-effect, re-export, `import()`, `require()`) and any call of the global `fetch` is a finding. Under `src/domain/exchange/inbound/`, naming `bindLabel` (45.1-01's label binding signer) or a release key (`release-<site>`, `release-p256-<site>`, an `org-release:` signer id) is a finding; `verifyLabelBinding` stays allowed. No baseline line was added.

## Deviations from Plan

**1. [Rule 2 - plan detail] `checkCrc` added to `ArchiveLimits`**
- **Found during:** Task 1
- **Issue:** the existing Office test fixture in `src/test/documents.test.ts` writes CRC-32 0, and Office files that Office itself opens should keep opening, while the plan requires the Office tests to pass unchanged.
- **Fix:** a fifth limit, `checkCrc`, true for exchange arrivals and false for the Office tools. A CRC-32 proves no authorship, so this costs the Office path no protection; declared sizes are still enforced there.
- **Commit:** cf165ad7

**2. [Rule 1 - semantics kept] The Office budget stays a read budget**
- **Issue:** the plan names `OFFICE_ARCHIVE_LIMITS` "with today's Office budget", but today's budget counts only what is read; checking a 50 MiB total at open would refuse a deck whose unread video is larger and break text extraction.
- **Fix:** `OFFICE_ARCHIVE_LIMITS` has only the format's limits; `readZip` keeps the 50 MiB (or caller-given) budget per read, checked against the declared size before inflating.
- **Commit:** cf165ad7

**3. Behaviour change for the Office tools (intended by D-31):** an Office file with two entries of one name, an unsafe name, an encrypted entry, ZIP64 or a compression method other than stored and deflate is now refused as "not a valid Office file" instead of being read with the last duplicate or an empty part.
