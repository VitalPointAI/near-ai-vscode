# OpenSearch installer completion and retry

The installer records OpenSearch as pending before applying the release. It records completion after the retention policy, snapshot repository and snapshot policy succeed. A full resume that would skip pending OpenSearch stops before proceeding. Explicitly unrelated release calls retain their existing behavior.

A retry checks the current version of the retention and snapshot policies before updating them. A confirmed missing policy uses the corresponding create operation. Ambiguous responses and an unacknowledged repository write keep the work incomplete. All required configuration bodies are checked before the object writes. Credentials remain on stdin.

The fake installer reproduced premature completion, an unsafe retry after a policy write with a lost response, and a snapshot lookup failure that would attempt creation. After the change all 29 installer and site renderer checks passed with pinned Helm 4.3.2 and zero skips. This verification used no cluster, audit data, or real credentials.
