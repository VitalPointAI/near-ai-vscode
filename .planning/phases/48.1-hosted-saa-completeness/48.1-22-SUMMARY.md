# Phase 48.1 Plan 22: The owner's development site key Summary

One command, `sh deploy/keys/new-dev-site-key.sh`, makes the development organization site key inside a SoftHSM2 token on the owner's machine and prints only its public key and PKCS#11 URI; it refuses without a terminal, never handles a PIN, and archives instead of deleting.

## The command for the owner

Run once, yourself, in a terminal at the repository root:

```sh
sh deploy/keys/new-dev-site-key.sh
```

1. If SoftHSM2 or OpenSC is missing, it prints `sudo apt-get install softhsm2 opensc` (`sudo dnf install softhsm opensc` on RHEL or Fedora) and asks `Install them now? Type yes to continue:`. The package manager then shows its own list.
2. `Step 1 of 2`: softhsm2-util asks for a security officer (SO) PIN, then the token (user) PIN, each twice. Keep both in your password manager.
3. `Step 2 of 2`: type the token PIN once more (not shown on screen). The key is made inside the token.
4. It prints, on standard output, only:

```
-----BEGIN PUBLIC KEY-----
MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...
...
-----END PUBLIC KEY-----
pkcs11:token=sterling-site-dev;object=sterling-site;id=%01;type=private?module-path=/usr/lib/softhsm/libsofthsm2.so
```

and then, as notes, where the public key is saved (`~/.config/sterling-signing/site-key.pub.pem`) and `export SOFTHSM2_CONF=$HOME/.config/sterling-signing/softhsm/softhsm2.conf` for signing. Put the public key in the site file as `organizationPublicKey` (H-21).

Afterwards: `--show` prints the same key and URI again; running it again without flags does the same and changes nothing; `--rotate` asks for yes, moves the token folder, its configuration and the saved public key to `~/.config/sterling-signing/softhsm/.archive/<UTC time>/`, and makes a new key.

The executor never ran the script outside `--test` with a temporary configuration, and never touched `~/.config/sterling-signing`.

## Documentation checked (behaviour the script relies on)

Read from the upstream sources at the released tags, 2026-11-24:
- OpenSC 0.27.0, `src/tools/pkcs11-tool.c` (https://github.com/OpenSC/OpenSC/blob/0.27.0/src/tools/pkcs11-tool.c): `gen_keypair` sets `CKA_SENSITIVE` true on the private key by default and `CKA_EXTRACTABLE` only with `--extractable`; the public key gets `CKA_PRIVATE` false unless `--private`; after generation it prints "Key pair generated:" and both objects with an `Access:` line (`sensitive`, `always sensitive`, `extractable`, `never extractable`, `local`); `--login` with no PIN given prints "Please enter User PIN: " and reads the PIN with `util_getpass` from standard input; `--read-object --type pubkey` writes the key as DER SubjectPublicKeyInfo (`i2d_PUBKEY`) to standard output when no `--output-file` is given.
- SoftHSM2 2.6.1, `src/bin/util/softhsm2-util.cpp` and `softhsm2-util.1` (https://github.com/softhsm/SoftHSMv2/blob/2.6.1/src/bin/util/): `--init-token` with `--free --label` and no PIN options asks for the SO PIN and the user PIN itself (`getPW`); `--show-slots` prints each token's `Label:` padded to 32 characters; `softhsm2.conf(5)`: `directories.tokendir`, `objectstore.backend = file`, `log.level`, `slots.removable`.
- SoftHSM2's default for `CKA_EXTRACTABLE` is not relied on: the script reads the Access line and stops (archiving the token) unless the key is sensitive and never extractable.
