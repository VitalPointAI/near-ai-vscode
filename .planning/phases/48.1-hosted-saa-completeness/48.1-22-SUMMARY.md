# Phase 48.1 Plan 22: The owner's development site key Summary

One command, `sh deploy/keys/new-dev-site-key.sh`, makes the development organization site key inside a SoftHSM2 token on the owner's machine and prints only its public key and PKCS#11 URI; it asks for PINs only in the token tools' own prompts, refuses to run without a terminal (not a security control), and archives instead of deleting.

## The command for the owner

Run once, yourself, in a terminal at the repository root:

```sh
sh deploy/keys/new-dev-site-key.sh
```

1. If SoftHSM2 or OpenSC is missing, it prints `sudo apt-get install softhsm2 opensc` (`sudo dnf install softhsm opensc` on RHEL or Fedora) and asks `Install them now? Type yes to continue:`. The package manager then shows its own list.
2. `Step 1 of 2`: softhsm2-util asks for a security officer (SO) PIN, then the token (user) PIN, each twice. Keep both in your password manager.
3. `Step 2 of 2`: when pkcs11-tool shows `Please enter User PIN:`, type the token PIN once more (not shown on screen). The key is made inside the token, and pkcs11-tool's listing of the new objects is shown.
4. It prints, on standard output, only:

```
-----BEGIN PUBLIC KEY-----
MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...
...
-----END PUBLIC KEY-----
pkcs11:token=sterling-site-dev;object=sterling-site;id=%01;type=private?module-path=/usr/lib/softhsm/libsofthsm2.so
```

and then, as notes, where the public key is saved (`~/.config/sterling-signing/site-key.pub.pem`) and `export SOFTHSM2_CONF=$HOME/.config/sterling-signing/softhsm/softhsm2.conf` for signing. Put the public key in the site file as `organizationPublicKey` (H-21).

Afterwards: `--show` prints the same key and URI again without logging in; running it again without flags asks for the token PIN, checks that the existing private key is sensitive and never extractable, prints the same key and URI and changes nothing; `--rotate` asks for yes, moves the token folder, its configuration and the saved public key to `~/.config/sterling-signing/softhsm/.archive/<UTC time>/`, and makes a new key.

The executor never ran the script outside `--test` with a temporary configuration, and never touched `~/.config/sterling-signing`.

## Documentation checked (behaviour the script relies on)

Read from the upstream sources at the released tags, 2026-11-24:
- OpenSC 0.27.0, `src/tools/pkcs11-tool.c` (https://github.com/OpenSC/OpenSC/blob/0.27.0/src/tools/pkcs11-tool.c): `gen_keypair` sets `CKA_SENSITIVE` true on the private key by default and `CKA_EXTRACTABLE` only with `--extractable`; the public key gets `CKA_PRIVATE` false unless `--private`; after generation it prints "Key pair generated:" and both objects with an `Access:` line (`sensitive`, `always sensitive`, `extractable`, `never extractable`, `local`); `--login` with no PIN given prints "Please enter User PIN: " and reads the PIN with `util_getpass` from standard input; `--read-object --type pubkey` writes the key as DER SubjectPublicKeyInfo (`i2d_PUBKEY`) to standard output when no `--output-file` is given.
- SoftHSM2 2.6.1, `src/bin/util/softhsm2-util.cpp` and `softhsm2-util.1` (https://github.com/softhsm/SoftHSMv2/blob/2.6.1/src/bin/util/): `--init-token` with `--free --label` and no PIN options asks for the SO PIN and the user PIN itself (`getPW`); `--show-slots` prints each token's `Label:` padded to 32 characters; `softhsm2.conf(5)`: `directories.tokendir`, `objectstore.backend = file`, `log.level`, `slots.removable`.
- SoftHSM2's default for `CKA_EXTRACTABLE` is not relied on: the script reads the Access line and stops (archiving the token) unless the key is sensitive and never extractable.

## Field fix (2026-11-24, branch fix/dev-site-key-pin-prompt)

**What happened.** The owner ran the script. Step 1 (softhsm2-util) worked. Step 2 stopped with `error: util_getpass error`, `Aborting.`, `new-dev-site-key: pkcs11-tool could not make the key`. Run by hand on the terminal, the same pkcs11-tool command worked, and its Access line read `sensitive, always sensitive, never extractable, local`.

**Cause, confirmed in the source.** `create_key` ran pkcs11-tool inside `out=$(...)`, so its standard output was a pipe. In OpenSC 0.27.0-rc1, `src/tools/util.c`, `util_getpass` calls `fflush(stdout)` and then `tcgetattr(fileno(stdout), &old)`, and returns -1 when that fails (it turns echo off on standard output's terminal, then reads the PIN from standard input). `login()` in `src/tools/pkcs11-tool.c` then calls `util_fatal("util_getpass error")`. With standard output a pipe, `tcgetattr` always fails. The fake pkcs11-tool read the PIN from standard input whatever its standard output was, so the fake-tool tests could not see this. The "Documentation checked" note above missed the standard output condition.

**Fix.**
- pkcs11-tool now runs under util-linux `script -q -e -c "stty -echo && pkcs11-tool ..." /dev/fd/3`, on a terminal of its own, inside `SESSION=$(... 3>&1 >&2)`. The prompt and output show on the owner's terminal as usual. script's copy of the session goes to file descriptor 3, which is the command substitution, so it never touches the disk and there is nothing to remove. The substitution's status is pkcs11-tool's (`-e`). Every word of that command is fixed or the checked module path; anything needing quoting stops the script first. (A first version kept the copy in a 0600 temporary file and removed it on exit; that broke this plan's "no rm, unlink or shred" check, so it was replaced before pushing.)
- The PIN is still typed only into pkcs11-tool's own prompt, never passed as an argument, an environment variable or a file. Echo is off on that terminal, so the PIN is in neither the copy nor the output. The `stty -echo` comes first because pkcs11-tool turns echo off only once its prompt is up: a scratch run on real SoftHSM2 with a delayed start showed a PIN typed before the prompt being echoed into the copy without it, and not with it. A run with the PIN typed at the prompt showed no PIN in the copy, and the Access line present.
- The Access line is read from the copy (CR stripped, matched on label `sterling-site` and ID `01`). As before, a key that is not sensitive and never extractable, or no such key, archives the token.
- **The key-exists path now checks too.** It runs `pkcs11-tool --login --list-objects --type privkey --label sterling-site --id 01` the same way and applies the same check. A login is needed: SoftHSM2 lists no private object without one (checked: `--list-objects --type privkey` without `--login` printed nothing and exited 0), and pkcs11-tool always makes the private key `CKA_PRIVATE` true (`gen_keypair`). A failed login stops with "nothing was changed". A key that fails the check is archived. `--show` stays login-free and says it did not check.
- `script` is listed in `deploy/host-packages.json` (apt `bsdutils`, essential on Ubuntu; dnf `util-linux`), so the install offer now names `softhsm2 opensc bsdutils`.
- Unchanged: terminal required, nothing deleted (`grep -cE '(^|[;&|[:space:]])(rm|unlink|shred)[[:space:]]'` is still 0), `--rotate` archives, the `--test` containment from #194.

**Tests.**
- New `deploy/test/dev-site-key-softhsm.test.mjs` runs the script against the real SoftHSM2 (`/usr/lib/softhsm/libsofthsm2.so`) and OpenSC, inside a pty made by `script`. Each test PIN is typed into that pty 300 ms after the tool's own prompt appears, never as an argument. HOME, TMPDIR and `SOFTHSM2_CONF` are inside the test's temporary folder; PATH holds only links to the real token tools and base utilities, with no rm, unlink or shred; every path is checked to be outside `~/.config/sterling-signing` and `~/.near-credentials` before anything runs. It:
  - makes a real token and key end to end, asserting the PEM (EC P-256), the URI, the saved public key and OpenSC's Access line;
  - shows that a second run logs in, checks the key and changes no file (SoftHSM2's own `token.object` flags, rewritten on every login, are only checked to be present);
  - shows that `--rotate` archives every earlier file unchanged and makes a new key.
  It also checks that no PIN is on the terminal (the same bytes script copies), on standard output or in any file. It fails, never skips, without the tools; CI's deploy job now installs `softhsm2` and `opensc`.
- **Against the old script:** all 4 fail, with the owner's exact `error: util_getpass error` and `pkcs11-tool could not make the key`.
- The fake-tool tests are kept and updated:
  - the fake pkcs11-tool now fails its PIN prompt with `util_getpass error` unless standard output is a terminal, as OpenSC does;
  - a fake `script` stands in for the pty, and a fake `stty` accepts only `-echo` under it;
  - they assert the `script -q -e -c "stty -echo && pkcs11-tool ..."` call shape, with the copy going to `/dev/fd/3`;
  - new: the existing-key path archives an extractable or not-sensitive key, a failed login changes nothing, and `--show` never logs in.
  Against the old script, 6 of the 13 fake-tool tests fail.
