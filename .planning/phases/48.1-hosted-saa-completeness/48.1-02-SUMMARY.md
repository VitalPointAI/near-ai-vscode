# Phase 48.1 Plan 02: Alerts as code Summary

Alertmanager now runs in the prometheus release and mails your organization's security operators through the site's own mail server; nine rules alert on OpenBao being sealed or failing to audit and on audit shipping failing, and every source has a guard so a missing or renamed input raises an alert too.

## Rules, metrics and sources

| Rule | Source | Expression (metric) | Metric documentation |
|---|---|---|---|
| OpenBaoSealed | openbao | `vault_core_unsealed == 0` (gauge) | https://openbao.org/docs/internals/telemetry/metrics/core-system/ |
| OpenBaoAuditDeviceFailing | openbao | `increase(vault_audit_log_request_failure[5m]) > 0 or increase(vault_audit_log_response_failure[5m]) > 0` (counters) | https://openbao.org/docs/internals/telemetry/metrics/audit/ |
| OpenBaoMetricsTargetDown (guard) | openbao | `up{job="openbao"} == 0` | Prometheus `up` |
| OpenBaoMetricsMissing (guard) | openbao | `absent(up{job="openbao"})` | Prometheus `up` |
| OpenBaoSealSeriesMissing (guard) | openbao | `absent(vault_core_unsealed)`, a gauge present from start | core-system page above |
| FluentBitOutputFailing | fluent-bit | `fluentbit_output_errors_total`, `fluentbit_output_retries_failed_total` on `site_opensearch` | https://docs.fluentbit.io/manual/administration/monitoring |
| AuditRecordsNotReachingStore | fluent-bit | `fluentbit_input_records_total{name="audit_kubernetes"}` read but `fluentbit_output_proc_records_total{name="site_opensearch"}` flat for 30 minutes, or no audit read at all | same |
| FluentBitMetricsTargetDown (guard) | fluent-bit | `up{namespace="sterling-log-shipper", app_kubernetes_io_name="fluent-bit"} == 0` | Prometheus `up` |
| FluentBitMetricsMissing (guard) | fluent-bit | `absent(up{...})` | Prometheus `up` |

## Deviations from Plan

1. **[Rule 2 - Security] OpenBao metrics through a dedicated TLS scrape job instead of pod annotations.** A plaintext metrics listener would break the "TLS on" invariant in openbao.test.mjs; the chart's pod job cannot verify the site CA. The job mounts ConfigMap sterling-site-ca, so sterling-monitoring joins sterling-pki's trust namespaces.
2. **[Rule 2] A required site setting** (alertRecipients) rather than a recipient list in the per-site example, so an empty list is refused by the existing D-11 mechanism. Every site file needs it; the site example and the CI site file carry it.
3. **[Process] One commit for both tasks** (dde09700); the seven tests were written first and seen failing (7 of 7).
4. **Known limit, recorded in the fit entry:** Alertmanager trusts the image's CA store for the mail server. A follow-up (48.1-12 or the Phase 47 follow-ups) can mount the site CA for it if a site's mail server uses only the site CA.
