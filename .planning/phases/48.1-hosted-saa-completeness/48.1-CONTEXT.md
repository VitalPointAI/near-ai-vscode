## Owner decisions (answered 2026-11-24)

- **(a) Separate keys: accepted.** A supplier release key (the existing cosign key in GitHub `container-release`; signs our images and releases only) and an organization site key (signs bundles, re-signed images, user exports, CSRs and CRLs). The owner has no HSM yet: during development the site key lives in SoftHSM2 on the owner's machine, used through the same PKCS#11 URI path a real HSM uses; production swaps in the real HSM by configuration only. The site preflight refuses a production-profile site whose signing token is SoftHSM2 (refusal `softhsm-signing-token`). Generating the development key is a one-command owner step (`sh deploy/keys/new-dev-site-key.sh`, plan 48.1-22, wave 1): it installs the packages, initialises a token, makes the key inside it, prints only the public key and URI; the private key never leaves the token, and agents never run it for the owner. Signing tool: pinned cosign for payload, attach and verify, OpenSC pkcs11-tool for the key operation (D-27). Applied by 48.1-22, 48.1-17 and 48.1-21.
- **(b) Audit retention: 5 years (1,825 days) for every hosted audit record,** for ITAR; one rule for all records. Online OpenSearch window 730 days; then the write-once archive until 1,825 days; deletion only after the archive holds the day; object-lock retention 1,825 days; site default 1,825, longer allowed, never shorter; the Controlled Goods period stays as counsel confirms, covered by the site setting if longer.
