## For the owner to decide

Each has a recommended default the plans use. Answer any time; the gate pull request of the plan that applies it is the last point to change it cheaply.

- **(a) Separate keys.** A supplier release key (GitHub `container-release`; signs our images and releases only) and an organization site key (offline, in the HSM; signs bundles, re-signs every image for admission, and signs user exports, CSRs and CRLs). This changes the earlier accepted default "one org key signs the bundle". **Recommended: separate them.** Why: today a key that sits in a GitHub environment also signs the trust files every site imports, so a GitHub-side compromise reaches every site; separated, it reaches only our releases, which the bundle build checks before the site key re-signs them. Applied by 48.1-17 after a blocking checkpoint.
- **(b) Audit retention.** **Recommended: 2 years (730 days) online plus the write-once archive for the same period; 5 years (1,825 days) where ITAR records apply; where Controlled Goods records apply, the period your organization's counsel confirms from the regulation.** Applied by 48.1-15 and 48.1-16 as site settings with these defaults.
- **(c) HQ recovery objectives.** **Recommended provisional defaults: RTO 8 hours, RPO 24 hours, for your organization to set.** Recorded in the system description (48.1-13) and handed to the Phase 47 follow-up's contingency and backup runbook.
- **(d) Off-site backup copy for the HQ.** **Recommended: yes, to a second organization site** (backups, the audit archive and key backups). Handed to the Phase 47 follow-up's backup runbook; the audit archive and key documents say it (48.1-08, 48.1-16).
