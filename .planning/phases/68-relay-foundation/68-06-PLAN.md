<objective>
Ship the relay as a hardened, shell-less container with a Compose definition, and prove the hardening, the healthcheck, restart durability and the absence of secrets in the image with a container test suite.

Purpose: RELAY-04 (image half) with D-13, D-14, D-15, D-16; RELAY-02 through the container healthcheck; RELAY-03 through a hard kill of the container.
Output: `relay/Dockerfile`, root `.dockerignore`, `relay/compose.yaml`, `relay/test/container/container.test.ts` and its `test:container` script, and `relay/README.md`.

Recorded choices:
- Digests are the ones research recorded on 2026-11-14: build stage `docker.io/library/node:26.13.1-slim@sha256:e6bedef217677b276c591795e169840edd9096dbf13f29df8ef8d1856b8820bc`, final stage `gcr.io/distroless/nodejs26-debian13:nonroot@sha256:1d736cf8b5716c07a245301f92717143215d248fd55771ee1936ef4b3302e531`, sidecar `docker.io/bbernhard/signal-cli-rest-api:0.101@sha256:2cf09d66a86fdd210e42ee91662216364acc27da1163a8c44167a77ea3a6559a`. The suite proves the final image runs Node 26.13.1 or a later 26.x, so a stale pin fails loudly.
- Compose variables use the `NEAR_AI_RELAY_` prefix (`NEAR_AI_RELAY_IMAGE`, `NEAR_AI_RELAY_PUBLISH_PORT`, `NEAR_AI_RELAY_SECRETS_DIR`) because the relay refuses unknown `RELAY_*` settings and an operator's shell may hold these.
- Compose cannot make a file secret optional and ignores `uid`, `gid` and `mode` on file secrets (Pitfall 4), so the operator gives the secret file to uid 65532 with mode 0400; the test does the same through the pinned build image.
- The image sets `RELAY_HOST=0.0.0.0` and `RELAY_PORT=8080` (container-internal); only Compose's `127.0.0.1` publish decides who can reach it (D-15).
</objective>
