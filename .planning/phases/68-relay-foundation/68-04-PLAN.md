<objective>
Give the relay its one private state directory and a durable store, and prove the restart promise with a real kill -9 drill: a queued message and its run record that were acknowledged are never lost or duplicated.

Purpose: RELAY-03 and D-04, D-06, D-07, D-17. The store interface comes first and is scoped by tenant because D-05 names a JSON-file-per-tenant fallback; plan 05 adds the remaining aggregates and the shared contract suite.
Output: state directory module, ambient `Database` declaration, the store interface, the v1 schema with ordered migrations, the `node:sqlite` store with the queue, run and tenant operations, main wiring, the kill drill and the state directory tests.

Recorded planning choices:
- **Schema v1 holds all five aggregates now** (tenants, conversation bindings, messages, runs, approvals, plus relay_meta). The storage format is the costly door (D-05), so it is written once, before any data exists; plan 05 adds the binding and approval operations against tables that already exist rather than a v2 migration inside an unreleased phase.
- **D-21:** no single-instance lock on the state directory in this phase; two relays on one directory is an accepted, documented risk until Phase 71 (threat T-68-12).
- **Payload text** is stored in the database (inside the private directory) because a queued message must survive a restart; it never reaches a log line (D-11).
</objective>

<assumption_delta_decision>
Detector: assumption-delta fired once (pluralization, term "fallback": "name the JSON-file-per-tenant fallback for registry/state now").
- Primary noun: `RelayStore`, the storage contract. `node:sqlite` (`SqliteStore`) is one implementation of it; the JSON-file-per-tenant store (D-05, deferred) would be another.
- Decision: promote. The interface and its contract suite are primary; nothing outside `relay/src/store` names SQLite, SQL or a single-database assumption. Concretely: message, run and approval operations take `tenantId` and never rely on ids being unique across tenants or contiguous; atomic compound operations (acceptInbound) touch one tenant's records only; tenants and conversation bindings are the only global aggregates (a fallback keeps them in one registry file).
- Invariant test (accepted, built in plan 05): `relayStoreContract(name, factory)` runs the same cases against every implementation, so a later variant that breaks the tenant-scoped shape goes red.
</assumption_delta_decision>

State directory (D-07, D-17), `relay/src/stateDir.ts`: `prepareStateDir` lstats the directory; when missing it creates it (recursive) and chmods it to 0700 explicitly so the result does not depend on the umask; it refuses with StateDirError a symbolic link, a non-directory, or an owner uid other than `options.uid ?? process.getuid()`; when owned by the relay but group or world bits are set it chmods to 0700, re-checks, and logs `state_dir.tightened` with `fromMode` as a four-digit octal string. It then lstats each direct entry: a symbolic link or an entry owned by another uid is refused; a regular file with group or world bits is chmodded to 0600 and logged as `state_dir.file_tightened` (name, fromMode); a subdirectory owned by the relay is chmodded to 0700 if open (later phases may keep per-tenant folders here; it does not recurse). Messages are plain sentences naming RELAY_STATE_DIR and the path, for example "RELAY_STATE_DIR /x is owned by uid 0; the relay runs as uid 1000. Give the directory to the relay's user or choose another directory." `writePrivateFileAtomic` accepts only a plain file name, writes `.{name}.{8 random hex}.tmp` opened with flag wx and mode 0600, writes, fsyncs, closes, renames over the target, then opens and fsyncs the directory; on any error it removes the temp file and rethrows. `readPrivateFile` opens with O_RDONLY plus O_NOFOLLOW, fstats the same descriptor, refuses anything that is not a regular file owned by the relay uid with no group or world bits, and returns undefined on ENOENT.

Interface (D-04, assumption-delta promote), `relay/src/store/relayStore.ts`, names as in artifacts_produced. TenantRecord { tenantId, displayName, status 'active' or 'suspended', createdAt, updatedAt }. InboundMessage { tenantId, channel, conversationId, requesterId, dedupeKey, payload (opaque text), receivedAt }. QueuedMessage adds messageId (number), state ('queued', 'claimed', 'done'), attempts, claimedAt (number or null). RUN_STATES is queued, running, waiting-approval, finished, failed, cancelled, interrupted; IN_FLIGHT_RUN_STATES is running and waiting-approval. RunRecord { tenantId, runId, messageId, channel, conversationId, requesterId, state, createdAt, updatedAt }. AcceptResult { duplicate, messageId, runId }. StoreError has `code` in 'newer-schema', 'unknown-tenant', 'binding-conflict', 'unknown-run', 'invalid-record' and a plain message that never contains a payload. Methods, all async: instanceId(); putTenant(record) (insert or update displayName, status, updatedAt, keeping createdAt); getTenant(tenantId); listTenants() ordered by tenantId; acceptInbound(message, runId) (atomic: when the tenant's dedupeKey already exists, write nothing and return duplicate true with the existing messageId and runId; else unknown tenant is StoreError unknown-tenant, else insert the message as queued and a run in state queued for it, both in one transaction); getMessage(tenantId, dedupeKey); claimNext(tenantId, channel, conversationId, now) (oldest queued message of that conversation becomes claimed, attempts plus 1); ackMessage(tenantId, messageId, now) (claimed to done, returns boolean); queueDepth(tenantId) (messages not done); getRun(tenantId, runId); transitionRun(tenantId, runId, from, to, now) (compare and set, returns boolean); countRuns(states); close(). Inputs are validated before any write: ids non-empty and at most 256 characters, channel in the set, payload at most 1 MiB, times safe integers; otherwise StoreError invalid-record.

Schema (`relay/src/store/schema.ts`): MIGRATIONS[0] is the v1 DDL, every table STRICT: relay_meta(key TEXT PRIMARY KEY, value TEXT NOT NULL); tenants(tenant_id TEXT PRIMARY KEY, display_name TEXT NOT NULL, status TEXT NOT NULL with CHECK in active and suspended, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL); conversation_bindings(channel TEXT NOT NULL with CHECK in teams and signal, conversation_id TEXT NOT NULL, tenant_id TEXT NOT NULL REFERENCES tenants, created_at INTEGER NOT NULL, PRIMARY KEY (channel, conversation_id)); messages(message_id INTEGER PRIMARY KEY AUTOINCREMENT, tenant_id TEXT NOT NULL REFERENCES tenants, channel with the same CHECK, conversation_id, requester_id, dedupe_key, payload TEXT NOT NULL, state with CHECK in queued, claimed, done, attempts INTEGER NOT NULL DEFAULT 0, received_at INTEGER NOT NULL, claimed_at INTEGER, done_at INTEGER, UNIQUE (tenant_id, dedupe_key)) with an index on (tenant_id, channel, conversation_id, state, message_id); runs(tenant_id TEXT NOT NULL REFERENCES tenants, run_id TEXT NOT NULL, message_id INTEGER NOT NULL REFERENCES messages, channel, conversation_id, requester_id, state with CHECK over the seven RUN_STATES, created_at, updated_at, PRIMARY KEY (tenant_id, run_id)) with an index on state; approvals(tenant_id TEXT NOT NULL, approval_id TEXT NOT NULL, run_id TEXT NOT NULL, requester_id, call_id, tool, title TEXT NOT NULL, state with CHECK in pending, answered, expired, decision TEXT with CHECK null or in allow, allow-run, allow-always, deny (the decisions of src/agent/loop.ts ApprovalReply other than pending), created_at, expires_at INTEGER NOT NULL, answered_at INTEGER, PRIMARY KEY (tenant_id, approval_id), FOREIGN KEY (tenant_id, run_id) REFERENCES runs (tenant_id, run_id)) with an index on (tenant_id, state, requester_id). `migrate` reads PRAGMA user_version; a value above SCHEMA_VERSION throws StoreError newer-schema ("This state was written by a newer relay (schema N); this relay reads up to schema M. Start the newer relay or restore a backup."); each pending migration runs in its own BEGIN IMMEDIATE transaction that also sets user_version; finally it inserts relay_meta instance_id (crypto.randomUUID) and created_at only if absent.

Store (`relay/src/store/sqliteStore.ts`, Pattern 3, Pitfalls 6 and 7): `openSqliteStore` first creates the file with mode 0600 if absent (open with flag a and mode 0600, close) so the -wal and -shm files inherit 0600, then `new Database(file, { timeout: 5000 })`, executes PRAGMA journal_mode = WAL (asserting the result is wal), PRAGMA synchronous = FULL and PRAGMA foreign_keys = ON on this connection, runs migrate, puts every claimed message back to queued (redelivery after a restart; attempts kept), and prepares all statements once. Every write method runs inside BEGIN IMMEDIATE and COMMIT with ROLLBACK when `db.isTransaction` after an error, and resolves only after COMMIT returned; a foreign key failure on an unknown tenant becomes StoreError unknown-tenant. Only parameter binding is used; no SQL text is built from values. close() closes the database once.

Wiring (`relay/src/main.ts`): after loadConfig and before the server, `prepareStateDir(config.stateDir, logger)` (StateDirError logs `relay.start_refused` reason state-dir, exit 1), then `openSqliteStore(path.join(config.stateDir, 'relay.db'))` (errors log reason store, exit 1); `health.setInFlightRuns(() => store.countRuns(IN_FLIGHT_RUN_STATES))`; `relay.listening` gains `instanceId`; shutdown closes the server first, then the store. `--healthcheck` still returns before any of this.
