<objective>
Load every secret the relay will ever need from operator-supplied files only, register each value with the redactor the moment it is read, make phone labels stable across restarts, and prove with a real relay run that no secret reaches output, state files or the state directory listing.

Purpose: RELAY-04 (secret custody half; the image half is plan 06) with D-08, D-09, D-10, D-11 (stable label), D-18.
Output: `src/secrets.ts`, `src/log/pseudonymKey.ts`, main wiring, and three test files.

Recorded choices (Claude's discretion inside the decisions):
- In Phase 68 no secret is required: nothing uses the Teams secret until Phases 69 and 71, which flip `TEAMS_APP_SECRET` to required when the Teams channel is configured. The loader's required path is fully built and tested now.
- An explicit `{NAME}_FILE` that points at a missing file is an error naming the variable (an operator's typo must not silently fall through to another source); a missing file in the two directory sources falls through.
- Secrets shorter than 8 characters are refused: the redactor cannot mask very short values without mangling unrelated log text, and no D-10 class is that short.
- A symbolic link at a secret path is followed and the target is checked through the opened descriptor (Kubernetes and some vault agents publish secrets as links).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator secret files -> relay memory | file permissions decide who else can read them |
| process environment -> docker inspect, /proc | anything in env is visible to anyone who can inspect the container or process |
| relay memory -> logs and errors | the only route a loaded secret could escape at runtime |
