## Artifact provenance

- The scoped Write and Edit tools already capture pre-write checkpoints. Reuse their mutation boundary for recording successful creates and the checkpoint's local scoping and persistence as a pattern. `capture` maps every read failure to a null original value and runs before the mutation. A null original or a path in `changedFiles` therefore gives insufficient provenance. Failed writes, existing files, shell writes and legacy checkpoint entries need independent positive evidence to qualify as recorded creates. Reverting a checkpoint may remove files or overwrite current content, so keep the checkpoint revert path outside CleanUp. [Write and Edit](../../../src/agent/tools.ts#L340), [checkpoint capture and revert](../../../src/agent/checkpoints.ts#L49), [checkpoint persistence](../../../src/agent/checkpoints.ts#L191), [checkpoint bounds tests](../../../src/test/checkpointBounds.test.ts)
- Record successful creation through trusted code with a workspace identity, run identity and evidence that lets the operation identify the same artifact later. Keep reviewed disposable locations as separately attributable evidence. The repository has no verified artifact creation ledger for this workflow. The exact recorded identity, its lifetime and the reviewed disposable list remain planning work. [CLEAN-01 and CLEAN-04](../../REQUIREMENTS.md#L801)

## Recoverable local records

- The team updater's backup-first flow and typed partial-failure receipt are usable recovery patterns. `runSerialised` shows how to serialize same-key writes in one process. The team file and project state helpers show temporary-file replacement for trusted metadata. These behaviors cover ordinary metadata updates. Quarantine and restore still need verified moves that preserve occupied destinations and recover safely if file movement and the manifest update are interrupted. Verify the filesystem and refuse an unsupported move. Restore needs to surface a conflict if the original destination is now occupied. Purge eligibility depends on a reliable retained record and affirmative human approval. Preserve the identity and lineage needed by the later HOLD-03 legal-hold check.
