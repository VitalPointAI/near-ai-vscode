# Phase 48.2 Plan 04: Verification with zero trust: a Node Sigstore verifier, anchors from configuration and three outcomes Summary

The workbench now verifies a release's evidence manifest offline with a dependency-free verifier that the pinned cosign 3.1.4 holds equal on accept and refuse, using only keys from configuration (your organization's site key, checked against `STERLING_ORGANIZATION_PUBLIC_KEY`, or a supplier key a person mounted), and reports Verified, Not verified (content shown, nothing Met) or Did not verify (nothing shown) with a plain reason; a delivered signature or a changed key changes the outcome within one 30-second check.

## A cosign key-mode bundle (cosign 3.1.4 `sign-blob --key --signing-config <empty> --bundle`), signature elided

```json
{
  "mediaType": "application/vnd.dev.sigstore.bundle.v0.3+json",
  "verificationMaterial": { "publicKey": { "hint": "<base64 SHA-256 of the key's DER SubjectPublicKeyInfo>" } },
  "messageSignature": {
    "messageDigest": { "algorithm": "SHA2_256", "digest": "<base64 SHA-256 of the file>" },
    "signature": "<elided: base64 DER ECDSA P-256 signature over the file with SHA-256>"
  }
}
```

No certificate, no `tlogEntries` (empty signing config, no transparency log). The parity test checks that the hint is `publicKeyFingerprint` in base64.
