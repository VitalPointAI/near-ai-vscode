## Managed cell confidential handoff

Plan 33.2-09 Task 2 supplies a private connector inside the normal sync exchange. The synthetic connector exercises committed supplemental and founding grants plus a separate continuity receipt. The latest authenticated roster controls intake. An affected cell can wait for its founding grant while a verified unaffected cell writes. The multi-page sync fixture also pairs continuity with each selected grant-only revision before that revision is visible to a writer. A delayed current proof pauses that cell, an older proof is refused, and a later exchange with the current proof resumes writes.

A configured confidential provider can keep recipient-side pending opaque handles in the private replica store. A local fixture checks scope and storage mode, restart recovery, expiry, accepted and superseded acknowledgment, concurrent reservation, and bounded retries. Eligible handles are retried on later exchanges. Each request to the opaque route contains only the handle.

A configured sender revalidates the current authorized grant or continuity receipt and stages the randomized handle and sealed packet in the private store before calling the opaque route. The local fixture reopens after a failed upload and observes the same handle and packet, then reopens after the upload succeeded and resumes confidential publication without uploading again. Local acknowledgment prevents repeated publication after completion and expired reservations stop sending. After an interruption with an ambiguous remote result, the retry uses the same handle and packet. Route uploads and confidential publication need idempotence by that handle.

The handover records five focused and 288 impacted checks at `34120732` for the recipient queue, and six focused and 289 impacted checks at `fd23fe38` for the sender. Those runs cover local persistence and synthetic exchange, including identical bytes and handle after an uncertain upload and resuming confidential publication after known upload. The production receiver's handle path remains unverified.

The local continuation connects the existing bounded, recipient-sealed artifact to the Workbench file workflow. Verify an already admitted device without the target epoch key and a late device with authenticated roster access. Inspect the sent artifact and filename, repeat save and import after interruption, exercise wrong recipient and mutated pages or packet, and check expiry before import and before first promotion if the roster arrives late. A fresh device missing base history needs Task 3's authenticated bootstrap and accepted frontier before the invitation flow can count as verified. The current managed welcome can carry roster material and deliberately omits raw grants.

Automatic delivery has a separate production prerequisite. `LiveReplicator.transportFor` currently creates `HubTransport` without a managed route or a configured confidential handoff provider. `HubTransport.grant` and the hub grant store tie raw grants to project/device sessions. Prove a distinct approved route that accepts an opaque handle plus sealed and padded bytes on put, and a handle on get, with no stable identity linkage at the relay. Prove authenticated, durable handle transfer with the exact sealed expiry, idempotence by handle through ambiguous upload, publication and acknowledgment, network deadlines and bounded retries across restarts. Inspect the actual request, authorization, storage, log and metric surfaces and record residual packet-size, count and timing visibility. Allow authorized direct file recovery where the route is unavailable. Any new route location or exception to the metadata boundary remains an owner decision.

## Hosted managed withdrawal

The local managed withdrawal API binds confirmation to the exact operation, roster predecessor and selected access root. The synthetic tests exercise the existing hosted person signer and close the action window during the store's staged write. A confirmation for a different operation cannot sign it, and an expired confirmation cannot commit it. An expired operation can leave a private sidecar whose signed roster entry was never written, so that evidence remains dormant.

Workbench's hosted managed Remove flow uses the existing review page and the same pending-action registry as the person signer. The service recomputes the binding from the current roster before resuming. Hosted Finish and grant actions and formal browser verification remain open. Browser acceptance requires 33-30 on main and uses the existing container harness.

Hosted Finish uses the Task 2 proposal for independent review. The existing passkey page confirms one part against an immutable private, exact unsigned grant intent and current authorization. A scoped signer uses the same action ID for child pages, the founding page, continuity permits and the roster entry. The signed founding hash is derived from those exact pages and remains the roster's commitment. The backend rechecks the binding before signatures and at the guarded store commit. A different cell or a stale review needs its own confirmation.
