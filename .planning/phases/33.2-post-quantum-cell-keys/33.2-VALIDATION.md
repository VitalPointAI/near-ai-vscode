## Managed cell confidential handoff

Plan 33.2-09 Task 2 supplies a private connector inside the normal sync exchange. The synthetic connector exercises committed supplemental and founding grants plus a separate continuity receipt. The latest authenticated roster controls intake. An affected cell can wait for its founding grant while a verified unaffected cell writes. The multi-page sync fixture also pairs continuity with each selected grant-only revision before that revision is visible to a writer. A delayed current proof pauses that cell, an older proof is refused, and a later exchange with the current proof resumes writes.

A configured confidential provider can keep recipient-side pending opaque handles in the private replica store. A local fixture checks scope and storage mode, restart recovery, expiry, accepted and superseded acknowledgment, concurrent reservation, and bounded retries. Eligible handles are retried on later exchanges. Each request to the opaque route contains only the handle.

A configured sender revalidates the current authorized grant or continuity receipt and stages the randomized handle and sealed packet in the private store before calling the opaque route. The local fixture reopens after a failed upload and observes the same handle and packet, then reopens after the upload succeeded and resumes confidential publication without uploading again. Local acknowledgment prevents repeated publication after completion and expired reservations stop sending. After an interruption with an ambiguous remote result, the retry uses the same handle and packet. Route uploads and confidential publication need idempotence by that handle.

The handover records five focused and 288 impacted checks at `34120732` for the recipient queue, and six focused and 289 impacted checks at `fd23fe38` for the sender. Those runs cover local persistence and synthetic exchange, including identical bytes and handle after an uncertain upload and resuming confidential publication after known upload. The production receiver's handle path remains unverified.

Local file and synthetic sync packets now carry a sender-signed statement inside the encrypted envelope. It binds the random handle, project, recipient, exact artifact digest, roster and access commitment, issuing device or certified session, and the deadline. A hosted session’s deadline cannot exceed its certificate expiry. The recipient verifies signature, current authority and commitment before pairing, promotion or acknowledgment. Durable sender and recipient queues pass the signed deadline to the confidential exchange and compare it with the packet before use. The opaque relay sees the same handle and padded ciphertext.

An early file waits as its original sealed packet while its roster arrives. Active waiting files are capped. Expired records remain private and dormant in the access-evidence archive. Promotion checks the current authenticated roster and the signed deadline immediately before placing live evidence. The synthetic fixture covers a roster arriving after expiry, and the earlier fixture still covers a timely reopen and promotion.

The Workbench save and open workflow is wired to a separate bounded file reservation. Reopening and selecting the same live grant permits the exact bytes to be saved again. A repeat handle cannot substitute a different recipient or expired issuance. An explicit new save can prepare an authorized current grant after expiry. Local fixtures cover the neutral filename, duplicate import, a changed packet or local cache, stale targets and a changed workspace during export. Formal hosted browser and real confidential provider verification remain open. A fresh device missing base history needs Task 3's authenticated bootstrap and accepted frontier before the invitation flow can count as verified. The current managed welcome can carry roster material and omits raw grants.

Automatic delivery has a separate production prerequisite. `LiveReplicator.transportFor` currently creates `HubTransport` without a managed route or a configured confidential handoff provider. `HubTransport.grant` and the hub grant store tie raw grants to project/device sessions. Prove a distinct approved route that accepts an opaque handle plus sealed and padded bytes on put, and a handle on get, with no stable identity linkage at the relay. Prove authenticated, durable handle transfer with the exact sealed expiry, idempotence by handle through ambiguous upload, publication and acknowledgment, network deadlines and bounded retries across restarts. Inspect the actual request, authorization, storage, log and metric surfaces and record residual packet-size, count and timing visibility. Allow authorized direct file recovery where the route is unavailable. Any new route location or exception to the metadata boundary remains an owner decision.

## Hosted managed withdrawal

The local managed withdrawal API binds confirmation to the exact operation, roster predecessor and selected access root. The synthetic tests exercise the existing hosted person signer and close the action window during the store's staged write. A confirmation for a different operation cannot sign it, and an expired confirmation cannot commit it. An expired operation can leave a private sidecar whose signed roster entry was never written, so that evidence remains dormant.

Workbench's hosted managed Remove flow uses the existing review page and the same pending-action registry as the person signer. The service recomputes the binding from the current roster before resuming. Hosted Finish and grant actions and formal browser verification remain open. Browser acceptance requires 33-30 on main and uses the existing container harness.

Hosted Finish follows the independently reviewed Task 2 contract. The existing passkey page confirms one part against an immutable private, exact unsigned grant intent and current authorization. Before each call, the scoped signer checks the next role and stage index and compares the exact canonical signed-domain bytes to those derived from that intent and verified earlier stages. Every authorized call uses the same action ID. The signed founding hash is derived from those exact pages and remains the roster's commitment. The backend verifies returned signatures and rechecks the binding at the guarded store commit. A different cell or a stale review needs its own confirmation.

The local hosted draft and grant signing checkpoint prepares one selected pending cell without signing or writing. Synthetic fixtures cover a fixed single page and a multi-page verified prefix. A child or founding request must match its canonical envelope, role and index. Each child signature is verified before its hash can enter the founding page. The draft is invalidated if an eligible session ages out. Ordinary hosted managed rekey refuses before contacting the signer. Verified grant pages also determine the exact rekey operation and access revision. Synthetic permit signing checks the ordered cell, device and writer, including the exact session certificate, and advances only after signature verification. The prepared entry helper seals once and ties its header signature to canonical copies of the exact sealed body and blobs.

The store checks authority under lock after staging access evidence and before making either the blob or entry live. An expiry during access-sidecar sync leaves only the dormant sidecar. The local hosted engine now derives the final access commitment from the still-selected evidence and exact verified permits. It compares the frozen entry against the reviewed operation, checks the signatures and full staged fold, then carries the immutable sealed artifact, current action authority and captured snapshot to the existing store lock. A synthetic protected-cell fixture exercises wrong approval, a competing write, expiry after sidecar staging, restart recovery, and an independent second pending cell. Workbench now lists pending parts for the current hosted lead and uses the existing review page for one part at a time. The draft stays attached to its pending action in the session backend. On return, the service resolves the current workspace, project instance, actor and signer, recomputes the exact review bytes, and resumes once. Synthetic checks cover an early return, replacement, cancellation, expiry, restart, replay, and a fresh review after an expired commit. Formal hosted browser acceptance remains open.
