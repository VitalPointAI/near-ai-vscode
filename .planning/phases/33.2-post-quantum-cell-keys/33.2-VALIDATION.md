# Phase 33.2: Validation Strategy

> Per-phase validation contract for 8 plans in 7 waves. Every test uses fictional people, devices and keys; vectors use recorded seeds.

`nyquist_compliant` stays false: every task has an automated check written first, but 33.2-08's container run takes up to 2400 s, above the per-task target, and each test file is created by its own task (tests first).

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `node:test` through `scripts/run-tests.mjs` (root, Node 24.22 with OpenSSL 3.5.9); the hub in `hub/` on Node 26.13.1; `npm --prefix workbench test`; the container suite `npm --prefix workbench run test:container` |
| **Quick run (root)** | `flock "$HEAVY_LOCK" systemd-run --user --scope -q -p MemoryMax=4G -p MemorySwapMax=0 choom -n 1000 -- timeout 300 env NODE_OPTIONS=--max-old-space-size=1536 sh -c 'npm run compile && node scripts/run-tests.mjs dist/test/<file>.test.js'` |
| **Hub run** | `cd hub && flock "$HEAVY_LOCK" systemd-run --user --scope -q -p MemoryMax=4G -p MemorySwapMax=0 choom -n 1000 -- timeout 600 env PATH="$HOME/.nvm/versions/node/v26.13.1/bin:$PATH" NODE_OPTIONS=--max-old-space-size=1536 sh -c 'npm run build && node ../scripts/run-tests.mjs dist/test/<file>.test.js'` |
| **Full suites** | 33.2-08 only, once each, one at a time |

Never bare `node --test` and never an uncapped `npm test`.

## Sampling Rate

- **After every task commit:** the task's own `<automated>` command.
- **After every wave:** the wave's new tests, `replicaCellKeys`, `replicaRoster`, `replicaCellLeak`, `architecture`, and the hub files when touched.
- **Blocking in every wave (crypto and data integrity):** v1 and v2 vectors, binding checks, the cutover rule in the fold and the hub, the Protected B rule, the architecture check.
- **Browser:** only the step-up on the switch is blocking (33.2-08); the rest is diagnostic.
