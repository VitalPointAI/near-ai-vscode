# Phase 33.2 Plan 03: Grant pages Summary

**An epoch's wraps for any number of devices fit in signed pages of at most 607 v2 wraps each, all committed by the one founding hash the roster holds; the fold and your organization's server read them as one grant.**

## Accomplishments

- Tracer: 2,000 v2 wraps make four pages, each within `GRANT_MAX_BYTES`, read back whole with the label; 400 make one page; 4,000 v1 wraps make the same v1 grant as `buildGrant`.
- Named refusals: `page-bad-signature`, `page-other-epoch`, `page-not-listed`, `page-missing`, `page-repeats-device`, `founding-malformed`.
- The roster fold places a paged founding grant with all its pages; a missing page holds it `missing-blob` until the page arrives; a changed page is refused and the founding grant waits.
- The hub keeps each page under its own hash, refuses to keep a founding page whose pages do not fold (`grant-not-placed`), and its key ring finds the hub's wrap on the second page.

## Task Commits

1. Tracer: `148d79d2` (test), `f11a0e5c` (feat)

## Deviations from Plan

- **No `readGrantPages` in `rosterCache.ts`:** the hub's ring already reads every grant it holds, so it finds its own wrap on any page without the page reader; `placedGrantsOf` counts each listed page as placed. `hubStore.ts` needed no change (grants are stored by hash).
- **Tests first:** for Task 2, tests and implementation were written together and committed test-first; the failing state was not run separately.
