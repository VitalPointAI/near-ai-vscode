# Phase 62 - UI Design Contract

> Visual and interaction contract for the Team Board (sidebar list, editor-panel kanban, card face, card detail, New item form, move flows, status bar line). Generated by gsd-ui-researcher in AUTO mode, to be verified by gsd-ui-checker. Every open question was resolved with the recommended option and recorded in "Decision Log" with its source.

Sources read: 62-CONTEXT.md (D-01 to D-18, locked), 62-RESEARCH.md (Webview design, Board model, Live updates, Pitfalls 6 and 9), 62-PATTERNS.md, UX-CONTRACT.md, 61-UI-REVIEW.md, media/activity, media/tools and media/mcp CSS, src/services/team/teamStatusBar.ts.

Surfaces in this phase:

| Surface | Host | Layout | Entry point |
|---------|------|--------|-------------|
| Team Board sidebar view | Webview view `nearAiTeamBoardView` in the NEAR AI container (visible only when `nearAi.teamMode` is set) | Compact list grouped by state | NEAR AI sidebar (the view itself); status bar click and `NEAR AI: Open Team Board` open the editor panel |
| Team Board editor panel | `createWebviewPanel('nearAiTeamBoard', 'Team Board')`, one at a time, `reveal()` when open | Kanban with swimlanes | "Open Team Board" button in the sidebar, status bar click, command |
| Team status bar line | `vscode.StatusBarItem` | One line of text with codicon | Always shown while a team session runs |
| Native prompts (host side) | `showInputBox`, `showWarningMessage` modal, `withProgress` notification | Native VS Code UI | Block, cancel, mark done, import |

One webview codebase (`media/board/board.js`, `board.css`) draws both layouts. The same model object feeds both.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (VS Code theme tokens plus plain CSS, following the existing `media/activity`, `media/tools`, `media/mcp` pattern). shadcn is not applicable to a VS Code webview. `shadcn init` is not run. |
| Preset | not applicable |
| Component library | none (hand-built DOM with `document.createElement` and `textContent`, as in `media/activity/activity.js`) |
| Icon library | codicons. Webviews cannot use the `$(name)` syntax, so the codicon CSS and font file are vendored into `media/board/` (see "Icons" below). The status bar and native prompts use `$(name)` directly. |
| Font | `var(--vscode-font-family)` at `var(--vscode-font-size)`. Monospace (GSD IDs, file globs): `var(--vscode-editor-font-family)`. No web fonts, no remote resources. |
| Colour source | `--vscode-*` CSS variables only. No hex, rgb, hsl or named colour literals anywhere in `board.css`. Fallbacks, when needed, point at another `--vscode-*` variable. `color-mix(in srgb, var(--vscode-xxx) N%, transparent)` is allowed for tints because it derives from theme variables. |
| Themes | Must read correctly in light, dark, high contrast dark and high contrast light (`vscode-high-contrast`, `vscode-high-contrast-light` body classes) and in `forced-colors: active`. |

Component Inventory: omitted on purpose (`Tool: none`, no component package exists to enumerate). The hand-built building blocks are listed under "Building blocks" so the planner and auditor share names.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon to text gap, gap inside a card between rows, badge padding vertical |
| sm | 8px | Card padding vertical, gap between badges, gap between buttons, menu padding |
| md | 12px | Card padding horizontal, gap between cards, gap between columns, toolbar row gap, narrow-width body padding (matches the existing 12px at max-width 520) |
| lg | 16px | Body horizontal padding (editor panel), toolbar padding, detail section gap |
| xl | 24px | Space between lanes, detail drawer padding |
| 2xl | 32px | Bottom padding of the scroll area |
| 3xl | 64px | Not used in this phase |

Fixed sizes (all multiples of 4 except the listed exceptions):

| Item | Value |
|------|-------|
| Column width (kanban) | `minmax(224px, 288px)`, collapsed stub 40px |
| Detail drawer width (kanban) | 360px, `max-width: 50%` of the panel |
| Icon size | 16px (codicon default) |
| Minimum interactive target | 24px by 24px (WCAG 2.5.8), 28px for icon buttons in the list |
| Progress bar height | 8px |
| Menu min width | 192px, max width 320px, max height 320px with scroll |
| Breakpoint | 520px webview width (matches the existing `@media (max-width: 520px)` in `media/activity`) |

Justified exception, md = 12px: it is a multiple of 4 and is kept because it is the existing gap and narrow-width padding in `media/activity/activity.css` (`--gap: 12px`, `padding: 0 12px` at max-width 520), so the board matches its sibling webviews. Other exceptions: 1px borders and dividers, 2px focus outline offset where needed to avoid clipping, 3px selected-card inset bar (existing precedent `box-shadow: inset 3px 0 0 var(--vscode-focusBorder)`), 2px and 4px border radii (buttons 2px, cards and menu 4px, pills 8px).

Density: this is a work surface. Card padding is `8px 12px`. The sidebar list row padding is `8px 8px`.

## Typography

All sizes are relative to `var(--vscode-font-size)` so the board follows the user's editor zoom and font settings. Exactly 4 sizes and 2 weights. Heading is 1.2em (not the 1.1em of `media/activity` h2) so a heading is clearly larger than 1em body once the semibold weight is accounted for; Display is 1.5em to keep a clear step above Heading.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Small (label) | 0.85em | 400 | 1.4 | Badges, meta rows, column captions, ages, helper text, field hints, history timestamps |
| Body | 1em | 400 | 1.5 | Card titles, descriptions, list rows, menu items, form fields, banners |
| Heading | 1.2em | 600 | 1.2 | Column titles, lane titles, group headers, detail section headings, card detail title |
| Display | 1.5em | 600 | 1.2 | Editor panel page title "Team Board" and the empty-state heading only. Not used in the sidebar (sidebar title uses Heading size). |

Weights: 400 regular and 600 semibold only. No italics. GSD IDs and file globs use `var(--vscode-editor-font-family)` at Small or Body size, weight 400 (ID in a card title row may be 600 when it is the leading token of the row).

Text handling: card titles clamp to 3 lines in the kanban and 2 lines in the list (`-webkit-line-clamp`, full text in the `title` attribute and in the detail). All text containers use `overflow-wrap: anywhere` so a 520 character must-have, a 93 character path, or a long unbroken token never forces horizontal scroll in the list layout. Numbers use `font-variant-numeric: tabular-nums`.

## Color

Every value is a VS Code theme variable. No custom palette. State is never encoded by colour alone: every state carries an icon and a text label.

| Role | Value (CSS variable) | Usage |
|------|----------------------|-------|

| Accent (10%) | `--vscode-focusBorder`, `--vscode-button-background` with `--vscode-button-foreground`, `--vscode-textLink-foreground`, `--vscode-progressBar-background` | See "Accent reserved for" |
| Warning | `--vscode-editorWarning-foreground` | Blocked badge text and icon, offline banner icon, "Looks finished, please confirm" is NOT warning (uses info) |
| Info | `--vscode-editorInfo-foreground` | "Looks finished, please confirm" badge, notice banners |
| Success | `--vscode-testing-iconPassed` | Done state icon, done task check, "Live" status icon (existing precedent in media/tools and media/activity) |
| Destructive / error | `--vscode-errorForeground` | Refusal message on a card, error banner, invalid field text, `aria-invalid` field border `--vscode-inputValidation-errorBorder`. Used for nothing else. |
| Hover / selection | `--vscode-list-hoverBackground`; selected card tint `color-mix(in srgb, var(--vscode-focusBorder) 12%, transparent)` over the card background, text stays `--vscode-foreground` | Card hover, selected card |
| Inputs | `--vscode-input-background`, `--vscode-input-foreground`, `--vscode-input-border`, `--vscode-dropdown-*` for selects | Filters, form |
| Menu | `--vscode-menu-background`, `--vscode-menu-foreground`, `--vscode-menu-selectionBackground`, `--vscode-menu-selectionForeground`, `--vscode-menu-border` (all with the fallbacks already used in `media/activity/activity.css`, minus hex) | Move to... menu |
| High contrast | Add `1px solid var(--vscode-contrastBorder)` to cards, menu, banners, badges when `body.vscode-high-contrast` or `body.vscode-high-contrast-light` | Required so borders survive |

Accent reserved for (explicit, never "all interactive elements"):
1. Focus ring on every focusable element: `outline: 1px solid var(--vscode-focusBorder); outline-offset: 1px` (existing pattern).
2. The 3px inset bar on the selected card (detail open) and the active lane/column header while dragging.
3. The 2px dashed outline on drop cells that accept the dragged card.
4. Primary buttons only: "New item" (toolbar), "Add item" and "Save changes" (form), "Import plans" (empty state for owner and lead). One primary button per visible surface state.
5. Link-style buttons (`button.link`): requirement chips in detail, dependency links, "Clear filters", "Show all".
6. Progress bar fill in lane headers and the milestone summary.

Colours that are deliberately not used: no per-state colours (columns are neutral), no custom red/green/blue, no gradients, no shadows other than the existing menu border.

Contrast note for the executor: muted text (`--vscode-descriptionForeground`) is only placed on `--vscode-editor-background`, `--vscode-sideBar-background` or `--vscode-editorWidget-background`. It is never placed on the tinted selected or drop-target backgrounds; those use `--vscode-foreground`.

## Layout

### Width rule (D-15)

A `ResizeObserver` on the root decides the layout from the webview's own width: **under 520px draws the compact list, 520px and over draws the kanban**. The sidebar is normally list and the editor panel is normally kanban, but a narrow editor panel shows the list and a very wide sidebar shows the kanban. Switching layout keeps the selected card, open detail, filters and collapsed state (all in `getState/setState`).

### Focal points (the one thing the eye lands on first)

| Surface | Primary visual anchor | How it is made dominant |
|---------|----------------------|-------------------------|
| Kanban, first screen | The Ready column: its header and cards, directly under the toolbar's `New item` button | Ready is the only column whose count change drives the status bar, so it is first in attention order after Backlog; headers use Heading size with a state icon, the sticky toolbar's only primary-filled control is `New item`, and cards carry the only 3px selected bar on screen |
| Sidebar list | The open Ready group at the top, with `New item` as the only filled button | Ready and Backlog are open by default, every other group is a closed one-line header, so the first screen is Ready cards |
| Empty board | The Display-size heading `No work on the board yet` and the single primary button (`Import plans` for owner and lead, `New item` for developers) | Centered column, nothing else filled or larger on screen; the summary line and filters are hidden until cards exist |
| Card detail drawer | The card title (Heading size, semibold) with its state icon and word, and directly under it the blocked notice when one exists | Title block is the first element, the only Heading-size text above the section headings, and `Move to...` sits in the same row |

### Compact list (sidebar, under 520px)

Top to bottom:
1. **Header (sticky)**: line 1 title "Team Board" (Heading size) and the status chip (see "Status chip"). Line 2 buttons: `Open Team Board` (secondary, icon `link-external`), `New item` (primary, icon `add`). Buttons wrap to full width below 280px. Owners and leads also see `Import plans` (secondary, icon `sync`) as a third button.
2. **Banners** (stacked, only those that apply): paused/offline, read-only, error, notice.
3. **Summary line** (Small, muted): `{n} cards · {r} ready · {b} blocked` ("1 card" singular). Milestone picker below it as a labelled select: label "Milestone", options the current milestone first, then others, then "All milestones".
4. **Filters disclosure**: a button `Filters` (icon `filter`, shows `Filters (2)` when 2 are active) with `aria-expanded` and `aria-controls`. Collapsed by default. Expanded content: toggle chips `Mine`, `Ready`, `Blocked`; select `Phase`; text input `Requirement` with a `datalist` of requirement IDs on the board; `Clear filters` link button (only when any filter is on).
5. **State groups**, in column order: Backlog, Ready, Claimed, In progress, In review, Shipping, Done, Cancelled. Each group is a heading (`h2`) containing a button: chevron, state icon, state name, count in brackets (`Ready (3)`), `aria-expanded`. Default open: Ready, Backlog. Default closed: every other group (empty groups are closed and show their caption when opened; Done and Cancelled closed even when they have cards). Empty group opened shows the line "No cards here." and, for Claimed, In progress, In review and Shipping, the caption from the copy table so the list looks the same in every phase (D-13).
6. **Rows** inside a group: `ul > li`. Each row: a main button (state icon, ID in monospace, title up to 2 lines) and a `Move to...` icon button on the right. Second line (Small, muted): badges and meta in the order used on the card face. Rows are never draggable (D-16). Row height grows with content; no fixed height.
7. Clicking a row main button opens **detail as a drill-in page**: the list is replaced by the detail with a `Back to list` button (icon `arrow-left`) at the top. Focus moves to the detail heading. Back restores focus to the row that opened it, scroll position preserved.

At 200px (the narrowest VS Code sidebar) nothing scrolls horizontally: buttons wrap, the status chip drops under the title, badges wrap, the `Move to...` button stays 28px square.

### Kanban (editor panel, 520px and over)

1. **Toolbar (sticky)**, two rows that wrap:
   - Row 1: `h1` "Team Board" (Display size) with status chip; right aligned: `Import plans` (secondary, owner and lead only), `New item` (primary).
   - Row 2: milestone select (label "Milestone"), the milestone summary `v0.6.0 Team Mode: 62%, 16 of 26 plans done` with a progress bar (weighted by estimate, text always shown), "Group by" segmented control (`Member`, `Phase`, `Milestone`, `None`; default Member), filters inline (chips Mine, Ready, Blocked; select Phase; Requirement input; `Clear filters`).
2. **Banners** under the toolbar.
3. **Column header row** (`role="toolbar"`, `aria-label="Columns"`, sticky below the toolbar): 8 columns in this order: Backlog, Ready, Claimed, In progress, In review, Shipping, Done, Cancelled. Each header: state icon, name, count, collapse chevron button (`aria-expanded`), and a one-line caption (Small, muted) on the four columns that later phases own: "Claiming arrives in a later update." (Claimed), "Starting work arrives with claims." (In progress), "Review arrives in a later update." (In review), "Adding finished work to the project arrives in a later update." (Shipping). Backlog caption: "Waiting, on hold or not ready." Ready caption: "Ready to be claimed." Done caption: none. Cancelled caption: none.
4. **Lanes**: for each lane a `section` with a header button (chevron, lane label, card count) and, for Phase and Milestone lanes, the progress block (`8px` bar, text `60%, 3 of 5 plans done`, or `No plans yet` with no bar). A lane with no plans starts collapsed. Under the header, one grid row of 8 cells aligned to the column headers. Group by None draws one row with no lane header.
5. **Horizontal scroll**: the board region scrolls horizontally when the columns exceed the width (8 columns at 224px is about 2000px). Column header row and cell rows scroll together. Collapsed columns are 40px stubs showing the icon, the count and the vertical name; clicking the stub or pressing Enter on its header button expands it.
6. **Detail drawer**: `aside#detail` on the right, 360px, opened by Enter or click on a card; non-modal; the board stays usable. `Close details` button, Escape closes it. Opening moves focus to the detail heading; closing returns focus to the opener card.

Card sort order inside a cell: Backlog, Ready, Claimed, In progress, In review, Shipping: ascending by phase number then plan number, board-created items after plans in creation order. Done and Cancelled: descending (newest phase and plan first). No wall-clock ordering. A cell with more than 30 cards shows the first 30 and a `Show all {n}` link button.

Member lanes: before Phase 63 every card is in one lane labelled `Unassigned`; board-created items still sit there and show `Created by {name}` in the card meta. From Phase 63 the lane label is the claimant's name. Lane order: members alphabetically by display name, Unassigned last. Phase lanes ascending by phase number. Milestone lanes: current first.

The initial live view of this repository's own roadmap is mostly the Done column (26 plans) with phases 62 to 67 as collapsed "No plans yet" lanes under Group by Phase. This is the intended first-run look and must read as complete, not broken.

## Card Face

Same content in list and kanban, laid out as below (kanban card, 8px 12px padding, 4px radius, 1px border, background `--vscode-editorWidget-background`).

| Row | Content | Notes |
|-----|---------|-------|
| 1 | State icon, GSD display ID, kind badge for board items | Plans show `62-03` (strip `plan:`). Board items show kind word plus the last 4 characters of the ULID in capitals, for example `Bug 7F3K`. IDs in monospace. |
| 2 | Title | Body size, weight 600 only for the ID, title regular. Clamp 3 lines (kanban) or 2 lines (list). |
| 3 | Meta row, wraps | In this order: assignee initials chip (Phase 63, hidden until claimed), `Blocked` badge, `On hold` badge, `Looks finished, please confirm` badge, dependencies `link` icon plus `2 dependencies` (hidden at 0, `1 dependency` singular), estimate `Est. 48k tokens` or `No estimate`, age `clock` icon plus `3 days` |
| 4 | Pending line (only while a write is in flight) | `Moving to Done...` or `Saving...`, Small, muted, card has `aria-busy="true"` |
| 5 | Refusal line (only after a refused move) | `error` icon plus reason, `--vscode-errorForeground`, with a `Dismiss message` icon button |
| 6 | Footer | `Move to...` button (hidden when the viewer has no permitted move) |

Formats: estimate `800 tokens`, `48k tokens`, `1.2M tokens`; age `Under 1 hour`, `5 hours`, `1 day`, `3 days`, `2 months` (60 days and over), computed by the host from the display-only `at` of the last state change and passed in as text; the webview never reads a clock for this. Age for an imported card counts from its import event.

Badges: pill, 1px `currentColor` border, Small size, always icon plus word. Blocked uses warning colour and shows only `Blocked` on the face; the reason is in the detail and in the accessible name. Looks finished, please confirm appears when a plan gained a SUMMARY but its stored state is not done (D-06); only owner and lead see a `Mark done` path for it (via Move to...).

Card states:

| State | Visual | Non-visual |
|-------|--------|-----------|
| Default | border `--vscode-panel-border` | |
| Hover | `--vscode-list-hoverBackground` | |
| Focus (roving) | 1px `--vscode-focusBorder` outline, 1px offset | `tabindex="0"` on the active card, `-1` on the rest |
| Selected (detail open) | 3px inset left bar `--vscode-focusBorder` plus 12% tint | `aria-current="true"` on `card-main` |

| Pending | dashed border plus the pending line | `aria-busy="true"` |
| Refused | refusal line stays until dismissed, the next move attempt on that card, or the card's data changing | announced once in the live region |
| Changed by a teammate | 3 second 2px outline `--vscode-editor-findMatchHighlightBackground` (static, no animation) | summarised in the live region, not announced per card |
| Done | success-coloured `pass` icon, title regular | |
| Cancelled | title with `text-decoration: line-through` plus the word `Cancelled` badge | never strike-through alone |

Accessible name of `card-main` (`aria-label`), built by one pure function, example: `Plan 62-03, Board webview client. State: Ready. Blocked: no. 2 dependencies. Estimated 48 thousand tokens. In this state for 3 days.` Variants insert `Blocked: waiting for the API key.`, `On hold.`, `The project plans say this is finished. Waiting for someone to confirm.`, `Cancelled.` The name never contains raw HTML and is set via `setAttribute`. `aria-describedby` points to one hidden node: `Press Enter to open details. Press M to move this card.` (omitted when the viewer cannot move it: `Press Enter to open details.`).

## Card Detail

Heading order inside detail: `h2` is the card title, `h3` for each section. Sections in order (a section with no data is omitted, except History and Tasks which show their empty line):

1. **Title block**: state icon and state word, display ID, title (Heading size), badges, then actions: `Move to...` (hidden when no moves), `Edit` (only for a board-created item the viewer may edit, see Permissions), `Close details` (kanban) or `Back to list` (list).
2. **Blocked notice** when blocked: `Blocked by {name}: {reason}` with the time (`<time datetime>`). Reason is user text, set by `textContent`.
3. **Why this is not ready** (Backlog cards only, from `readiness().reasons`): bullet list in plain words: `It has no estimate.`, `It does not say which parts of the project it covers.`, `It waits for {n} unfinished plan(s).`, `A plan it depends on is not on the board.`, `It is blocked.`, `It is on hold.`, `Its phase is on hold.`
4. **Facts** (`dl`): Phase, Milestone, Order within the phase (plans), Type, Created by (board items), Estimate, In this state for, Where it came from (`From the project plans` or `Added on the board`).
5. **Description** (board-created items only; imported items carry none, see A1).
6. **What must be true when it is done** (`ul`, wrapped text, each up to 600 characters).
7. **Requirements**: link-style buttons, each applies the requirement filter (`aria-label` `Filter the board by BOARD-01`).
8. **Dependencies** (`ul`): each row is a button `62-01 Work model` with state icon and state word; missing ones read `61-09 (not on the board)` as plain text.
9. **Files** (`ul`, monospace): first 8 shown, `Show all {n}` link button for the rest.
10. **Tasks** (checklist): `ul`, each row icon (`pass` or `circle-outline`) plus the word `Done` or `To do` (visually in Small muted, not only sr-only), task title. Summary line `3 of 5 tasks done` first. Tasks are never cards (D-07).
11. **History**: `ol`, newest first, at most 50 (D-18, Pattern 8). ## Moving Cards

### Offered moves (D-12, D-16, planMove)

`Move to...` lists exactly the targets in the card's `moves` array (the host computed it with `planMove`; the webview does not decide). Labels are plain words with the effect in brackets. Items appear in this order; Block/Unblock follow a `role="separator"`.

| Menu label | Resulting event | From | Who |
|------------|-----------------|------|-----|
| `Done (mark as finished)` | mark done | unclaimed | owner, lead |
| `Cancelled (cancel this item)...` | cancel with reason | unclaimed, blocked | owner, lead |
| `Backlog (put on hold)` | hold | Ready | owner, lead |
| `Ready (release the hold)` | release | held Backlog | owner, lead |
| `Backlog (reopen)` | reopen | Done, Cancelled | owner, lead |
| separator | | | |
| `Block...` | block with reason | not done, not cancelled, not blocked | owner, lead |
| `Unblock` | unblock | blocked | owner, lead |

An ellipsis after a label means a prompt follows. Targets that claim or integration own are never in the menu (D-16). Ready cannot be chosen for a Backlog card that is not computed ready; that case is only reachable by drag and gives the refusal in "Refusal copy".

### Pointer path (kanban only)

- Cards are `draggable="true"` only when `moves.length > 0`. The sidebar list never drags.
- `dragstart`: set `dataTransfer` type `application/x-near-ai-card` to the item id (not `text/plain`, so dropping on an editor inserts nothing), `effectAllowed = "move"`, add `.dragging`. Announce nothing.
- During drag: cells whose column is in the card's `moves` and which are in the card's own lane get the 2px dashed `--vscode-focusBorder` outline and a 12% tint. All other cells stay quiet but still accept the drop so the reason can be given; hovering one shows a transient caption inside the cell (Small, `role="presentation"`): `Can't drop here: {reason}`.
- `drop` on an offered cell: post `move`, show the card's pending line `Moving to {Column}...`, keep the card where it is until the new state arrives, then relocate it (with the 150ms move transition when motion is allowed) and announce `Moved plan 62-03 to Done.`
- `drop` on a refused cell: no message to the host, no relocation; the card shows the refusal line immediately using the card's own `refusals[column]` text, and the live region announces `Can't move plan 62-03 to {Column}. {reason}`. This is the snap back: the card never leaves its cell, the drag image returns, and the reason stays on the card.
- Dropping on the card's own column does nothing and says nothing. Dropping in a different lane is refused with `This card stays in its own row. Drop it in another column of the same row.`
- **Escape cancels the drag**: the browser cancels native drag on Escape; the client also listens for `dragend` with `dropEffect === "none"` and no `drop` seen, clears all highlights and announces `Move cancelled. The card is still in {Column}.`
- The host re-checks every move on fresh state; a stale offer produces a `refused` message and the same refusal line.

### Keyboard path (all layouts)

See "Keyboard Model". `M`, Shift+F10 or the ContextMenu key on a card, or Enter/Space on its `Move to...` button, opens the menu. This satisfies WCAG 2.5.7 (no dragging-only function).

## Keyboard Model

Principles: every function is reachable and operable without a pointer; one tab stop per group (roving tabindex); arrow keys move inside a group; Escape always backs out one level; focus is never lost to `body`.

### Tab order (kanban)

1. Toolbar controls in visual order: milestone select, Group by segmented control (one stop, arrows move between radios), chips, Phase select, Requirement input, Clear filters, Import plans, New item.
2. Banner actions (Try again, Show details) are placed in the DOM directly under the toolbar so they come next.
3. Column header row (`role="toolbar"`, one stop; Left/Right move between column buttons; Enter or Space collapses or expands).
4. For each lane in order: the lane header button (one stop), then that lane's cards as one roving group (one stop on the active card), then the active card's `Move to...` button, then the active card's `Dismiss message` button if present. Tab leaves the lane and goes to the next lane header.
5. `Show all {n}` link buttons, in DOM order after the cells they belong to.
6. The detail drawer (if open) is last in the DOM, so Tab reaches it after the board; opening it moves focus into it.

### Tab order (list)

Header buttons, banners, summary milestone select, Filters disclosure and its contents (when expanded), then for each group: the group header button (one stop), then, when open, the group's rows as a roving group (one stop on the active row) followed by that row's `Move to...` button.

### Keys

| Context | Key | Action |
|---------|-----|--------|
| Card group (kanban) | Left / Right | Move to the card in the previous / next column of the same lane with cards; keeps the vertical index when it exists, else the last card. Does nothing at the ends. |
| Card group (kanban) | Up / Down | Previous / next card in the same cell. Does nothing at the ends. |
| Card group | Home / End | First / last card in the current cell |
| Card group | Ctrl+Home / Ctrl+End | First / last card in the lane |
| Row group (list) | Up / Down, Home / End | Previous / next, first / last row in the group |
| Card or row | Enter or Space | Open detail (the button's native activation) |
| Card or row | M, Shift+F10, ContextMenu | Open the Move to... menu for this card (only when it has moves; otherwise do nothing) |
| Card | Delete / Backspace | No effect (there is no delete) |
| Group, lane, column header | Enter or Space | Toggle expanded |
| Column header toolbar | Left / Right, Home / End | Move between column buttons |
| Group by segmented control | Left / Right (or Up / Down) | Change selection and apply immediately |
| Menu | Down / Up | Next / previous item, wrapping |
| Menu | Home / End | First / last item |
| Menu | a letter | Jump to the next item starting with that letter |
| Menu | Enter or Space | Run the item, close the menu |
| Menu | Escape | Close, return focus to the `Move to...` button |
| Menu | Tab | Close and continue to the next element in the page order |
| Detail | Escape | Close the detail (when no menu or prompt is open) and return focus to the opener |
| Form | Escape | Same as `Close form` (with the discard rule) |
| Drag in progress | Escape | Cancel the drag, announce `Move cancelled...` |
| Anywhere in the board | none other | No global single-key shortcuts except M on a focused card |

After a successful move, focus goes to the same card at its new place (the client looks it up by id when the next `state` arrives). After a refusal, focus returns to the `Move to...` button or the card that started the move. After a form submit succeeds, focus goes to the new card if it is visible with the current filters, else to the `New item` button.

| Columns | `columns: [{ key, label, caption?, count }]` (always 8) |
| Lanes | `lanes: [{ key, label, count, progress?, collapsedByDefault }]` per grouping |
| Cards | `cards: [{ id, displayId, kind, title, column, stateLabel, lane: { member, phase, milestone }, blocked?: { reason, byName, since }, held, doneInGsd, dependencyCount, estimateText, ageText, initials?, createdByName?, moves: [{ key, label, effect, needsPrompt }], refusals: { [column]: reason }, a11yLabel }]` |
| Detail (on demand) | `{ itemId, facts, mustHaves, requirements, dependencies, files, tasks, notReady, history }` |

Selectors the client must expose (stable ids and data attributes for tests): `#live`, `#banner`, `#toolbar`, `#detail`, `#menu`, `#item-form`, `.column[data-column]`, `.lane[data-lane]`, `.cell[data-column][data-lane]`, `.card[data-id]`, `.card-main`, `.move-btn`, `.group[data-column]` (list).

Messages (host validates every one, unknown shapes are ignored): webview to host `ready`, `visible {value}`, `move {itemId, target}`, `new-item {draft}`, `edit-item {itemId, changes}`, `detail {itemId}`, `import-plans`, `open-board`, `retry`, `show-details`; host to webview `state {model}`, `refused {itemId, reason}`, `notice {text}`, `detail {itemId, ...}`. The reason for block and cancel is gathered by the host with the native prompts above, so `move` carries no reason; a cancelled prompt makes the host reply `refused {itemId, reason: ''}` which clears the pending line silently.

### Layout rule (kanban)

- **Toolbar band:** the toolbar and banners are bands with a solid editor background, never see-through. The page itself does not scroll in the kanban. (62-21)
- **One board scroller:** the board region below the toolbar is the only element that scrolls, in both directions, so cards never pass under the toolbar. (62-21)
- **Sticky column header row:** the column header row sits at the top of the board region, stays there while the board scrolls, and has a solid background above the cells. The header row and every lane share one column grid, so headers and cells always line up. (62-21)
- **Cells as tall as their row:** every cell in a lane row is as tall as the row, and nothing in one lane spills into the next. (62-21, checked by the 62-16 layout probe and proven across widths and themes by 62-22)
- In the list layout the page scrolls normally and the toolbar is not sticky. (62-21)

### Readable cards

- A folded column holds no cards: its stub shows only the column name and count. (62-21)
- Titles wrap between words, never inside a word. (62-21)
- The card's main button keeps card styling: left aligned, theme text colour, no button background. (62-21, proven by 62-22)
