Existing (boardView.ts): BoardController.move(state, itemId, target) plans a move three times (known state for the prompt, current state after the prompt, fresh state inside log.append) and answers { type: 'refused', itemId, reason } (reason '' for a dismissed prompt); the write bucket of T-62-49; staleRefusal(name) for a card someone else changed first.
Existing (page): NearAiBoard api (post, cardData, setPending, showRefusal, openMenu, registerMenu, registerDetail); menu.js builds #menu from card.moves; detail.js fills #detail.

Page protocol added here:
- page to host: { type: 'assign', itemId } and { type: 'unassign', itemId } (exact keys, item id rules as for move). The host decides what they mean from the log: for the owner or a lead, assign opens the person list and unassign removes whoever holds the card; for any other member, assign puts that member on the card and unassign takes them off, both through planAssign with the viewer's own id, so the page never names a person.
- host to page: the existing state and refused messages.
</interfaces>
