## Decisions and assumptions

- **Classification (from RESEARCH Pattern 7):** bad signature, ctHash, GCM tag, entry chain, or filename/header mismatch = tampered; valid segments whose chain order is wrong = reordered; a missing sequence or a tail below the high-water mark = truncated; two segments with the same lineage (same prevSeg or overlapping seq for one author) = forked; header or entry `v` above 1 = unknown-version; the epoch key fails to unwrap or decrypt every segment = wrong-key.
- **High-water mark (A9, assumption):** the mark `{ seq, segId, count }` lives in the KbModeRecord in globalState (plan 13-02); losing the profile loses the truncation anchor until Phase 19's version vectors. The caller supplies it; an explicit "accept rollback" is recorded by the host (plan 13-11).
- **Order of checks** is cheapest-first per segment but the report names the first failing point in total order.
