## Decisions and honest limits

- **Index:** KbRedactor terms = normalised titles, texts, places, and any `entities` strings from live (not erased) items in the verified fold, plus 8-word shingles of texts longer than 64 characters; terms shorter than 3 characters are ignored. Normalisation: NFC, `toLocaleLowerCase('und')`-style case folding via `toLowerCase()`, whitespace collapsed.
- **Guard behaviour:** Write and Edit into `.planning/` (any depth) throw a ToolError when the new content contains an index hit: `Findings belong in the knowledge base, not in .planning/ files. Write workflow notes without claim text, entity names, or places.` Writes elsewhere in the workspace are not blocked by this guard (the user's own files; Phase 15's intake governs base writes).
- **Honest limit (stated in the SUMMARY and carried to Phase 24):** the guard is exact-match on known terms; a model can paraphrase. Phase 24 re-proves plaintext absence across all flows.
- **Sealed handoff:** plaintext fields `{ version, createdAt, projectRoot, reason, currentAction: 'Knowledge-base conversation (details sealed)', nextAction: 'Resume from NEAR AI history in this knowledge base.', activeAgents, pendingApprovals, sealed: { enc: 'aes-256-gcm', iv, tag, data } }`; the sealed blob holds the original currentAction/nextAction; key = HKDF-SHA-256(localSecretsRoot, salt = utf8(kbId), info = "near-ai-kb/handoff/v1", 32).
