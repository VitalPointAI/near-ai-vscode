<objective>
The hub's HTTP protocol, first half (D-34 to D-36, D-39, D-41, D-44): sessions that work only on the TLS connection they were made on, and the routes a client needs to enrol a project, see heads, catch up, append and move blobs. Events, presence, checkpoints and join requests extend `routes.ts` in 32-21, 32-22 and 32-25; the client transport (32-23) implements exactly the wire shapes below.

Wire shapes (JSON, content-type application/json, cache-control no-store; errors are {error: id, message: one plain sentence} and never echo request data):
- POST /v1/session {project} -> {project, hub, challenge}; then {answer} -> {project, token, expiresAt}. 403 session-refused with reason unknown-project, not-admitted, not-a-person-device, quarantined, wrong-hub, wrong-project, wrong-challenge, wrong-connection, bad-signature, challenge-expired.
- Authorization: Bearer token. 401 with reason no-token, unknown-token, token-expired, other-connection, revoked, quarantined; 403 wrong-project.
- GET /v1/projects/:p/heads -> {project, rosterHead, streams: [{stream, heads: [{writer, seq, hash}]}], grants: [hash], checkpoint?}.
- POST /v1/projects/:p/append {entries, grants?, blobRefs?: [{entry, blob}]} -> {project, accepted, refused: [{index, hash?, reason, message}], rosterHead, checkpoint?}; 409 blob-missing; 413; 429 with Retry-After.
- GET /v1/projects/:p/entries?stream=S&writer=W&from=N -> {project, stream, writer, entries, more, head: {seq, hash} or null, checkpoint?}.
- PUT /v1/blobs/:hash (octet-stream) -> 201 or 200 {project, hash}; GET /v1/blobs/:hash -> bytes with header x-near-ai-project, for a held blob of the token's project the device may read, or the canonical bytes of a grant hash listed in its heads; otherwise 404 not-found.
- POST /v1/enrol {enrolment, project, entries, grants, blobs?, rosterHead, mac} -> 201 {project, rosterHead, hub}.

Grants travel inside append and heads because grants live outside the streams and the hub needs them for access lists; blob references are declared in append because the hub cannot read which blob a sealed body names. Both are flagged in the phase report as protocol details D-34 did not spell out.
