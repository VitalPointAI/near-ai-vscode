<objective>
The single-machine copy finding of the PR #130 review (D-07): the copy's signed head mark is stored before the copy is put in place, and taken back if putting it in place fails.

Purpose: today `writeStaged` renames the staging folder into place and only then stores the mark (src/staff/replica/singleCopy.ts, near line 581). A failure or a stop in between leaves a copy whose ledger today's host takes on first read with nothing to check it against. The new order means a copy in place always has its mark.
Output: changes in singleCopy.ts and staffReplicaCopy.test.ts.

Branch: `feat/phase-32-03-copy-mark-first`, merged into `feat/phase-32-sync-hub` after wave 1. 32-11 changes the same two files in wave 4.

Note on D-07's last sentence: today's host does not refuse a ledger whose mark is missing (head marks live in each computer's own secret storage, so a project opened on another computer has none, and the host records one on first read). The refusal for a copy left without a mark is therefore made where it can be told apart: in the copy flow, for its own destination on this computer.
</objective>
