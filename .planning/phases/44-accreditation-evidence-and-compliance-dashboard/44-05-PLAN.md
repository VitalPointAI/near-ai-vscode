<objective>
The data contract between the compliance package and the Accreditation pages (D-29, D-31, D-50), the components loader with the responsibility resolver (ACCR-03, D-40), and the output word lint (D-27, D-49).

Purpose: the pages (44-15), the generator (44-14) and the package builder (44-17) are written in parallel later; they need one fixed shape for the dashboard, the overlay, the bundle manifest, the per-family text files and the refresh record, one CSV writer, and one rule for honest words.
Output: six schemas, the extended `buildDashboard` output, `lib.mjs` for the browser and Node, the components and responsibility modules, the word lint with its parity test, and fixtures including a sample organization overlay with marker strings (VALIDATION Wave 0).

Planning choices (reported):
1. `lib.mjs` is plain ES module JavaScript with no imports, so the browser, the refresh script, the package builder and compliance's tests share it; the overlay merge rule there is checked against `computeStatus` by a parity test in 44-14 (one engine is authoritative; the view must agree with it on every row of the rules table).
2. The overlay schema has no state field: an overlay supplies your organization's answers, its own evidence (control, component, collectedAt, passed, windowDays, ref) and its decisions (signed by the official or self-signed); the merged view computes state from them.
3. Official titles and control text are official fields and are never linted; our fields are listed in `OUR_TEXT_FIELDS`, and a new field is linted unless it is added to `OFFICIAL_TEXT_FIELDS` on purpose (D-49, pitfall 5).

Branch `feat/phase-44-05-dashboard-contract` (D-39).
</objective>
