The `compliance/` package and the phase's tracer: one fixture control travels from an OSCAL catalogue through a component statement, an evidence rule and a per-test report row to a computed state in the dashboard JSON (orchestrator tracer rule; D-14, D-15, D-16, D-17, D-21, D-43, D-44, D-45, D-48). Purpose: prove the architecture end to end (source to evidence to state to page data) before any importer, collector or page exists, and fix the contract names once.
Output: the package skeleton (Node 24 type stripping, `tsc --noEmit`), the shared model, the first status, rules and dashboard functions, the vendored OSCAL schema with validators, the no-status invariant test, and the VSIX exclusions.

Planning choices (discretion, reported in the summary):
1. `@types/node` is pinned at 22.20.5, the exact version the root lockfile already carries, instead of a new 24.x release: research flagged the newest release as too new; a version already approved in this repository needs no first-install checkpoint, so the tracer stays autonomous. Node 22 types are a subset of what Node 24 runs. Rating reversible.
2. One vendored file, `oscal_complete_schema.json` of OSCAL 1.2.1 (D-16 "the OSCAL JSON Schemas for the pinned version"), with per-model root wrappers built in `validate.ts` from the complete schema's own definitions. It holds every model and keeps the code PR small (pitfall 3). Rating reversible.
3. The no-status walk allows exactly one form: a prop named `status` with value `withdrawn` on a control in a file under `catalogs/`, because the NIST catalogue marks withdrawn controls that way; it is the publisher's lifecycle marker, not our assessment. Any other value or place fails (D-17, D-44). Rating reversible.
4. All compliance tests sit flat in `compliance/test/*.test.ts` (collector tests named `collector<Name>.test.ts`), so the package `test` script never needs editing by later plans.

Branch `feat/phase-44-01-skeleton-tracer` from `feat/phase-44-accreditation`, merged back after wave 1 (D-39).
