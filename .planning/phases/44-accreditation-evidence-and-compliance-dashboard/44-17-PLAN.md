The release documentation package (ACCR-09, D-04, DESIGN section 11) and the pull request summary (ACCR-10, D-07, D-25).

Purpose: success criterion 4 (a release's package validates, imports into Trestle, verifies against checksums and attestation, and holds no secrets or organization data) and success criterion 2 (a dropped test shows in the PR's summary).
Output: the package builder in five modules, the PR summary, two commands, and tests including a producer and consumer parity test.

Planning choices (reported):
1. The package's evidence is the release commit's redacted bundle plus the two CycloneDX SBOMs (the VSIX's and the relay image's), which list public component names; full npm audit reports are not copied, because the bundle's counts are the evidence (D-24).
2. Resolved profiles come from oscal-cli in the release job (`--resolved <dir>`, 44-19); locally the package is built without them and the README says which files a release adds.
3. The PR summary compares the PR's dashboard (built by `bundle` with kind pr and the latest main bundle as `--previous`, so daily evidence carries over) with the main bundle's dashboard, and reads the PR's changed files from a list the CI job writes.

Branch `feat/phase-44-17-package-pr-summary` (D-39).
