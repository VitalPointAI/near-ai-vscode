      - Leaving live clears the history timer; going live again resumes the check.
    - **Local causes and no base.**
      - A run reporting `waiting` (`cannot-open-yet`, `store-full` or `store-busy`), or `unchecked`, gives `history` `waiting` or `unchecked`, and the sentence contains `HISTORY_WAITING_TEXT`.
      - A run reporting `waiting` with `no-base-yet` gives `history` `no-base`, and the sentence contains `HISTORY_NO_BASE_TEXT`.
      - Each retries on the same back-off, never counts towards `stalled`, and is never shown as checked.
      - In particular, a store-wide cap filled by another writer never makes the sentence blame your organization's server or the writer.
    - **Logs the store does not accept, and the skip list kept per start (accepted).**
      - A run that lists a log in `notAccepted` makes the replicator pass it in `skip` to every later run of this start, so it is not fetched again in that start.
      - A run whose only remaining work is skipped logs is not counted towards `stalled`.
      - **After a restart** (a new LiveReplicator over the same store and memory), that log is fetched once more and is reported in `notAccepted` again. Through three restarts in a row, `history` never becomes `stalled`, and the sentence never contains `HISTORY_STALLED_TEXT`.
    - **Findings and the vouching invariant.**
      - A `base-unverifiable` finding from a history run appears in `status.findings` as a detail line, and the state stays live.
      - **A run reporting `incomplete` with a `history-refused` finding carrying `unvouched`:**
        - the state turns to `attention` with reason `history-refused`, and its sentence is that finding's FINDING_TEXT;
        - syncAction offers `show-details`, never `readmit`;
        - once the next exchange returns the state to live, `history` is `incomplete`, and the sentence contains `HISTORY_INCOMPLETE_TEXT`, never the plain synced sentence alone;
        - no further history runs happen until the next start.
      - A `history-refused` without `unvouched` stays a detail line.
    - **Refused.**
      - A run reporting `refused` turns the state to `attention` with reason `forked-view`.
      - syncAction offers `readmit` to a lead device and `show-details` to others.
      - No history run happens while the hub is distrusted (`blocked`). After the lead's Re-admit the runs resume.
