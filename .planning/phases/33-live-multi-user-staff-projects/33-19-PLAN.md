## Local Task 1 adapter checkpoint

The adapter branch starts at `34075c03`, the completed 33-04 core. The exact prerequisite exports are present once and the manifest has no keybindings. The plan's literal `BoundDocument` substring check also matches `BoundDocumentChange`.

`registerStaffEditorBindings` tracks open documents selected by an injected `BindingSource`. It loads the replica core only after a source match, forwards local change snapshots and refreshes existing bindings on source notifications. Closing a document detaches its session and flushes captured edits before releasing the core.

For remote rendering, the adapter compares the open document version with the binding's expected version and submits one `WorkspaceEdit` in the same synchronous turn. VS Code's extension host serializes the open model version. LF normalization uses one EOL edit in the same API. The tests exercise this contract with a VS Code-shaped stub, including rejection after a simulated host-side version change. [VS Code 1.101.0 edit converter](https://github.com/microsoft/vscode/blob/1.101.0/src/vs/workbench/api/common/extHostTypeConverters.ts#L571-L615), [extension-host dispatch](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/api/common/extHostBulkEdits.ts#L20-L28).

The tracer's initial compile reported the missing adapter module. The five cases cover local append and a multi-range remote edit without echo, lazy loading, close and flush, version races and LF normalization. The fixture uses local stores and in-memory documents. Production editor attachment belongs to 33-10. The next outside-file task depends on 33-06's last-projected record and its pending write-race resolution.
