<objective>
Build the model protocol and the legal gate: the JSON-in-text step protocol with parse repair, bounded retries, context compaction, and incompatibility detection for raw-completion abliterated models (CYBER-04, D-19, D-20), and the twelve-region disclaimer catalogue with locale detection, re-acceptance rules, and the public-sector warning tier (CYBER-03, D-13..D-18).

Purpose: These are the two systems every run depends on — the protocol makes a tool-less model drivable, the legal gate makes every mode lawful by construction. Both are pure domain logic plus a thin agent-layer driver, so they test under plain Node.
Output: src/domain/cyberProtocol.ts, src/domain/cyberLegal.ts, src/agent/cyberProtocolDriver.ts, three test files.

Recorded planning choices:
- Retry bound defaults to 3 (research Open Question 5) as a named constant `MAX_STEP_REPAIRS = 3`, not a magic number inline.
- Region detection maps IANA timezone -> region (Europe/London -> uk, America/* -> us, ...) with 'us' fallback, matching the research's Region Detection section; the override is always visible in the panel (25-07).
- Per the spec-less-probe fallback: predicates authored directly from CYBER-03/04 and D-13..D-22; the edge-probe run was declined by the operator (recorded, not fabricated).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model -> harness | Model text is untrusted; only validated Step objects act |
| User -> engagement | Disclaimer acceptance is an authorization input; the record must match the shipped text |
| Locale/OS -> region detection | Timezone is environment input; detection must fail safe to 'us' with visible override |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-08 | Elevation of Privilege | Disclaimer gate (bypassed by re-run) | high | mitigate | needsReacceptance keyed on region, scope, extension version AND textVersion: any change voids the stored acceptance; every run revalidates before starting (D-18) |
| T-25-01 | Tampering | Protocol driver (target banner steering the model) | high | mitigate | Steps are validated against the scope-checker before execution; probe output reaches the model only through the untrusted-fenced path defined in 25-01 |
| T-25-10 | Repudiation | Disclaimer acceptance record | medium | mitigate | Acceptance stores acceptor legal name, OS user, machine, extension version, textVersion, ISO timestamp (D-17); embedded in every export (D-16, delivered in 25-05) |
| T-25-11 | Denial of Service | Parse-repair loop | medium | mitigate | MAX_STEP_REPAIRS bound; incompatibility is a typed visible failure, no infinite retry |
| T-25-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero new npm dependencies in this plan (no Package Legitimacy Audit table exists; fallback policy would treat any install as ASSUMED and require blocking checkpoints) |
