<objective>
Build the safety core for offensive work: the engagement-wide intrusive grant (D-04) riding the existing permission path, the container/temp/disabled sandbox tiers (D-08) with two-way cleanup proof (D-10), the read-only post-exploitation rules (D-11), and the rate/time/stop enforcement that makes CYBER-10 true.

Purpose: CYBER-10 and the D-08/D-10/D-11 decisions are the trust boundary of the whole phase — every later offensive capability (25-06) runs inside them.
Output: src/services/cyberSandbox.ts, src/agent/cyberExploitTools.ts, src/domain/cyberLimits.ts, two test files.

Recorded planning choices:
- The engagement grant extends RunGrants (src/agent/permissions.ts) with an additive `intrusiveEngagement?: {engagementId: string; scope: ResolvedScope}` field: a cyber tool call whose step names that engagement is allowed when the grant exists and the target is in scope; everything else keeps the existing decision order byte-for-byte (existing permission tests must stay green unchanged).
- Sandbox commands use execFile with fixed argv (docker/podman run --rm --name cyber-<uuid> ... , exec, rm -f) — no shell string assembly, no docker API client (research Don't-Hand-Roll row).
- Temp-folder tier: mkdtemp under os.tmpdir with a per-run allowlist of executable paths passed to the step runner; documented limitation (no network isolation) is stated in the disabled/reason report, matching D-08's honesty requirement.
- The emergency-stop test file name matches VALIDATION.md's Wave 0 list (cyberEmergencyStop.test.ts).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Model -> sandbox | Payload text from the model executes only inside the sandbox with fixed argv |
| Sandbox -> host | A container escape or temp-tier write is the primary containment risk |
| Sandbox -> target | Outbound network reach is denied by default (--network none) |
| Stop signal -> running step | Abort must propagate within one tool call |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-14 | Elevation of Privilege | Sandbox escape via container | critical | mitigate | --network none default, --rm, no privileged flags, read-only target mount (:ro), unique per-run name, cleanup proof via ps -a absence (D-08/D-10) |
| T-25-05 | Elevation of Privilege | Post-exploitation shell (write/lateral/persistence) | high | mitigate | postExploitAllowed allowlist + named-rule refusals; every command recorded for the report (D-11) |
| T-25-09 | Elevation of Privilege | Engagement grant (model expanding its own scope) | high | mitigate | Grant is scope-checked per call; out-of-scope under grant is DENIED not asked; deny list and emergency stop ordered before the grant |
| T-25-15 | Denial of Service | Rate/budget enforcement | medium | mitigate | Sliding-window limiter; wall-clock budget per D-09; violations refuse with reasons |
| T-25-16 | Tampering | Temp-tier sandbox residue | medium | mitigate | mkdtemp per run, rm -rf in finally, ENOENT assertion; disabled tier instead of silent downgrade |
| T-25-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero new npm dependencies; container images are named by the engagement (user-provided or the fixture default) and any pull is an approval-gated, ledger-recorded action deferred to 25-07's install offers |
