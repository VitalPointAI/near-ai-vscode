<objective>
Close the rig items of DESIGN section 12 with recorded experiments (D-25), close the load and hub rows from 48-09's run, switch the Section 10 conditions rows to rule ids for statements 48-07 merged after 48-08's sync, and bring the Traefik and prewarm results to the owner, who alone decides whether the ingress default (O2) or the pool default changes (D-05, D-08, VER-09).

Purpose: success criterion 3 ("the open verification items ... are each closed with evidence or recorded as a gap with an owner and date"), for the items only a running site can answer.
Output: experiment modes and run files, the register's rig rows updated, the gaps updated, and the owner's decisions.

Planning choices (reported):
1. Experiments that use the harness (ingress, cold start and pool, step-up) get small modes in `loadtest/src/experiments/`; operator procedures (kms-pkcs11, revocation lists) are recorded with `node loadtest/src/cli.ts experiment record --name <item> --result <file>`, which writes an `experiment` run file with integers, booleans, versions and the steps followed. Experiment files are never a capacity source (48-03).
2. Ingress and pool variants run in a separate namespace with a copy of the production AppDefinition; Phase 47's charts and values stay untouched (Traefik's settings for the experiment are `loadtest/experiments/traefik-values.yaml`, recorded by hash). The rig is the public reference site, so variants are removed afterwards and the summary says when.
3. Gaps close by evidence (`gaps.ts`): when an experiment closes a row, its gap's remediation and milestone are rewritten to what its controls still need (for example a statement through a 48-07 or 48-08 follow-up batch); a gap whose controls need nothing more is listed for the owner at Task 3, and removed only with the owner's confirmation (deleting needs the owner).
4. If the HSM test passed on a certified model, the `hsm` and `openbao` statements are a 48-08 follow-up batch (a gate PR), not written here.
5. Branch `feat/phase-48-experiments` (no gate path).
</objective>
