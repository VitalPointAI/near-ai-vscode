<objective>
The deployment evidence path (VER-06): a script on a site collects read-only outputs, the `site-export` command turns them into allow-listed facts and a signed envelope in the existing signed-payload format, and one new collector, `deployment`, verifies it offline against a trust list in a gate file and emits counts-only observations whose time is the export's signed time (D-13, D-14 (b), D-16).

Purpose: success criterion 2 ("the dashboard shows its controls from collected evidence, never assumed"; "a fixture export with a lapsed audit shows Stale") and VER-05's fail-closed rule for observation evidence.
Output: the collector and its registration and window, the trust list, the exporter and its CLI command, the collection script, tests, and a README section.

Planning choices (reported):
1. One collector id `deployment` with window `settings` (7 days, owner item 7 default; research Pattern 3). Without the `OBSERVATION_WINDOWS` entry the evidence would be judged at the head commit and never go stale (Pitfall 1).
2. Signing: the envelope from `compliance/src/signed.ts` with purpose `site-evidence-export`; trust anchors in a new gate file `compliance/attestations/site-signers.json`, same shape and loader as `signers.json` (`loadSigners` in `riskAcceptance.ts`), empty until the owner adds the reference site's operator key in 48-08 (owner item 7: a dedicated operator key, not an OpenBao Transit key).
3. Collection is split from fact derivation: `compliance/site-export/collect.sh` runs only read-only commands on the site into a folder; `siteExport.ts` parses that folder with strict readers, so all logic is tested with fixtures and no code in this repository calls into a site (D-16). Readers are written against the upstream output formats of the products Phase 47 chose (47 D-53: Keycloak, OpenBao, RKE2 audit policy, Kyverno admission, Harbor or Zot, cosign); 48-08 runs them on the rig and fixes any format difference.
4. The facts carry the Keycloak version; the collector compares it with `KEYCLOAK_MIN_FIXED` (from research register row 3: upstream 26.8.0 or later). 48-05 re-checks the source at execution and 48-06 adds the cross-check that the constant matches the dated desk record. A Red Hat build of Keycloak fails this check until its fix version is confirmed (register row 3 gap).
5. No CI wiring here: `ci.yml` and `compliance-scheduled.yml` inputs are 48-06 (D-33 pattern), and this plan's gate edits join the gate PR 1 that 48-06 opens with the owner checkpoint (D-27). Branch `feat/phase-48-02-deployment-evidence`.

Flagged assumption (edge probe, VER-06 unclassified, not auto-resolved): the probe could not classify VER-06; this plan's truths cover its behaviour, and no probe predicate is authored for it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| site to repository | an export file crosses from a site into the public repository or a customer's local bundle |
| export to observations | the collector turns the site's facts into the evidence that decides rows |
| operator key to trust list | only a key in a gate file can make an export count |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48-04 | Spoofing | deploymentCollector | high | mitigate | verifyEnvelope with purpose `site-evidence-export` and keys only from `compliance/attestations/site-signers.json` (gate path); wrong purpose, unknown key and bad signature refused (Task 2 tests) |
| T-48-05 | Tampering | export facts | high | mitigate | strict fact allow-list, every key required; pass or fail derived in collector source from counts and versions; no pass field accepted (Task 2) |
| T-48-06 | Repudiation | replayed old export | high | mitigate | collectedAt is the signed time and the `settings` window applies, so a replay reads Stale after 7 days (Task 1, Task 2 window edge) |
| T-48-07 | Information disclosure | export, observations, bundle | high | mitigate | facts are counts, booleans, enums and two version strings; observations pass redactObservation; the command runs scanLine over the payload and refuses on a hit; leak assertions in tests (Tasks 2, 3) |
| T-48-08 | Denial of service | oversized export or source file | low | mitigate | MAX_PAYLOAD_BYTES on the envelope and a size cap per source reader |
| T-48-09 | Elevation of privilege | signing key custody | medium | mitigate | a dedicated operator key (HSM-backed where available) through `--emit-signing-input`/`--attach-signature`, never a key held by the assessed OpenBao (owner item 7); the trust list stays empty until the owner adds a key |
| T-48-SC | Tampering | npm installs | high | mitigate | No new package: `yaml` and the rest come from the existing compliance lockfile via `npm ci --ignore-scripts` |
