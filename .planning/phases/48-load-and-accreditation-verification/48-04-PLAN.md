<objective>
The two load populations that make per-person and per-hub figures representative: hub load through the hub's own test client, and an active sample of sessions driven by a real browser running a versioned activity profile and signing in with a WebAuthn virtual authenticator (D-19, D-21, D-23).

Purpose: VER-02 asks for "steady-state CPU and memory per person under the activity profile" and "load per hub"; a session with no frontend is not a person (research "Representative load"), and the hub's 150-person target needs a real client.
Output: the hub driver and its bundling step, the browser sample and profile, stage-controller hooks for both, and the README sections.

Planning choices (reported):
1. Tracer first is the hub path because it needs no new package; the Playwright package check (Task 2) must come before the browser task, as the package legitimacy gate requires.
2. Hub driver: `hub/test/helpers/hubWorld.ts` and `hubClient.ts` import `@ext/...` aliases, so `loadtest/scripts/build-hub-driver.mjs` bundles `loadtest/hub-driver/driver.ts` with the hub's installed esbuild and `hub/tsconfig.json` paths into `loadtest/dist/` (ignored by `.gitignore`'s `dist/`), research Open Question 7. Nothing under `hub/` is edited. On the rig the driver targets load-test hub instances running the production hub image digest with keys the test world made, so the measured code is the shipped hub and no production key is involved.
3. Browser: Phase 46 pins `@playwright/test` in `workbench/` (46 D-28, D-41); `browser.ts` loads it with `createRequire` from `workbench/package.json` (owner item 6 default: no `loadtest` dependency, no change to `scripts/resource-check.mjs`). Chromium only, through a CDP session (`WebAuthn.enable`, `WebAuthn.addVirtualAuthenticator` with resident key and user verification) before navigating. Browser-dependent checks are `*.integration.ts` files run by this plan and on the rig, not by the CI glob `loadtest/test/*.test.ts` (48-06), because CI has no browser or hub build in that job.
4. If this plan finishes before 48-06 opens gate PR 1 it joins that branch; otherwise it is a normal PR (no gate path). Branch `feat/phase-48-04-active-load`.
</objective>
