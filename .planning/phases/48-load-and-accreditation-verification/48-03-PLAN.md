<objective>
The load-test harness core, proven against fakes before any rig exists: a stage controller over Theia Cloud's service API, measurement readers over the cluster's own records and metrics store, one hashed run file per run, a generated capacity page, and a docs check that refuses any capacity figure not read from a run file (D-09, D-10, D-19 to D-22).

Purpose: success criterion 1 ("a repeatable load test on our own hardware ...; capacity figures in docs come only from it"). The rig runs are 48-08; this plan makes them repeatable and makes a hand-typed figure impossible to merge.
Output: the `loadtest/` folder (no dependencies), `docs/hosting/capacity.md`, `docs-site/test/capacityFigures.test.mjs`.

Planning choices (reported):
1. Load generator: plain `fetch` plus a stage loop in Node, no k6 (AGPL-3.0) or Locust (research Standard Stack); the browser sample and hub driver are 48-04.
2. No dependencies (owner item 6 default): `loadtest/package.json` lists none, so `scripts/resource-check.mjs` is not changed; type checking reuses the compliance package's TypeScript and `@types/node` through `typeRoots`; kubectl, Prometheus and the browser build are rig tools documented in `loadtest/README.md` (research Pitfall 7).
3. Run files: `loadtest/runs/<id>.run.json`, id `<UTC start yyyymmddThhmmssZ>-<rig>`, kinds `load`, `experiment`, `dry-run`; raw values (per-session start durations, per-pod steady-state averages, per-window counts) live inside the file as integers so the page's figures can be recomputed from it; long metric series are not stored, the queries and their time ranges are (D-22). Size cap 5 MiB.
4. Burst (D-20): after each stage's steady state, a burst of `burst` additional starts (default 500) is measured and then stopped; the run file records the burst size and the peak concurrency. A burst the rig cannot hold is a not-reached result for that stage's burst, recorded with its reason.
5. Two populations (research "Representative load"): bulk sessions are started through the API and kept alive with activity reports; per-person figures come only from the active sample (48-04). This plan's run file keeps the two apart from the start (`perPerson.active`, `perPerson.idle`).
6. Not a gate path: `loadtest/`, `docs/` and `docs-site/test/` are outside `GATE_PATHS`; the CI step that runs these tests is added in 48-06. Branch `feat/phase-48-03-loadtest-core`.

Flagged assumption (edge probe, VER-01 unclassified, not auto-resolved): the probe could not classify VER-01; "repeatable" is taken to mean the same inputs file reproduces the same stage plan and the run file records everything needed to repeat it; it is not mechanically compared across two rig runs.
</objective>
