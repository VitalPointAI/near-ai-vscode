# Phase 70.1 Plan 03: Your organization's guide as signed rules Summary

Guide rules, compilation rules, code words and added fact types live in `classification@1`, are evaluated by pure code over typed facts on an item and across a session, and a personal or project layer can only make them stricter. Show Policy shows counts, the system-high and the trial mode, and never a rule's text or a code word.

## Shapes for 70.1-04 and 74.3

- Section keys added: `codeWords?: { listLabel: Label, entries: [{ id, token, label }] }` (token a label token, one token per list); `factTypes: string[]` (sorted, not repeating `BASE_FACT_TYPES`); `guideRules`, `compilationRules: [{ id, guideRef (one line, at most 64), label (the rule text's own label), description (one line, at most 280), when: { allOf: fact types (sorted, at most 16), sameSubject (default false) }, then: Label }]`. At most 512 rules in all, ids unique across both lists.
- `BASE_FACT_TYPES`: `unit, location, date, future-date, capability, operation, named-person, codeword, marking, controlled-item, hidden-instruction`.
- `addFacts(session, incoming, item?) -> Parsed<{ facts, exception?: 'aggregate-cap' }>`: facts are `{ type, subject?, item? }` and nothing else; duplicates once; past `SESSION_FACT_CAP` (4096) the session set comes back unchanged with the exception.
- `evaluateRules(facts, { guideRules, compilationRules }, 'item' | 'session') -> Floor[]`: `guide` or `compilation` basis naming the rule id.
- `markingFloors(text, section)`: markings (`marking` basis), then code words (`detector` basis, ref the entry id).
