<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Source/dependencies → release archive | Repository files, lockfile-resolved tooling, and compiled output become an installable VSIX; unexpected development content or altered provenance must be detected. |
| Extension host → provider/wallet/webview | Public documentation must describe actual outbound data, SecretStorage, local-only, approval, and external-wallet boundaries without overstating TEE or staking capabilities. |
| Marketplace user → README/SECURITY.md claims | Users rely on release documentation to make privacy, permissions, installation, and security decisions; inaccurate claims are a trust and safety failure. |

## Least-Privilege Constraints

- The packaged extension contains only the manifest, compiled runtime, required documentation/license, and explicitly required Marketplace assets; development runtime, planning, source, tests, and source maps are excluded.
- No dependency may be added for this closure; provenance evidence must use the existing lockfile and installed toolchain.
- SECURITY.md must distinguish implemented controls from unavailable/fail-closed staking configuration and from provider-level claims the extension cannot independently guarantee.
- Visual demos and documentation must contain no API keys, wallet signing material, private prompts, raw context, local paths, or credential-file content.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-05-19 | Information disclosure | VSIX archive and Marketplace assets | high | mitigate | Add explicit development-artifact exclusions, compare every compiled runtime module against archive contents, and fail packaging tests on forbidden or sensitive entries. |
| T-05-20 | Tampering | Marketplace README and SECURITY.md | high | mitigate | Derive claims from current source and verification evidence, record limitations/remediation, and run documentation/content checks before release. |
| T-05-21 | Supply-chain tampering | package.json/package-lock.json/toolchain | high | mitigate | Perform lockfile and installed-tree provenance review, run production dependency audit, avoid new packages, and document exact reproducible commands. |
| T-05-22 | Elevation of privilege | Release packaging command | high | mitigate | Keep packaging on the existing local `vsce` tool, run a fail-closed archive verifier after packaging, and require the full lint/test/audit gate before release evidence is marked complete. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; if the executor proposes one, stop for the official package-legitimacy review rather than silently adding it. |
</threat_model>
