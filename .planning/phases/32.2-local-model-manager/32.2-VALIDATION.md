# Phase 32.2: Validation Strategy

Per-phase validation contract for feedback sampling during execution. Drawn from `32.2-RESEARCH.md`, section "Validation Architecture".

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `node:test` with `node:assert/strict`, TypeScript compiled by `tsc` to `dist/test`, run only through `scripts/run-tests.mjs` |
| **Config file** | `tsconfig.json`; no test config file |
| **Quick run command** | `systemd-run --user --scope -q -p MemoryMax=4G -p MemorySwapMax=0 choom -n 1000 -- timeout 300 env NODE_OPTIONS=--max-old-space-size=1536 sh -c 'npm run compile && node scripts/run-tests.mjs dist/test/<file>.test.js'` |
| **Full suite command** | the same wrapper with `sh -c 'npm test'` and a longer timeout, once at the phase boundary, one heavy run at a time |
| **Estimated runtime** | about 5 to 30 seconds per focused file |

## Sampling Rate

- **After every task commit:** the focused test file for that task through the quick run command; `architecture` and `copyLint` after any task that adds a file or user text.
- **After every plan wave:** the wave's test files plus `architecture`, `copyLint` and the gate tests the wave touched, in one capped run.
- **Before verification:** the full suite once, then the extension-host end-to-end scenario once.
- **Blocking at once:** security, authorization, policy, hash and boundary checks (owner cadence rule).
- **Max feedback latency:** 300 seconds (the cap's timeout).
