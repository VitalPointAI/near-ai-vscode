# Phase 62.1 Plan 08: The timeline in a real VS Code window Summary

**A new `timeline` e2e launch runs 18 steps in a real VS Code window on a hidden xvfb-run screen, on this repository's own roadmap (84 cards in 39 steps of v0.6.0). Every click, hover and key is real input aimed with the probe's boxes. All 18 steps pass with no probe problem, a 6.8 ms first draw and a 16.8 ms frame p95. Along the way the run found five real defects in the timeline, each fixed with a regression test.**

## Performance

- **Duration:** about 60 min (02:15 to 03:16 UTC)
- **Tasks:** 3. Task 1 was a tracer, and its verify was run again end to end (exit 0) before Task 2 built on it.
- **Real-window runs:** 8, one at a time, each under MemoryMax=6G and timeout 1800. Before each run: 11 GB free and no other e2e process.

- **The launch (run.ts):**
  - `'timeline'` is in LAUNCHES.
  - `timelineWindow()` uses prepareBoardProject (this repository's committed `.planning` behind the public-looking address), fresh user data, and `.vscode-test/screens-timeline`, emptied at the start of each run.
  - A free DevTools port on 127.0.0.1.
  - It passes on NEAR_AI_E2E_FBDIR and NEAR_AI_E2E_TIMELINE_PART when given. The hidden-screen guard and the Wayland stripping are unchanged.
- **The dispatch (suite.ts):** one line, loading `./timelineSuite` lazily.

  - It has its own Observer, ask, settled, sizeTo, act (facts and blur only), aim, click, emptyPoint, inView, key, direction and noCard helpers.
  - In order: the first open from a real click; seeding the Ready bug from the owner's second client; keys in horizontal and vertical; the mouse; a move from the card; the teammate's change; the frame set; no page error; the narrow width; then the four rare states.   - A test-seam controller clears the seam when it is disposed.

## Deviations from Plan

### Real-window defects found and fixed (Rule 1, each with a regression test)

**1. Small text under 0.85 of the editor font (probe rules 3, 11, 12)**
- **Found during:** Task 1, the first screen.
- **Issue:** the Now pill, the percents, the progress words and every phase label were 11.05 px against the 14 px editor font.
- **Fix:** every Small size in the timeline part of board.css, and the board's card face inside `#tl-preview` and `#tl-card`, is now `max(0.85em, calc(var(--vscode-editor-font-size, 0px) * 0.85))`. That is 11.9 px by default, and it follows a person's editor font.
- **Commits:** 054129a / 404e909 / 7678044

**2. Lines 3 px off a grown mark (rule 8)**
- **Found during:** Task 2, at Home.
- **Issue:** a focused dot's mark grows to 1.25x, but its lines kept ending at the edge of the unscaled mark.
- **Fix:** each path keeps its two ends, and `fitLines()` moves the ends at a grown mark 2.5 px out after every emphasis change.
- **Commits:** 4e3d6cd / 7a79940

**3. The card over a band header's percent (rule 12)**
- **Found during:** Task 2, in vertical, on the bug's card at the end of the timeline.
- **Issue:** with no clear side, placement fell back to covering the header.
- **Fix:** when the card would cover a header, a phase label or the Now pill, opening it first centres its dot. The canvas grows past its end while that card is open.
- **Commits:** f890e89 / 1d6d1b2

**4. Progress words cut without a title (rule 12)**
- **Found during:** Task 3 (b), in a shown finished short band beside Fold milestone.
- **Fix:** the progress words carry their full text in `title`, as the milestone title already does.
- **Commits:** e6f3e40 / 0bd01b4

**5. The card title read as clamped (rule 3)**
- **Found during:** Task 2 (bug card) and confirmed in Task 3.
- **Issue:** with two lines at line height 1.2, the glyph boxes reach about 2 px past the line boxes. The title's scroll height was 39 against a client height of 37.
- **Fix:** `.tl-card-title` gains `padding-bottom: 0.15em`. The line height stays 1.2.
- **Commits:** 7617d76 / d388f75
