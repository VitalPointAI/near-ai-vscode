# Phase 62.1 - UI Design Contract: Board timeline

> Visual and interaction contract for the Team Board's second view: one timeline for the whole project, milestones as bands, phases as segments, every card a dot in dependency order. Generated by gsd-ui-researcher (non-interactive: every open question was resolved with the recommended option and logged in "Decision Log" with its source). To be verified by gsd-ui-checker.

Sources read: 62.1-CONTEXT.md (D-01 to D-12, locked, with the owner's verbatim request), 62-UI-SPEC.md including the amendments of 2026-11-03 and 2026-11-04 (this contract inherits everything there unless it says otherwise), 62-CONTEXT.md, 62-UAT.md (the gaps this design is built against), UX-CONTRACT.md ("Visual analysis surfaces"), PROJECT.md (no developer knowledge required), media/board/board.js, menu.js, detail.js, drag.js, board.css, layout-probe.js, src/domain/team/board.ts, src/services/team/boardView.ts (CSP).

**The timeline is part of the same board.** Same page (`media/board/`), same toolbar band, same banners, same live region, same Move to... menu, same detail drawer, same card face, same theme variables, same type scale, same focus ring rules, same plain-language rules. It adds a view; it adds no signed event, no host message type that changes state, no permission rule and no dependency (D-12).

### What went wrong before, and the rule here that prevents it

| 62-UAT finding | Rule in this contract |
|----------------|----------------------|
| Toolbar was see-through and cards scrolled behind it (test 2) | Every sticky or floating element in the timeline (milestone title, vertical milestone header, preview, expanded card, legend band) has an explicit opaque theme background. The probe fails any of them whose computed background alpha is below 1. |
| Columns bled into the next lane (test 4) | Positions come from one pure geometry function with fixed pitches larger than the hit targets, so two dots can never share space; the probe checks every pair of dot boxes, labels and phase labels in the real window. |
| Cards were unreadable, squeezed, broken mid-word (test 8) | Dots carry no title text. Text appears only in the preview and the expanded card, which have a fixed readable width (256px and 320px), wrap between words, and are never squeezed. The expanded card shows the full title with no clamp. |
| Cards existed but were not visible on open (test 3, 0.6.3 re-test) | The current milestone is centred on open; finished milestones fold to a tile that says how many cards it holds; a stack taller than its cap shows `+{n}`, never silently hides cards. |
| Drag worked only in fake DOM (test 6) | The timeline has no drag of cards at all. Every action goes through the expanded card's buttons and the existing Move to... menu. Pointer drag on empty space only pans. |
| Proven only by vm tests | Real-window screenshots (96 images, see the matrix) and layout-probe rules are part of acceptance (D-11). |

## Spacing Scale

Inherited unchanged from 62-UI-SPEC: xs 4px, sm 8px, md 12px (declared exception kept from the board), lg 16px, xl 24px, 2xl 32px. Added for the timeline: 3xl 48px (gap between milestone bands). Every value below is a multiple of 4, except these declared exceptions (as the board's 12px and 1px borders are):

| Value | Where | Reason |
|-------|-------|--------|
| 2px | Dot focus-ring width and offset | A 1px ring around a 20px mark is too faint to find; 2px offset keeps the ring clear of the mark's own 2px stroke so the state shape stays readable under focus |
| 2px | Mine outer ring width and offset (50% and 75% zoom) | Separates the Mine ring from the mark's 2px stroke so it reads as a second ring, not a thicker stroke, while staying inside the 28px hit box (20 + 2 x 2 + 2 x 2 = 28) |
| 2px | Background-coloured gap ring around the 8px info and error pips | Cuts the pip off from the mark so it reads as a separate sign over any state colour, in every theme |
| 4px dash, 2px gap | Held (On hold) ring | At a 20px circle (about 63px around) this gives about 10 visible dashes, enough to read as dashed; a 4px gap made the ring read as dots |
| 2px | Axis line, line arrowheads' stroke, emphasised line width | Line weights, not spacing; 1px lines vanish on high-DPI screens at rest emphasis |

| Selected halo | 36px circle behind the mark |
| Axis line | 2px |

| Gap between milestone bands | 48px along the axis, with a 1px divider centred in the gap |

### Pitches by zoom (centre to centre; always at least the hit target plus 4px, so two dots never touch)

| Zoom | Horizontal: along the axis (step pitch) | Horizontal: across (stack pitch) | Vertical: along (step pitch) | Vertical: across (stack pitch) | Dot content |
|------|------|------|------|------|------|
| 50% | 32px | 32px | 32px | 32px | mark only |
| 75% | 48px | 40px | 32px | 48px | mark only |
| 100% (default) | 64px | 40px | 40px | 64px | mark and initials |
| 150% | 96px | 40px | 60px | 96px | mark and initials |
| 200% | 128px | 40px | 80px | 128px | mark, initials and display ID |

Zoom changes spacing, never the size of a dot, a hit target or any text, so targets stay 28px and text stays readable at every level (a CSS `transform: scale` zoom is not allowed).

## Typography

Inherited unchanged: exactly 4 sizes relative to `var(--vscode-font-size)` and 2 weights.

| Role | Size | Weight | Line height | Used in the timeline for |
|------|------|--------|-------------|--------------------------|
| Small | 0.85em | 400 | 1.4 | Initials, display ID label, phase labels, progress text, preview meta, legend words, `+{n}`, folded tile counts, zoom level |
| Body | 1em | 400 | 1.5 | Preview title, expanded card title and text, notices, `No plans yet` |
| Heading | 1.2em | 600 | 1.2 | Milestone titles (`h2`), the expanded card title (`h2#tl-card-title`) |
| Display | 1.5em | 600 | 1.2 | Not used in the timeline (the page title `Team Board` stays as it is) |

Weights 400 and 600 only. No italics. Text in the preview and expanded card wraps between words (`overflow-wrap: break-word; word-break: normal`, the G-62-7 rule). The preview clamps the title to 3 lines with the full title in the expanded card; the expanded card never clamps. Phase labels are one line: when the segment is shorter than the label, the label shows the phase number only (`62`), and when shorter than that, nothing (the full name is in the `h3` text for screen readers, in the dot preview and in the expanded card). A label that is cut uses `text-overflow: ellipsis` and has the full text in `title`. Numbers use `tabular-nums`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--vscode-editor-background` | Scroller, canvas, gaps between bands, the glyph colour inside filled dots |
| Secondary (30%) | `--vscode-editorWidget-background` (preview, expanded card, legend band, folded tile); `--vscode-sideBarSectionHeader-background` falling back to `--vscode-editorWidget-background` (milestone headers, opaque); `--vscode-panel-border` falling back to `--vscode-widget-border` (axis, dividers, borders); `--vscode-foreground` and `--vscode-descriptionForeground` (text) | Surfaces and structure |

### Mine (D-05)

The current person's cards (model `mine: true`) have a filled initials chip: background `--vscode-foreground`, text `--vscode-editor-background`. Other people's chips are hollow: 1px `currentColor` border, text `--vscode-foreground`. A card that is mine but has nobody assigned (I added it) shows the filled chip with the `person` glyph (10px) instead of letters. The chip is beside the mark at 100% zoom and above; at 50% and 75% (no chip) a mine card's mark gets a 2px `--vscode-foreground` outer ring at 2px offset. The words `Assigned to you` or `You added this` are in the accessible name, preview and expanded card.

### Accent reserved for (explicit list; extends the board's list)

1. Focus ring on every focusable element. Dots use a 2px `--vscode-focusBorder` outline at 2px offset following the button's round shape (`border-radius: 50%` on mark-only dots, fully rounded ends (radius half the 28px height) on wider dot buttons); other controls keep the board's 1px rule. Declared exception: 2px on dots because a 1px ring around a 20px mark is too faint to find.
2. The selected halo behind the dot whose card is expanded: 36px circle filled with `color-mix(in srgb, var(--vscode-focusBorder) 20%, transparent)`.
3. The chosen option of the View and Direction switches, and the pressed Legend button (`--vscode-button-background`, as the board's chips).
4. Progress bar fill in milestone headers.
5. Primary buttons stay the board's (`New item`, `Import plans` in the empty state). The timeline adds no primary button.
6. Link-style buttons in the expanded card (dependency names), always underlined on hover and focus and always in high contrast.

Contrast targets (checked by the probe in all four themes): text 4.5:1 against its own background; dot marks, glyphs on filled discs, emphasised lines, the axis, focus rings and the selected halo's ring 3:1 against the canvas. Faint at-rest lines are decorative and exempt.

## Layout

### Where the switches go (D-04)

Toolbar row 2 (the existing `controls` row; the band stays solid, G-62-2):

| Columns view (unchanged except the first control) | Timeline view |
|------|------|
| View switch, Milestone select, milestone summary, Group by, filters | View switch, Direction switch, Zoom group, Legend button, filters |

- The View switch is the first control in row 2 in both views and in the narrow list layout, so it never moves when the view changes. Options `Columns` and `Timeline`. Default `Columns` for a person who never chose.
- In Timeline, Milestone select, the milestone summary and Group by are hidden (`hidden`, not removed): every milestone is on the timeline with its own progress in its header, and lanes do not apply. Filters stay and work (see "Filters").
- `Import plans` and `New item` stay in row 1, unchanged.
- Both choices, the zoom level, the legend's open state, which finished milestones the person opened, and the scroll position per direction are remembered in webview state. `UI_VERSION` goes from 2 to 3; a version 2 state keeps all its fields and gains the timeline defaults (no reset of the person's board choices).
- Switching view keeps the selected card: a card expanded in the timeline is the selected card in Columns, and a card selected in Columns has its dot focused and centred when the timeline opens.

### The scroller (62-21 rule kept)

In Timeline the page does not scroll. The toolbar, banners and legend band are opaque bands at the top; `.tl-scroll` below them is the only element that scrolls, in both directions. Nothing passes under the toolbar.

### Horizontal (left to right)

```
| v0.4.x line  [Show milestone] |   | v0.6.0 Team Mode  [Current]  62%, 26 of 42 plans done   | | Added on the board |
| Finished: 30 done    |   |  Phase 60 ____   Phase 61 ________    Phase 62 _______   | |                    |
| (folded tile)        |   |  o---o---o---o----o----o---o---o---o---o----o---o---o    | |  o---o             |
|                      |   |      o       o         o       o   o                     | |                    |
|                      |   |              o                     o  +3                 | |                    |
```

Top to bottom inside each milestone band:
1. **Milestone header** (56px, opaque, sticky to the left edge of the scroller while its band is in view, max 320px wide): `h2` title (Heading), the `Current` badge on the active milestone, progress bar 96px x 8px and `{p}%, {d} of {t} plans done`, and for a finished milestone a `Fold milestone` button.
2. 8px gap, then the **phase rail**: one row per set of non-overlapping phase spans (24px each). A phase segment runs from the start of its first step's slot to the end of its last step's slot; its label sits left-aligned above its 4px bar. Overlapping spans (two phases whose steps interleave) go on separate rail rows, so labels never collide.
3. 8px gap, then the **axis**: a 2px line along the band through the centre of stack row 0, with an 8px tick at each step.
4. **Dots**: step `s` at `bandStart + 24 + s * stepPitch`; stack slot `k` at `axisY + k * stackPitch` (row 0 sits on the axis, parallel cards stack below it). Inside a step, slots go in phase then plan number order, so one phase's parallel cards sit together.
5. 32px canvas padding below the tallest stack in any band.

Bands follow each other left to right in roadmap order with 48px between them. Cards added on the board (no milestone) get a last band titled `Added on the board`, laid out by their own dependencies.

### Vertical (top to bottom)

```
| v0.6.0 Team Mode  [Current]  62%, 26 of 42 plans done        (sticky, full width) |
| Phase 60      |  o   o                                                            |
|               |  o                                                                |
| Phase 61      |  o   o   o                                                        |
|               |  o   o                                                            |
| Phase 62      |  o   o   o   o   o   o   o   o   +3                               |
| v0.4.x line  Finished: 30 done   [Show milestone]           (folded tile)        |
```

1. **Milestone header**: a full-width 56px row, opaque, sticky at the top of the scroller while its band is in view, pushed off by the next band's header.
2. **Phase gutter** on the left (160px, 120px or 64px by width): each phase label sits at the top of its segment beside a 4px bar that runs the segment's length. Overlapping spans put their bars in extra 8px columns inside the gutter, nearest the axis first. When two labels would overlap, the later one moves down to the next free line inside its own segment; when its segment is shorter than one label line, it shows the number only.
3. **Axis**: a 2px vertical line right of the gutter, ticks at each step.
4. **Dots**: step `s` at `bandTop + 56 + 24 + s * stepPitch`; slot `k` at `axisX + k * stackPitch` (slot 0 on the axis, parallel cards to the right).

### Narrow widths

| Width of the board tab | Behaviour |
|------------------------|-----------|
| 1400px and wider | Either direction as chosen. Horizontal shows about 18 steps at 100%. |
| 900px to 1399px | Either direction. Toolbar row 2 may wrap to a third line; the bands stay opaque and above the scroller. |
| 520px to 899px | Either direction. Vertical gutter 120px. |
| Under 520px (includes the 480px screenshot width) | The timeline is drawn **vertical**, whatever was chosen. The Direction switch shows `Vertical` checked and `Horizontal` with `aria-disabled="true"` and the title `Horizontal needs a wider window.`; the saved choice is kept and comes back when the tab is wider. Gutter 64px (phase number only). The toolbar uses the list layout's wrapping rules and the Filters disclosure. The expanded card is the scroller width minus 16px and is placed above or below its dot only. |
| Zoom 200% to 400% | The effective width falls under 520px, so the same forced-vertical rule applies (reflow, WCAG 1.4.10). Two-dimensional scrolling inside the timeline scroller is the accepted exception, as for the kanban. |

### First screen (D-09)

- First open of the timeline (no saved scroll for this direction): the active milestone's band is centred along the axis. If the band is longer than the scroller, the first step that holds a card not done or cancelled is placed one third of the way in from the start edge. Across the axis the scroll starts at 0.
- Later opens restore the saved scroll for that direction and zoom.
- If no milestone is active, the first milestone with unfinished cards is used; if every card is finished, the last milestone.

### Folded finished milestones (D-09)

- A milestone whose every card is Done or Cancelled is "finished" and starts folded into its tile: title (Heading, clamp 2 lines, full text in `title`), the line `Finished: {d} done` or `Finished: {d} done, {c} cancelled` (Small), and the button words `Show milestone` (the whole tile is the button). Enter, Space or click opens it; the band grows to full size and the header shows `Fold milestone`.
- A person's open/fold choice per milestone is remembered. A milestone that stops being finished (a card reopened) unfolds by itself and stays unfolded.
- Lines to or from cards inside a folded milestone attach to the tile's nearest edge, so cross-milestone dependencies stay visible.

### Stacks taller than the cap

A step with more than 8 cards shows 8 dots and a `+{n}` button in the 9th slot (same box as a dot, Small text, 1px `--vscode-panel-border` border, fully rounded ends like the dot buttons). Activating it shows the whole stack (the canvas grows; following content moves with the band animation) and the button becomes `Show fewer` in the last slot. Lines to hidden cards attach to the `+{n}` button.

## Dots

Each dot is a `button` (keyboard and screen reader operable), in an `li`, inside its phase's `ol`.

| Part | Contract |
|------|----------|
| Mark | SVG 20px, shape and colour from the state table, glyph 12px |
| Initials | the assignee's initials from the model (`assignee.initials`, max 2 letters) in the 20px chip; hollow chip for someone else, filled for mine; no chip when nobody is assigned and it is not mine |
| Display ID | at 200% only, editor font, Small, after the chip |
| Hover | the mark grows to 1.25x (the hit box does not change, so nothing shifts), the card's lines are emphasised, and after 300ms the preview opens |
| Focus (keyboard) | 2px focus ring, lines emphasised, preview opens at once (no delay), the dot is scrolled into view with 48px margin |
| Expanded | selected halo, mark at 1.25x, lines emphasised, `aria-expanded="true"`, `aria-controls="tl-card"` |
| Changed by a teammate | the board's static 3 second 2px outline in `--vscode-editor-findMatchHighlightBackground`, plus the pulse (see Motion) |
| Pending | dashed 1px outline around the hit box, `aria-busy="true"` |
| Filtered out | not a button: drawn in the ghost layer as an 8px hollow ring in `--vscode-descriptionForeground` at its usual place, no initials, no preview, not focusable, absent from the list for screen readers; its lines are not drawn |
| Drag | none. Dots are not draggable. Pointer down on a dot and moving does nothing; pointer down on empty canvas pans. |

### Accessible name of a dot (built by one pure function in `timeline.ts`, set with `setAttribute`)

`{card.a11yLabel} {Assigned to {name}. | Assigned to you. | Nobody is assigned.} Step {s} of {n} in {milestone title}. {Waits for {list}. | Waits for nothing.} {Needed by {k} cards. | (omitted at 0)}`

Example: `Plan 62-03, Board webview client. State: Ready. Blocked: no. 2 dependencies. Estimated 48 thousand tokens. In this state for 3 days. Assigned to Dana. Step 3 of 7 in v0.6.0 Team Mode. Waits for 62-01 and 62-02. Needed by 4 cards.`

`{list}` names up to 3 IDs then `and {k} more`. `aria-describedby` points to the hidden hint `Use the arrow keys to move along the timeline. Press Enter to open the card. Press M to move it.` (without the last sentence when the card has no menu).

## Hover Preview and Expanded Card (D-06)

### Preview (hover after 300ms, or keyboard focus at once)

256px wide, opaque `--vscode-editorWidget-background`, 1px `--vscode-panel-border` (contrastBorder in high contrast), 4px radius, the floating shadow, padding 8px 12px, `pointer-events: none`, `aria-hidden="true"` (the dot's name already says everything).

Content, top to bottom: state icon and state word plus display ID (Small); title (Body, clamp 3 lines); badges as on the card face (Blocked, On hold, Looks finished, please confirm, Cancelled); `Assigned to {name}` or `Nobody yet` (Small); `Step {s} of {n}` and `Waits for {k}` / `Waits for nothing` (Small, muted); the hint `Click to open the card.` (pointer) or `Press Enter to open the card.` (keyboard), Small, muted.

Closes 100ms after the pointer leaves the dot, at once when focus leaves, on Escape, and when the expanded card opens. Moving from one dot to another within 600ms of a preview closing opens the next preview with no delay.

### Expanded card (click, Enter or Space)

It is the board's card face, rendered by the same code path as a kanban card (`cardEl`'s content: state row, ID, title, meta row with assignee, badges, dependency count, estimate, age, pending line, refusal line), so the two views can never drift apart. Differences, all additive:

| Part | Contract |
|------|----------|
| Container | `section#tl-card[role=dialog][aria-modal=false]`, 320px wide, opaque `--vscode-editorWidget-background`, 1px border (contrastBorder in high contrast), 4px radius, floating shadow, padding 12px 16px, gap 8px between rows |
| Title | `h2#tl-card-title`, Heading size, **no clamp**, wraps between words; receives focus on open (`tabindex="-1"`) |
| Close | icon button top right, `close` icon, `aria-label` and `title` `Close card`, 28px |
| Timeline facts | under the meta row, a `dl` (Small): `Step` `3 of 7 in v0.6.0 Team Mode`; `Waits for` the dependency names as link buttons (activating one moves focus to that dot and opens its card) or `Nothing`; `Needed by` the same, omitted at 0; `Finished` `{local date}` only for done cards when the model gives it (D-01: the only place a time appears) |
| Notes | the cycle note or a missing dependency note when they apply (copy below) |
| Actions row | `Move to...` (the existing menu, anchored to this button, with moves, then a separator, then the assignment items, exactly as on the board; hidden when the viewer has no menu, disabled with the reason when offline), then `Open details` (secondary). No other actions and no new paths: everything posts the existing host messages and the host re-checks permissions. |
| Open details | closes the card, opens the existing `#detail` drawer for this card; closing the drawer returns focus to the dot |
| Refusals and pending | shown in the card exactly as on a board card, never auto-dismissed; after the card closes, the dot keeps the refusal pip until the refusal is dismissed or the card's data changes |

Closing: Escape (when no menu is open; with the menu open, Escape closes the menu first), the Close button, a click or tap anywhere outside the card and outside the menu, or opening another dot (the card switches to that dot). Focus returns to the dot when focus was inside the card; a click on another dot keeps focus there.

### Placement (preview and card use the same function)

Measured against the scroller's visible rectangle less the 8px edge margin, and below any opaque sticky milestone header.

| Direction | Order of sides tried | Alignment |
|-----------|----------------------|-----------|
| Horizontal | below the dot, above, right, left | below/above: card's left edge at the dot's left edge, shifted left as needed to stay inside; right/left: card's top at the dot's top, shifted up as needed |
| Vertical | right of the dot, left, below, above | right/left: card's top at the dot's top, shifted up as needed; below/above: left edge at the dot's left edge, shifted as needed |
| Under 520px | below, above | full scroller width minus 16px |

Rules: take the first side where the whole card fits. If none fits, take the side with the most room and cap the card's height to it (the card scrolls inside; the title row and Close stay at the top). The card never covers its own dot's hit box. The card is positioned inside the canvas, so it moves with its dot when the person pans; it is re-placed only when it opens, when the window resizes, when the zoom or direction changes, or when a live update moves its dot. The Move to... menu (z-index 10) stays above the card (z-index 6); the preview is z-index 7; milestone headers are z-index 3.

## Dependency Lines (D-07)

- One SVG under the dots. Each line goes from the dependency's dot to the dependent's dot: horizontal direction from the right edge of the source mark to the left edge of the target mark; vertical from the bottom edge to the top edge.
- Same slot row: a straight line. Different rows: a cubic curve with both control points half a step pitch along the axis from the ends, so lines leave and arrive along the direction of travel.
- A dependency the board does not have draws no line; the card says `Waits for {id}, which is not on the board.`
- Hover, focus and the expanded card emphasise that card's lines in and out (style table above); everything else stays at rest.
- Lines are redrawn after any layout change; while dots are moving they are hidden (opacity 0) and fade back when the move ends.

## Zoom and Pan (D-09)

| Input | Effect |
|-------|--------|
| `Zoom out` / `Zoom in` buttons | Steps through 50%, 75%, 100%, 150%, 200%; the button at the end of the range is `aria-disabled` |
| Zoom level | `output` shows `100%`; its `aria-label` is `Zoom 100%` |

## Keyboard Model (D-10)

One tab stop for all dots (roving tabindex). "Along" and "across" follow the direction.

| Along back | Left | Up | Previous step, same rules |
| Across forward | Down | Right | Next dot in the same step; at the end, nothing |
| Across back | Up | Left | Previous dot in the same step; at the start, nothing |
| Home / End | | | First / last dot of the current milestone |
| Ctrl+Home / Ctrl+End | | | First / last dot of the timeline |
| Page Down / Page Up | | | First dot of the next / previous phase |

| M, Shift+F10, ContextMenu | | | Open the Move to... menu for the focused dot, anchored to the dot (as on a board card; nothing when the card has no menu) |

| `+` `=` `-` `0` | | | Zoom (see above) |

Tab order in the Timeline view: toolbar controls in visual order (View, Direction, Zoom out, Zoom in, Fit milestone, Show legend, filters, Import plans, New item), banner actions, the legend (no stops inside), then inside the timeline in DOM order: each milestone's `Fold milestone` button (finished, unfolded milestones only), the dot group (one stop on the active dot), then the expanded card (when open, it follows the dots in the DOM; opening moves focus into it). ## Filters

The toolbar filters (Mine, Ready, Blocked, Phase, Requirement) apply in the timeline. Positions never change because of a filter (the sequence stays readable): matching dots are drawn as usual, the rest become ghosts. Lines are drawn only between two matching dots. The board's debounced `Showing {shown} of {total} cards.` announcement is unchanged. When nothing matches, the scroller shows the board's empty filter state (`No cards match these filters`, `Clear the filters to see every card.`, `Clear filters`) in an opaque band at the top of the scroller, and the ghosts stay visible below it.

## Live Updates

- A new model renders in place. Focus, the expanded card, the preview, zoom and scroll stay where they are.
- A dot whose state changed gets the pulse and the static 3 second outline; teammates' changes get the board's one batched announcement, never one per dot.
- When the layout changes (a dependency finished and cards moved to an earlier step, a card was added, a milestone finished and folds next time), dots move to their new places (see Motion); the expanded card follows its dot and is re-placed with the same rules.
- A milestone that becomes finished while shown stays shown in this session; it starts folded on the next open.
- While a menu is open, the menu follows the board's rule (it never offers moves the model no longer has).
- Nothing renders while the tab is hidden (the board's `visible` rule); on show, the cached model draws first, then the refresh, with no first-draw stagger the second time.

## Motion (D-08)

Only `transform` and `opacity` are animated (plus `stroke-dashoffset` on emphasised lines). No animation blocks input: dots are focusable and clickable from the first frame; a new interaction cancels a running animation and jumps to its end state. The client reads `matchMedia("(prefers-reduced-motion: reduce)")` before animating and listens for changes.

| Motion | Trigger | Duration | Easing | Distance / change | Reduced motion |
|--------|---------|----------|--------|-------------------|----------------|
| Dots appear in sequence | first draw of the timeline in a session (not on live updates, not on return from hidden) | 160ms per dot; start delay `min(step * 24ms, 600ms)` | `cubic-bezier(0.2, 0, 0, 1)` (ease-out) | scale 0.6 to 1, opacity 0 to 1; only dots in or near the viewport animate, the rest appear at once | all appear at once |
| Lines fade in | after the last dot of the first draw | 200ms | ease-out | opacity 0 to 1 | appear at once |
| Dot grows on hover or focus | pointer enters, focus arrives | 120ms | ease-out | mark scale 1 to 1.25 (hit box fixed) | no scale; the focus ring and line emphasis still show |
| Lines draw in on emphasis | hover, focus or expand | 240ms | ease-out | `stroke-dashoffset` from the path length to 0, for that card's in and out lines only (at most 24 paths) | drawn at once |
| Preview opens | 300ms after hover, at once on focus | 120ms | ease-out | opacity 0 to 1, 4px slide away from the dot | appears at once |
| Expanded card springs open | click, Enter, Space | 200ms | `cubic-bezier(0.34, 1.56, 0.64, 1)` (small overshoot) | scale 0.85 to 1 and opacity 0 to 1, `transform-origin` at the corner nearest the dot | appears at once |
| Expanded card closes | Escape, Close, click away | 120ms | ease-in | scale 1 to 0.95, opacity 1 to 0 | disappears at once |
| State change pulse | a live update changes a dot's state, or the person's own move is confirmed | 600ms, once | ease-out | a 2px ring in the new state colour scales 1 to 1.8 and fades out | no pulse; the static 3 second outline only (it is not motion) |
| Dots move to new places | live re-layout, zoom change, fold or show a milestone, show a full stack | 240ms | `cubic-bezier(0.4, 0, 0.2, 1)` | FLIP translate from the old to the new position; lines hidden during the move, fade in 120ms after | jump to the new place |
| Direction switch | Direction switch, or crossing the 520px width | 320ms | `cubic-bezier(0.4, 0, 0.2, 1)` | FLIP every dot from its horizontal to its vertical place (or back); headers and rail cross-fade 160ms | redraw at once |
| View switch | View switch | 160ms | ease-out | the incoming view fades in, opacity 0 to 1; no movement | at once |

Performance budget on the repository's own board (about 100 cards, about 150 lines):
- First draw of the timeline: script and layout under 100ms before the first frame; the stagger adds at most 760ms and never delays input.
- During pan, zoom, direction switch and the first-draw stagger: frame interval p95 at or under 17ms (60 fps) as the target; the real-window run reports it, and fails above 33ms p95 (under 30 fps).
- No layout reads inside animation frames except one batched read before a FLIP; `will-change: transform` only on elements while they animate.
- One SVG for all lines; at most 24 paths animate at a time.

### Truths lifted into the plan (verifiable without a browser: `node --test` on `timeline.ts`, the geometry function and the page in the vm harness)

- The layout function is pure and deterministic: the same state gives the same steps, slots and edges; a dot's step is its dependency depth within its milestone; parallel cards share a step; ties break by phase then plan number; a cycle falls back to number order and sets `cycle` on its milestone.
- At every zoom level in both directions, no two dot boxes, phase labels, or a phase label and a dot box come closer than 4px; every dot box is at least 28px by 28px.
- Under 520px the drawn direction is vertical whatever is saved, and the saved direction is unchanged.
- Dots are never draggable and no timeline element posts a message the board does not already post.
- The expanded card offers exactly the board card's menu (moves, separator, assignment items) and `Open details`; nothing else.
- Every authored timeline string is free of U+2014 and U+2013 and of the banned plain-language terms; every title and name is set with `textContent`.
- The timeline CSS uses only `--vscode-*` variables and `color-mix` of them; no colour literal.
- `prefers-reduced-motion: reduce` removes every timeline transition and animation, and the client skips FLIP and the stagger.
- Persisted state version 3 keeps every version 2 field and adds the timeline fields; a version 2 state loads with Columns as the view.

### Real-window probe rules (layout-probe.js gains a timeline section; every rule reports a plain problem string)

1. **No overlap**: no two dot hit boxes, initials chips, display ID labels, phase labels, `+{n}` buttons or milestone headers overlap by more than 1px.
2. **Nothing clipped**: every dot, label and header lies fully inside the canvas; any text container whose content is wider than its box has `text-overflow: ellipsis` and a `title` (an intentional cut), else it is a problem.
3. **Readable preview and card**: when shown, the preview and the expanded card lie fully inside the scroller's visible rectangle less 8px, below every opaque sticky header and the toolbar; they do not cover their own dot's hit box; their computed background alpha is 1; no text line inside is cut (each text element's `scrollWidth` at most its `clientWidth`); the card title is not clamped; computed font sizes are at least 0.85 of the editor font size; every button inside is at least 24px by 24px.
4. **Opaque layers**: the toolbar, legend band, milestone headers, preview and expanded card have a computed background alpha of 1 in all four themes.
5. **One scroller**: the page has no horizontal or vertical scroll in Timeline; `.tl-scroll` is the only scrolling element.
6. **Focus visible**: the focused dot is fully visible and not under a sticky header after any arrow key.
7. **First screen**: on first open, at least one dot of the active milestone is inside the visible scroller.
8. **Lines attached**: each line's ends are within 2px of its two dots' mark edges (or the tile or `+{n}` edge).
9. **Contrast**: dot marks and glyphs at least 3:1 against the canvas; initials, preview and card text at least 4.5:1 against their own background; in all four themes.
10. **Hit targets**: every dot, tile and `+{n}` is at least 24px by 24px, and the gap between neighbouring hit boxes is at least 4px.
