<objective>
Put the route check at the one place content leaves for a model, `NearAiClient.request`, driven by a session context every production request runs inside, and record each route decision. With the default label nothing changes; plans 20 to 24 make labels raise the tier.

Purpose: CLAS-06 (the route decided before every model request, wherever it starts) and D-31, using D-36's pre-send meaning; OFFL-01 (local data only); GATE-07 (route decisions recorded). This is the first plan of PR 4. The route check was placed here on purpose (research section 11 names it as the part to move if PR 2 grows): it goes live with the labels that give it something to decide, PR 2 stays a tool-gate PR, and no plan depends on a size condition.
Output: `src/gate/sessionMark.ts`, the route check and `RouteRefusedError` in `nearAiClient.ts`, the client's route kind from `providerFactory.ts`, session contexts at every production request site, `gateRouteGuard.test.ts`.

Size note: about 95,000 tokens, under the per-plan budget; the route check, the session context at every request site and the route records only prove the requirement together, so they stay one plan.
</objective>
