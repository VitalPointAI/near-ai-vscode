<objective>
Make the chat's label last and show: it is saved with the chat, survives restarts and syncs without ever going down on its own, appears next to the model and in the status bar, and comes down only when a person says why; a lowering reaches another copy of the chat only as a signed declassification that the other copy can check. Ships with plan 22 in PR 4c, so no release keeps a mark only in memory.

Purpose: PR 4c (D-49). CLAS-04 (the mark never goes down except by a person's declassification, which is recorded), CLAS-01 (chats carry labels), GATE-07 (label.declassify and label.declassify-rejected recorded), D-29, D-33, D-54.
Output: `ThreadMeta.label` with a raise-only `mergeMeta`, signed lowerings and the merge's judge, the chat label and refusal text on the page, the status bar label, `nearAi.label.lowerChat`, `gateChatLabel.test.ts`.

Corrections from the 2026-11-17 audit and the PR #78 review, applied here: `label.declassify` and `label.declassify-rejected` are on `LABEL_EVENT_IDS` (plan 19); the status bar learns which chat is in view from the chat itself; the merge is raise-only, because a lowering time carried unsigned in synced metadata could be claimed by any copy (a teammate's, a compromised computer's) and a newer-lowering-wins rule could discard a raise made elsewhere; a lowering travels only as a declassification signed with the Phase 69 signer and checked against this computer's key sources, and it is applied only when its from-mark covers the other copy's mark and that copy was not used after it; older versions pass the field through, which a test pins; the unreadable-label sentence names the Lower command. The route refusal sentences that name the Lower command are in plan 24.

Recorded design choices (planner's discretion, visible): outside Team Mode this computer knows only its own install's keys, so a lowering made on another computer is not applied (the joined, higher mark stays and the chat says why) until Phase 71's verified devices; a lowering is judged where a copy first meets it, so a computer that cannot verify it keeps the higher mark, and that mark can sync back to the computer that lowered it; the person is told and can lower again there. This is the fail-closed reading of CLAS-04.
</objective>

## Trust Boundaries

|----------|-------------|
| sync -> chat metadata | another computer's, a teammate's or an attacker's copy can carry any label and any claimed lowering |
| person -> declassification | the only way down, signed with the person's device key |
| chat page (webview) -> label text | label strings are rendered in the page |

| T-70-73 | Repudiation | a declassification nobody can trace | medium | mitigate | only the person's command, a required reason, a label.declassify record and a signed declassification; applied and rejected merges recorded; source scan for other callers (Tasks 2, 3) |
