## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| published release (GHCR or HQ, GitHub release assets) -> the comparison | the artefacts under test |
| tagged source and approved files -> the rebuild VM | the independent build's inputs |
| rebuild VM -> network | only the npm path the release build used |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48.3-107 | Tampering | a rebuild that shares state with the release build | medium | mitigate | a fresh VM from your organization's guest image, inputs copied in by hash, destroyed after |
| T-48.3-108 | Repudiation | a "reproduced" claim that is not true | high | mitigate | the result is computed from digests only; differences are listed file by file; G525 records what differs |
| T-48.3-109 | Tampering | hostile archive paths in a compared layer or zip | medium | mitigate | the comparison streams and never extracts; unsafe paths are reported as differences |
| T-48.3-110 | Tampering | the rebuild running other commands than the release did | medium | mitigate | commands come from `release.yml` at the tag; an unrecognised build step stops the run |
| T-48.3-SC | Tampering | npm installs | high | mitigate | No package is installed on the host; the rebuild's `npm ci` runs inside the VM from the tag's lockfile by integrity, as the release build did |
</threat_model>
