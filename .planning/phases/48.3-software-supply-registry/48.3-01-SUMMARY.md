# Phase 48.3 Plan 01: The intake's policy and state machine Summary

**The owner's supply policy (7-day age, named-approver fast lane, one or two approvers by flag, D-04 licences with an SPDX expression parser, tighten-only site policy) and the eight-state intake lifecycle, as pure tested code that every later intake plan calls.**

## What was built

- `evaluate(facts, policy, now)` runs D-16's gates in order: hard refusals first (name, integrity, registry signature, `MAL-`, KEV, critical with a fix, source form), then the age gate (waiting with `releaseAt`, or the fast lane with a reason), then the review flags (new or similar name, scope mismatch, install script, licence, provenance regression or unverified, repository change, publisher change, high finding). The approver count is the largest any flag needs, never the sum.
- `licenceAllowed` parses `AND`, `OR`, `WITH` and parentheses without throwing; malformed expressions are "unparseable" (review), over-long ones go to review.
- `mergePolicy` applies your organization's `supply.policy` and refuses any looser value with "Your organization's supply policy may only tighten the defaults: <field> <value> is looser than <default>."
- `transition` implements every D-15 transition; `openStates()` and `overdue()` support the scheduled run and the alerts of 48.3-19.
