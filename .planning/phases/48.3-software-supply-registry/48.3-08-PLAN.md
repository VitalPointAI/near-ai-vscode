<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream registries -> gather host | untrusted images and metadata enter |
| gather host -> quarantine -> signing host | gathered bytes and claims cross into the host that holds the key |
| signing host -> HQ Harbor approved/ and sterling/ | only signed, approved content is published |
| registry accounts | the gather robot (push quarantine), the signer robot (read quarantine, push approved, sterling, supply) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48.3-26 | Tampering | an upstream image swapped behind its tag | high | mitigate | fetch only by the locked digest; a differing digest is refused |
| T-48.3-27 | Tampering | a compromised gather host feeding altered bytes | high | mitigate | the signing host re-derives SBOM and scan from the bytes and checks the digest against the lock; only publish time and origin are claims (G524) |
| T-48.3-28 | Elevation of privilege | the gather host signing | high | mitigate | the gather host has no key; `oci.mjs` refuses signing work on a gather-role host; the site key lives only on the signing host's HSM |
| T-48.3-29 | Spoofing | approvals with the release key (G396) | high | mitigate | `assertSiteKey` refuses anything but the site key's pkcs11 address and the configured release key; test "site key only" |
| T-48.3-30 | Repudiation | evidence lost in the copy to approved/ | medium | mitigate | `verifyAll` after every copy; a missing attestation fails the publish (Pitfall 2) |
| T-48.3-31 | Elevation of privilege | robot account misuse | medium | mitigate | the gather robot can only push to quarantine; credentials come from host files named in the site file, never command lines; 48.3-09 creates the robots with these rights only |
| T-48.3-32 | Spoofing | a release image not built by us | high | mitigate | supplier release key signature and SBOM attestation verified in key mode before anything is copied into sterling/ |
| T-48.3-33 | Tampering | a state file edited in quarantine to "approved" | low | mitigate | a state file grants nothing; only a site-key record on the digest makes content servable, and `reconcile` finds signatures without records |
| T-48.3-SC | Tampering | npm installs | high | mitigate | No package is installed in this plan |
</threat_model>
