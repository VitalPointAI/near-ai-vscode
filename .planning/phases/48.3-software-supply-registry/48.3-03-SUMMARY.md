# Phase 48.3 Plan 03: Spike S-B (hauler and OCI referrers) Summary

## Spike S-B

Question (D-36, research open question 3; Pitfall 2): does hauler 2.1.2 carry an artefact's cosign signature and its OCI 1.1 referrer attestations (SBOM, scan, VEX, promotion record) through `store add`, `store save`, `store load` and `store copy`, for images and for non-image files, so evidence travels with the digest into the offline bundle and onto air-gapped sites; and is ORAS needed.

Setup, all on this machine with nothing but 127.0.0.1:
- hauler 2.1.2 and cosign 3.1.4 from `sh compliance/ci/install-tool.sh <tool> /tmp/x483/tools` ("hauler 2.1.2 sha256 5c4c5b54a4a249bbafebd069dda3df86622515c93fa6657b045e081d82b7b2ce OK", "cosign 3.1.4 sha256 424e2c97d0b45fd7a6b608a87f090f35633f4c23ece5f092d48bba11aaf4bbfa OK"), never on PATH.
- Zot by the pinned digest `ghcr.io/project-zot/zot-linux-amd64@sha256:b68f727fe35c1eb45b2ae91519dfb0e33192d69b5104882c3e7809b7146c4a02`, rootless podman, 512 MiB, on 127.0.0.1:18897 (A, `x483-sb-zot-a`) and 127.0.0.1:18898 (B, `x483-sb-zot-b`), ports from the owner's instruction for this run (the plan's 5711 and 5712 were not used). Podman fetched the digest again before starting A (the local copy had been removed by something else on this machine); the content is fixed by the digest. Same config as spike S-A (`distSpecVersion 1.1.1`, `compat ["docker2s2"]`, no extensions).
- Its own scratch folder `/tmp/x483/sb` (not 48.3-02's), `HOME=/tmp/x483/sb/home`, hauler's directory `-d /tmp/x483/sb/hauler`; a throwaway cosign key pair; for the site-key path, spike S-A's throwaway SoftHSM2 token and its helpers (statement, PAE, DER, bundle, referrer push). Every step inside the owner's capped wrapper.

## Commands

Task 1 (the tracer), as run:

```
podman run -d --name x483-sb-zot-a --memory 512m -p 127.0.0.1:18897:5000 -v .../zot-config.json:/etc/zot/config.json:ro,Z ghcr.io/project-zot/zot-linux-amd64@sha256:b68f727f...
podman run -d --name x483-sb-zot-b --memory 512m -p 127.0.0.1:18898:5000 -v .../zot-config.json:/etc/zot/config.json:ro,Z ghcr.io/project-zot/zot-linux-amd64@sha256:b68f727f...
podman build -q -t localhost/x483-sb-hello:1 -f img/Containerfile --network none img            # FROM scratch + one file
podman push -q --tls-verify=false --digestfile hello.digest localhost/x483-sb-hello:1 docker://127.0.0.1:18897/spike/hello:1
  -> sha256:8813a31cba45caa59ce83591aadaa7b189818300634ae65d06bfdb6e967e26d2
REF=127.0.0.1:18897/spike/hello@sha256:8813a31c...
cosign sign   --key cosign.key --signing-config signing-config.json -y --allow-http-registry $REF
cosign attest --key cosign.key --signing-config signing-config.json --type cyclonedx --predicate sbom.cdx.json -y --allow-http-registry $REF
# the site-key record, by spike S-A's path: statement + PAE, pkcs11-tool --sign --mechanism ECDSA --signature-format openssl on the token,
# a Sigstore bundle v0.3, pushed as a referrer manifest in cosign's shape
curl -s -H 'Accept: application/vnd.oci.image.index.v1+json' http://127.0.0.1:18897/v2/spike/hello/referrers/sha256:8813a31c...
hauler store add image $REF -s store1 -d /tmp/x483/sb/hauler                 # no --key (47-01: hauler's --key cannot read cosign v3 bundles)
hauler store info -s store1 -d /tmp/x483/sb/hauler
hauler store save -s store1 -d /tmp/x483/sb/hauler -f haul.tar.zst
hauler store load -s store2 -d /tmp/x483/sb/hauler -f haul.tar.zst
hauler store info -s store2 -d /tmp/x483/sb/hauler
hauler store copy registry://127.0.0.1:18898 --plain-http -s store2 -d /tmp/x483/sb/hauler
curl -s ... http://127.0.0.1:18898/v2/spike/hello/referrers/sha256:8813a31c...;  curl -s http://127.0.0.1:18898/v2/spike/hello/tags/list
cosign verify --key cosign.pub --insecure-ignore-tlog --allow-http-registry 127.0.0.1:18898/spike/hello@sha256:8813a31c...
cosign verify-attestation --key cosign.pub --type cyclonedx --insecure-ignore-tlog --allow-http-registry 127.0.0.1:18898/spike/hello@sha256:8813a31c...
cosign verify-attestation --key token.pub.pem --type urn:near-ai-vscode:supply-record:1 --insecure-ignore-tlog --allow-http-registry 127.0.0.1:18898/spike/hello@sha256:8813a31c...
```
