<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| approver's device -> Keycloak -> OpenBao -> review command | the approver's identity crosses three systems before it is recorded |
| signed record -> anyone checking it | the record's content is trusted only after cosign verifies the site-key signature |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48.3-11 | Spoofing | an approval claimed by someone not listed | high | mitigate | OpenBao's role binds `sub` to `supply.approvers` and `acr` to the step-up; `sufficient` checks the list again; the subject comes from OpenBao, never from the command line |
| T-48.3-12 | Elevation of privilege | one person approving twice, or approving their own fast lane | high | mitigate | distinct subjects only; requester excluded for the fast lane; tests "repeated subject" and "fast lane requester" |
| T-48.3-13 | Spoofing | device-code phishing (an attacker starts a flow and sends the code) | medium | mitigate | the review command shows the item being approved and the code together; the token lives 5 minutes and can only look itself up; the record names the approver, and OpenBao's audit log records the login |
| T-48.3-14 | Tampering | a record for one digest reused for another | high | mitigate | `checkRecord` compares the subject digest with the artefact's; cosign verifies the attestation on that digest only |
| T-48.3-15 | Repudiation | a site-key signature with no record | high | mitigate | `reconcile` feeds `SupplySignatureUnmatched` (48.3-19) |
| T-48.3-16 | Information disclosure | the review client used as a general sign-in | low | mitigate | public client, loopback redirects only, no password or implicit grant; the OpenBao token it leads to can only look itself up |
| T-48.3-SC | Tampering | npm installs | high | mitigate | No package is installed in this plan |
</threat_model>
