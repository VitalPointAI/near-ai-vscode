# Phase 48.3 Plan 02: Spike S-A (cosign 3.1.4 attestations and the PKCS#11 attach path) Summary

**On the pinned cosign 3.1.4 and Zot 2.1.23, SBOM, scan, VEX and supply-record attestations are stored as OCI 1.1 referrers and verify in key mode; a record signed on a SoftHSM2 token verifies with stock cosign once our own code builds the bundle and pushes the referrer; `cosign copy` loses referrers, `cosign save`/`load` keeps them.**

## Decision

48.3-08's `deploy/supply/lib/sign.mjs` implements exactly this; it does not re-spike.

Storage: every attestation is a Sigstore bundle v0.3 stored as an **OCI 1.1 referrer** of the artefact's digest (`artifactType application/vnd.dev.sigstore.bundle.v0.3+json`). No tag forms. Predicate types, as cosign writes them:

| Evidence | `--type` | predicateType |
|---|---|---|
| SBOM (CycloneDX) | `cyclonedx` | `https://cyclonedx.org/bom` |
| Scan (Grype) | `vuln` | `https://cosign.sigstore.dev/attestation/vuln/v1` |
| VEX | `openvex` | `https://openvex.dev/ns` |
| Promotion record | `urn:near-ai-vscode:supply-record:1` | `urn:near-ai-vscode:supply-record:1` |

Attach, one line each. With a file key (CI, fixtures, the lab before the owner signs):
- SBOM: `cosign attest --key <key> --signing-config <empty> --type cyclonedx --predicate <sbom.cdx.json> -y <ref@digest>`
- Scan: `cosign attest --key <key> --signing-config <empty> --type vuln --predicate <vuln.json> -y <ref@digest>`, where `vuln.json` is cosign's vuln schema with the Grype JSON in `scanner.result`, `scanner.db.version` the database schema, `scanner.db.uri` the signed database reference, and `metadata.scanFinishedOn` the database `built` time (48.2 D-15), never the scan clock
- VEX: `cosign attest --key <key> --signing-config <empty> --type openvex --predicate <vex.json> -y <ref@digest>`
- Record: `cosign attest --key <key> --signing-config <empty> --type urn:near-ai-vscode:supply-record:1 --predicate <record.json> -y <ref@digest>`

With your organization's site key in the HSM (every approval, D-09): stock cosign cannot open a `pkcs11:` key, so for each of the four types our code builds the in-toto statement (subject name and digest, the predicateType above, the predicate as written) and the DSSE PAE, signs SHA-256(PAE) through `pkcs11-tool --sign --mechanism ECDSA` on the PKCS#11 URI (48.1-17's `pkcs11-sign.mjs` operation; `--signature-format openssl` returns DER directly, otherwise r||s is converted), wraps it as a Sigstore bundle v0.3 with `verificationMaterial.publicKey.hint` = base64(SHA-256(DER SPKI)), and pushes it as a referrer manifest of exactly cosign's shape (empty config with `artifactType`, one bundle layer titled `sha256-<hex>.sigstore.json`, annotations `dev.sigstore.bundle.content: dsse-envelope` and `dev.sigstore.bundle.predicateType`, `subject`). `cosign attach attestation` is not used: it writes the deprecated `.att` tag, which the default verify skips once any referrer exists. The push needs the registry's blob and manifest API (Node `fetch` against Harbor with the signer robot's credentials) or hauler/ORAS; spike S-B (48.3-03) settles whether hauler can carry these referrers.

Verify, one line each, with the public key the caller trusts (the site key's for approvals):
- `cosign verify-attestation --key <public key> --type cyclonedx --insecure-ignore-tlog <ref@digest>`
- `cosign verify-attestation --key <public key> --type vuln --insecure-ignore-tlog <ref@digest>`
- `cosign verify-attestation --key <public key> --type openvex --insecure-ignore-tlog <ref@digest>`
- `cosign verify-attestation --key <public key> --type urn:near-ai-vscode:supply-record:1 --insecure-ignore-tlog <ref@digest>`

The exit code says only that one attestation of the type verified; the checker parses the statements printed on stdout and checks the subject digest and the record's content (state, policy hash, approvals) itself.

Copies: `cosign copy` loses referrers (Pitfall 2 confirmed) and is never used. `cosign save --dir` and `cosign load --dir` keep every referrer. Every copy is followed by verify-attestation of every type at the destination.

Research assumptions: A1 (cosign 3.1.4 accepts `--type vuln`, `--type openvex` and a custom URI type) is **confirmed**, with the correction that `vuln` needs cosign's own schema. Open question 4, Zot's half: Zot 2.1.23 with `distSpecVersion 1.1.1` stores and lists all of them as referrers, **confirmed**; Harbor's half stays for the lab run (48.3-22). The PKCS#11 part of D-17 ("signed with the site key as a cosign attestation") holds with the attach path above, not with any cosign signing command.
