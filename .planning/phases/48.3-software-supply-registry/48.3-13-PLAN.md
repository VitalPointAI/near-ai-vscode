<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registry.npmjs.org -> gather host | untrusted packuments and tarballs |
| gather host -> signing host | bytes and claims (publish time, provenance, publisher) |
| signing host -> Verdaccio (promotion) and Harbor supply/ | approved bytes and their evidence |
| approved list -> CI | the signed lock CI trusts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48.3-54 | Tampering | a compromised maintainer's new version (Shai-Hulud) | high | mitigate | 7-day age gate at resolution; script, provenance-regression and publisher gates; `MAL-` check; CI keeps `--ignore-scripts` |
| T-48.3-55 | Tampering | a tarball altered after npm signed it | high | mitigate | integrity and npm registry signature checked on the signing host with pinned keys |
| T-48.3-56 | Spoofing | a typosquat or dependency-confusion name | medium | mitigate | name gate; no uplink in Verdaccio, so an unapproved name cannot be served |
| T-48.3-57 | Tampering | `npm publish` sending a package to its own `publishConfig.registry` | medium | mitigate | our own publish request to Verdaccio only; never `npm publish`; test "no npm publish" |
