<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registries -> log store | audit records cross into the site audit index |
| registries -> outside networks | egress that must not exist |
| signing host or import host -> cluster API (sterling-supply-status) | the supply status written from outside the cluster |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48.3-40 | Repudiation | registry actions not in the audit store | medium | mitigate | Harbor's forward and Zot's audit log both land in `audit-*`; Harbor's database copy is kept as well |
| T-48.3-41 | Spoofing | forged syslog records sent to port 5140 | medium | mitigate | the Service is ClusterIP only, so only pods inside the cluster can send; the records are tagged `audit.harbor` and the review runbook reads them as Harbor's claims, with Harbor's own database copy as the check; a forging pod inside the cluster is the accepted residual |
| T-48.3-42 | Tampering | Harbor or Verdaccio fetching from the internet (SSRF in webhooks, GHSA-2phj-cp9f-qq6w) | high | mitigate | `siteOnly` egress for both namespaces; render test with a non-empty egressAllow |
| T-48.3-43 | Tampering | a stolen status token silencing alerts | medium | mitigate | the token can only change one ConfigMap; 90-day lifetime; `SupplySyncStale` fires when no write happens for 36 hours, and a write that zeroes counts is visible in the audit log of the API server |
| T-48.3-SC | Tampering | npm installs | high | mitigate | No package is installed in this plan |
</threat_model>
