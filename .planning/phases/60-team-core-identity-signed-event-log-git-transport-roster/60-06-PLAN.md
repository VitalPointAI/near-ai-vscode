## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| code branch -> team.json reader | Anyone with push access to the code branch can edit team.json |
| team state -> audit file | Audit entries are persisted in the project directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-60-27 | Spoofing | team.json genesis anchor | high | mitigate | Strict validation plus a local trust pin that refuses a changed team or owner key; bounded by code-branch write access (honest limit documented) |
| T-60-28 | Elevation of privilege | team.json remote and ref fed to git | high | mitigate | REMOTE_NAME_PATTERN cannot start with a dash; ref pattern with no .., // or .lock; values only ever passed as separate argv entries |
| T-60-29 | Information disclosure | team.json and audit writes | high | mitigate | assertNoSecrets before every write; audit metadata limited to ids, role, type and lamport |
| T-60-30 | Tampering | concurrent team.json writes | medium | mitigate | Per-path promise chain plus temp-file-then-rename; failures rethrown with cleanup cause |
| T-60-31 | Repudiation | duplicated or missing audit entries | low | mitigate | Deterministic audit ids plus a persisted high-water mark |
| T-60-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this plan; package.json unchanged |
