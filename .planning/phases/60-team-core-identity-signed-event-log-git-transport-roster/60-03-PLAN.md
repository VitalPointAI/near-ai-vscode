<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote server -> mirror | The remote (or anyone with push access) can withhold, reorder, rewrite or flood the branch |
| user git config -> mirror | Global hooks, insteadOf and credential helpers apply to the mirror |
| git stderr -> status text | Error output can contain URLs with credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-60-10 | Tampering | gitTransport.ts fetch | high | mitigate | Ancestry check of the trusted head after every fetch plus persisted pin; rewrite refused and quarantined, state kept (D-33) |
| T-60-11 | Repudiation | gitTransport.ts read | medium | mitigate | Only first-parent added files become entries; modified, deleted, merged or unexpected files become anomaly rows; content read from the adding commit |
| T-60-12 | Information disclosure | status reasons, diagnostics | high | mitigate | redactGitMessage on every reason; URL never stored or logged; canary userinfo test |
| T-60-13 | Tampering | lost-race retry | high | mitigate | Builder re-invoked per attempt so Lamport, prev and sig are fresh; landed pushes recognised by ancestry (no duplicates) |
| T-60-14 | Denial of service | append retries | medium | mitigate | Bounded retries with jittered backoff; busy result instead of a throw; per-mirror mutex |
