<objective>
Write the schema layer of the validation pipeline (D-09 step 1): an exact envelope validator, exact-key body validators for the ten Phase 60 event types with the D-31 shapes, the policy field validators, and `parseEventFile`, which turns one committed file into an event or a rejection with a fixed reason.

Purpose: the bodies are signed into the log forever (D-31 one-way), so their schemas must be exact and pinned by tests before the materializer (60-05) depends on them. Unknown versions and types must be rejected in a way that tells the user to update rather than looking like corruption (D-07).

Output: validate.ts, policy validators in policy.ts, and teamValidate.test.ts.
</objective>
