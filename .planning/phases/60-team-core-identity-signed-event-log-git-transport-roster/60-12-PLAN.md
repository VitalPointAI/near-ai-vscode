Close UAT gap G-60-1: the Team status bar did not reliably move to "Team sync paused: remote unreachable" and back, because polling stopped. The status text was correct (60-UAT.md root cause, .planning/debug/team-status-paused-recovery.md). Fix the three defects behind it and keep the D-19/D-25 cadence exactly as designed:

1. `SyncScheduler.focusChanged` acts on every call. A call with unchanged focus clears and re-arms the pending timer from now. A stream of such calls starves polling (fake clock: 1 run in 1 hour). A repeated `focusChanged(true)` starts one unthrottled sync per call.
2. `createVscodeTeamSession` forwards every `onDidChangeWindowState` event. VS Code also fires that event when only `active` changes.
3. The scheduler caches focus and only events write it. The listener is registered after the awaited first sync, so a focus change during that sync (up to 60 s on a stalled remote) is lost and never corrected.

Purpose: the phase scope promises that "an unreachable remote shows a visible Team sync paused state instead of failing silently" (ROADMAP Phase 60, TEAM-04). That only holds if polls actually run on the D-19 cadence: pollSeconds when focused, 120 s when unfocused, an immediate fetch on a real focus gain. Backoff must also follow D-25: doubling per failure to 10 minutes, with a retry on focus.

Output: a corrected `src/team/syncScheduler.ts` and `src/services/team/teamSession.ts`, `fireWindowState(focused, active)` in the vscode stub, and regression tests at scheduler level and session level, including a one-hour fake-clock starvation case.
