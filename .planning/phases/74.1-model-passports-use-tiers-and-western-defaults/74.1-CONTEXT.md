- **D-13 (the use of a request):** a session route gains `useOf(): UseInput` (session facts: the gate context from `GateRuntime.context`, tools, writes, checking job, lane, project kind and exercise attribute, inherited tier, feature) and keeps a high-water use that only rises; a sub-agent's route starts at its parent's. `routeFactsFor` reads it through `currentSessionRoute()` and sets `RouteFacts.use` with `useTierFor(input, policy.models)`, so `nearAiClient.ts` (frozen at 1860 lines) is not grown. `RoutePolicy.project` carries the session's project id, so a `t1-risk` authorization scoped to a project can cover it (lifts 41 D-54 for this purpose). - **D-14 (alternatives, never retry):** on a `route.passport` refusal the reason lists up to five catalogue models for which `decideRoute` with the same mark, use, floor and policy allows (the same matcher, `resolvePassport`); none when none would. ### Lifecycle and evaluation

- **D-15 (passport state and triggers):** pure `passportState(resolved, observed, now)` gives `approved`, `expired` (date or trigger), `revoked` or `unknown` (design 12.1). A fired trigger is kept once per passport hash in the extension's global storage and recorded once as the route event `route.passport-triggered`; a new signed passport (new hash) clears it. Revoked means a `legal.removalOrders` entry exactly `all uses`: not usable at any tier, research included.

The one exception is chat you review (T1) allowed by a `t1-risk` authorization, whose own `evidence.assessment` reference is the evaluation for that exception. ### Report mode and Stop agent work now (owner-confirmed direction; mechanism recommended by Claude)

- **D-28 (the switch):** report mode stays the default (D-18a) with the notice of D-22. A security officer stops agent work outside policy with **Stop agent work now**: a control in the workbench (74.1-19) that, after a fresh step-up, signs a `model-switch/1` record with their person key: `{ format, seq, mode: 'enforce' | 'report', scope?: { models: [passport ids] }, by: { did, credential: <RoleCredential hash> }, reason, at, prev }`, canonical JSON. The officer must hold a verified, unexpired, unrevoked `RoleCredential { role: 'security-officer' }` covering your organization (checked with Phase 71's checker, 71-07). Its effect in the passport step: `enforce` sets the effective `models.mode` to enforce; `scope.models` makes each named passport revoked (D-15's removal order, every use refused, research included); `report` returns to your organization's own layer's mode, never looser than that layer. The highest `seq` that verifies wins; `prev` chains them. It takes effect without a restart: in hosted sessions within a minute through the live site record path of 47-32 (a ConfigMap mounted read-only without subPath, watched by the session), with a test that bounds the session's part of the delay and a measurement on the lab site; on desktop and edge installs at the next policy fetch or rules import (C-10). Undo is the same officer, or another holding the same credential, signing `report`. No person gets an override that loosens policy; the only way to loosen is a signed policy change.
