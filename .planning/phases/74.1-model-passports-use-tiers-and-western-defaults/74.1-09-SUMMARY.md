# Phase 74.1 Plan 09: Checking roles on another family, and both families in the record Summary

Every reviewer, plan checker, verifier, editor, red team, release guard and tradecraft reviewer in a team or staff run now runs on a model family none of the run's writers used, allowed by the gate for a checking job; under enforce, with none available, it is not started and the lead and the person read why. A J2 team writing on Nemotron 3 Super gets its tradecraft reviewer and release guard on Command A+ or gpt-oss. Each checker's records carry `checkFamilies { author, checker }`, and a forged same-family record is refused.

## What changed (0cb60ec8, Tasks 1 and 2 in one commit: the child route line carries both the checking job and the families)
