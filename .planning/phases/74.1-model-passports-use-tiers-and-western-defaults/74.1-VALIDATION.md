# Phase 74.1: Validation Strategy

> Per-phase validation contract for 17 plans in 7 waves. Every test uses fictional organizations, people and projects (Example Organization, Exercise NORTHERN EXAMPLE), fake catalogues and fake endpoints; no real model and no network.

`nyquist_compliant` stays false: every code task has an automated check written first, but four plans open with a UI gate decision (07, 11, 12, 13), 74.1-01 Task 1 starts with a licence re-check at the publishers (read only), 74.1-14 Task 2 may be skipped by its Phase 33 precondition, and 74.1-17's full run takes longer than the per-task target. Each test file is created by its own task (tests first) rather than in a separate wave 0.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | `node:test` through `scripts/run-tests.mjs` (root); the compliance package's tests through `cd compliance && node ../scripts/run-tests.mjs test/<file>.test.ts`; `scripts/test/*.test.mjs` through `scripts/run-tests.mjs` |
| **Quick run (root)** | `flock "$HEAVY_LOCK" systemd-run --user --scope -q -p MemoryMax=4G -p MemorySwapMax=0 choom -n 1000 -- timeout 300 env NODE_OPTIONS=--max-old-space-size=1536 sh -c 'npm run compile && node scripts/run-tests.mjs dist/test/<file>.test.js dist/test/architecture.test.js'` |
| **Full suites** | 74.1-17 only, once: root lint, compile and all tests (6G, 1800 s), the compliance package, docs-site, `node scripts/resource-check.mjs`, `node scripts/build-road-to-production.mjs --check` |
| **Estimated runtime** | root file under 60 s; compliance file under 60 s |

Never bare `node --test` and never an uncapped `npm test`.

## Sampling Rate

- **After every task commit:** the task's own `<automated>` command (always with `architecture.test.js` when `src/` changed, so frozen files never grow).
- **After every wave:** every new test file of the wave, `gatePassportEnforce.test.js`, `gateDecideRoute.test.js`, `gateRouting.test.js`, `gateRecordIds.test.js`, `copyLint.test.js`, `architecture.test.js`.
- **Blocking in every wave that touches them (authorization, data flow, provenance):** the enforce-mode refusal before any fetch; the use high-water; the t1-risk scope and expiry checks; the non-commercial licence rule; the different-family rule; the research workspace's no-project, no-tool rules; record field checks.
- **Before `/gsd-verify-work`:** 74.1-17's full suites green once.
- **Browser checks:** none blocking. The owner's check of the built extension (74.1-17 Task 2) is the one manual check.
