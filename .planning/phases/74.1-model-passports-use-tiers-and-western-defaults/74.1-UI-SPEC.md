### Checkboxes (owner, 2026-11-25)

Owner, verbatim: "make sure the checkboxes line up/are centered vertically with the text next to them on the right".

Every checkbox row in this phase follows one rule. That covers S11's Projects it covers, Labels it covers and Conditions; S13's "Stop these models entirely" list (in Stop agent work now and in Change models stopped entirely); and any checkbox a later edit adds to these surfaces:
- the box sits to the left of its label text;
- it is centred vertically on the label's first line;
- an 8px gap separates the box from the text;
- the whole row (box plus text) is one `label` wrapping its `input`, so a click anywhere on the row toggles the box;
- each row is at least 24px high, which also meets the 24px minimum target;
- the box is 16px by 16px.

Extension webviews (`media/policy/policy.css`, and any other new page with a checkbox). This is the rule as built and render-tested in 74.1-11; it is the one to copy:

```css
label:has(> input[type=checkbox]) { display: flex; align-items: flex-start; gap: 8px; min-height: 24px; padding-block: max(0px, calc((24px - 1lh) / 2)); }
input[type=checkbox] { flex: none; width: 16px; height: 16px; margin: 0; }
/* line-height inherit: a form control's own line height is `normal`, so its 1lh would not be the label's. */
label:has(> input[type=checkbox]) > input[type=checkbox] { line-height: inherit; margin-top: calc((1lh - 16px) / 2); }
```

Theia workbench (`workbench/extension/src/browser/model-switch.css`), with the same rule scoped to the widget and its dialogs:

```css
:is(.sterling-model-switch, .sterling-model-switch-dialog) label:has(> input[type=checkbox]) { display: flex; align-items: flex-start; gap: 8px; min-height: 24px; padding-block: max(0px, calc((24px - 1lh) / 2)); }
:is(.sterling-model-switch, .sterling-model-switch-dialog) input[type=checkbox] { flex: none; width: 16px; height: 16px; margin: 0; }
:is(.sterling-model-switch, .sterling-model-switch-dialog) label:has(> input[type=checkbox]) > input[type=checkbox] { line-height: inherit; margin-top: calc((1lh - 16px) / 2); }
```

**Corrected 2026-11-25 (74.1-11, recorded by 74.1-16).** The rule this section first gave (`align-items: center` on the label, `align-self: flex-start` on the box) failed its own render test by 3.75px: a one-line label's text was centred in the 24px row while the box was pinned to the first line's top, and the box's `1lh` read the input's own `normal` line height instead of the label's. The rule above starts box and text at the top of the row, pads a one-line row to 24px, and gives the box `line-height: inherit`, so the box sits on the first line's centre whether the label is one line or wraps. The render test is `workbench/test/e2e/sovai-checkboxes.spec.ts` (Chromium, light and dark themes).

Rows in a `fieldset` stack with a 4px gap. The box keeps the platform's own checkbox drawing and focus ring (2px `focusBorder` outline, 2px offset). See "Acceptance items for the UI plans" for how the alignment is checked.

## Typography

Exactly 3 sizes and 2 weights across every new or changed element in both hosts.

| Role | Size | Weight | Line height | Used for |
|---|---|---|---|---|
| Body | 13px (`var(--vscode-font-size, 13px)` in webviews, so a person's font size setting still holds) | 400 | 1.5 | All running text, picker rows, notices, card bodies, form fields, buttons, badges, reason lines, messages |

Every text container has `overflow-wrap: anywhere`; nothing truncates except native `select` option text, whose full words are also in the option's `title` and in the facts line (S4). Copy tolerates 30% longer text (a later French pass) without layout change.

## Interaction contracts

### Research workspace (74.1-07)

- Opening the command opens or reveals the one research workspace panel (one per window). The panel's folder is in the extension's global storage, never in a project; the module imports no `vscode.workspace` file API (74.1-07 acceptance).
- Every message goes through a session route with use `{ lane: 'research' }`; requests carry no tools and no project text. The model list shows every catalogue model, including research-only ones.
- **Adding a file** ("Add a file" or a drop): a file inside an open project folder is refused with `laneNotice` and `projectFileRefused`, even when dropped (Q2). Any other file is copied into the workspace's folder first, then attached, and `copiedIn` says so. A path inside the workspace's own folder attaches directly. Symlinks and `..` are resolved before the check (74.1-07 `laneAttachmentAllowed`).
- **Anything else that would reach a project or a tool** (a `/` command, an `@` file reference, a paste of a project path as an attachment) gets `laneNotice` and does nothing else. The composer offers no `/` command list here.
- **Copy** on an answer or a code block puts `copyHeader` as the first line, then a blank line, then the text; the header is added once even when the copied text already starts with it. The status line says `copied`.
- "New research chat" starts a fresh conversation; the previous one stays in the folder and the panel shows the newest on reopen. There is no history browser in this phase.
- Restricted Mode: identical (see "Restricted Mode").

### Cyber panel and Compare Models (74.1-10)

- The cyber banner is the same component and first line as S1; the panel reads its words from `RESEARCH_TEXT`.
- With no engagement model and no abliterated model offered, the handoff never falls back to a fixed model: the model select shows `cyberChooseModel` and Run stays disabled with that sentence visible.
- Targets (Q3): a Workspace folder or Git repository folder target inside an open project is refused at Resolve scope with `cyberProjectTarget`; a folder outside every open project, a URL, a range or a container resolves as today.
- Compare Models: the disabled jobs and the reason line come from the host's role options (`modelRoles.ts` approval field); the page only renders them. A crafted `apply-role` for a job the model is not approved for is refused by the host with `applyRefused` in the page's status line, and no setting is written.

### Picker, directory and Insert (74.1-12)

- One helper builds a row's words from the catalogue entry, the resolved passport, `passportState` and the session's use; the picker and the directory both call it.
- Choosing a disabled option is impossible with a native select (it is skipped by the keyboard and not selectable). A saved choice that is now forbidden is not restored: the select falls back to the job's resolved default, and the status line says `pickerSavedForbidden`.
- Insert at cursor: the page reads the trust facts it already receives with each answer (no new host message); the host also refuses an `insert-code` message for an answer whose model is not approved for agent work under enforce, with `applyBlocked` in the status line.

### Empty-state card and report-only notice (74.1-13)

- The card replaces the reply only for a `route.passport` refusal with no alternatives; with alternatives the 74.1-04 sentence stays.
- Ways forward appear only when their condition holds: "Add an AI service" when the guide's AI services option exists on this build (it opens that option; the guide ends on a policy editor proposal); "Use {model} for this chat" when the label's routing is any cloud and a closed-model approval covers the use, naming the first such model; "What NEAR AI has been asked" always; "Open Research Workspace" always.
- "Use {model} for this chat" sets the model for this chat only, with one press (Q7), records that the person chose it, removes the card's buttons, shows `afterUse`, and puts the refused message back in the composer if the composer is empty. Nothing is sent by itself.
- The notice is raised by the first would-refuse of `route.passport` in the session and cleared only when the effective mode turns to enforce. It has no dismiss control; a crafted dismiss message from the page is refused by the host. A new chat tab in the same session shows it at once.
- "Adopt the Western defaults" (personal layer only) opens the policy editor on a proposal adding `{ models: { v: 1, mode: 'enforce', unknownMaxTier: 'T0' } }` with the proposal reason `adoptReason` and the effect sentence (`adoptEffectNear` when it is true, else `adoptEffect`); the existing "Apply to my rules" applies it. Nothing writes the policy from the notice. Under your organization's layer the notice offers no Adopt and its detail ends with who to ask.

### Exception request (74.1-11)

- Shown only under your organization's layer. On a computer with no organization layer the section offers no draft, and a crafted page message asking for one is refused by the host.
- One draft at a time. The page only renders and posts; `riskAcceptance.ts` validates every field, and the host checks every message field by field and requires it to name the shown draft.
- Use is fixed: chat you review. Ends on cannot be after today plus 90 days or before tomorrow.
- "Review the request" validates; errors go under their fields with focus to the first. "Sign and save the request" signs the body with this computer's key as the named person's inner signature (C-8, G414), then opens a save dialog through the existing "Save a file for your organization" path. Nothing changes locally and no policy edit is recorded.
- "Renew exception" opens a draft with the same model, projects, labels and conditions, a new Ends on (today plus 30 days) and an empty Mission benefit, which must be written again.
- Self-signed exceptions cover nothing (owner, 2026-11-24): no surface shows "(self-signed on this computer)" for an exception.

### AI bill of materials (74.1-15)

- Palette `when`: a workspace folder is open. With several folders, a quick pick `bomPickTitle` lists them by name.
- Runs with window progress `bomProgress`; writes `.near-ai/state/ai-bom.cdx.json` atomically after checking that the resolved folder stays inside the project (else `bomOutside`); a second run replaces it with the same bytes for the same log.
- The success message offers "Open File". Unreadable records are skipped and counted in the message.

### Stop agent work now and Return to report only (74.1-19)

- Only a session whose credential state holds a verified, unexpired, unrevoked security-officer credential sees the status bar entry, the palette command and the page's controls (Q4). Every decision is the backend's; a crafted call from anyone else is refused as plain data.
- Step-up comes first: pressing the state's button opens "Confirm it is you" when the step-up is not fresh; the confirm button goes through `stepUpUrl()` and returns to the page, which reopens the same dialog. When the step-up is fresh the action dialog opens directly.
- The reason is required. It is kept in `sessionStorage` under one key only while the dialog is open, so a step-up reload does not lose it (WCAG 3.3.7), and is removed when the switch is sent or the dialog is closed. The reason is not secret: it is published with the switch.
- The "You sign" preview always shows exactly what will be signed (WCAG 3.3.4).
- Enter never signs unless the primary button has focus; Theia's `AbstractDialog` accept-on-Enter is overridden (74.3 P8).
- On a network failure the signed record is kept in memory only while the page is open, and "Send switch again" re-posts it. If a resend answers stale-seq and the server's current record is the one just sent, the page shows the published result; otherwise it shows `errStale` and the new state.
- After a published switch the dialog closes, focus returns to the status card's heading, and the message line announces the result.

## Security rules for the UI (checked in tests)

1. No prompt, answer, attachment content, key, signature or credential body in any notification, status bar text, log line, page message, saved request or AI bill of materials (74.1 execution notes).
2. The research workspace module imports no `vscode.workspace` file API, and the host refuses any page message naming a path outside the workspace's folder (74.1-07).
3. Every page message is checked field by field by the host; pages only render and post. A crafted dismiss for the notice, a draft request on a computer with no organization layer, an `apply-role` for a job not approved, or a switch call from a session without the role is refused.
4. No surface offers a model the gate would refuse: the card's options and Compare Models' jobs come from `decideRoute` through the host.
5. The AI bill of materials is written only inside the project (realpath check) and never includes prompt or answer text.
6. Nothing a person signs on one computer alone allows a model; no screen shows a self-signed exception.
