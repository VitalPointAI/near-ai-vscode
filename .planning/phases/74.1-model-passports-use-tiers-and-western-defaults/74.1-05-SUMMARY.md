# Phase 74.1 Plan 05: Defaults in one place (Task 1) Summary

The model defaults are now Western passports by job in `AGENT_DEFAULTS.models`, and `resolveJobModel` picks a person's own value, then your organization's default, then the shipped preference: the first catalogue model the gate allows for the job. Today's ids live only in `AGENT_DEFAULTS.reportFallback`, used in report mode while no preferred model is in the catalogue and never under enforce.

## Task 2: stopped before starting

Task 2 makes `readModelTiers`, `readSafetyModel` and `readAgentModels` return "" when unset, with no fallback, and moves every package default to "". The only place that then gets a concrete model is the run start, which 74.1-08 rewires. Every other consumer would get an empty model:
- `src/extension.ts` lines 183 and 196 (the default chat model);
- `src/services/teamStudioPanel.ts` (the tiers at 83 and 102, and the image model);
- `src/services/toolsPage.ts` and `src/services/modelComparisonPanel.ts` (the settings they show and use);
- `src/services/chat.ts` lines 900, 1161 and 1179 (the vision and transcription models that read chat attachments), and the backup candidates at 972 and 981.

The decision needed is one of these:
- (a) Give the readers a fallback to `AGENT_DEFAULTS.reportFallback`, which keeps today's behaviour but changes the acceptance check that says "" when unset.
- (b) Send each of those consumers through `jobModelsFor` as part of 05 Task 2, which goes beyond the plan's file list and touches frozen `chat.ts` in place.
- (c) Accept the gap until 74.1-08, with these consumers broken in the meantime. This is not recommended.

Task 1 left the readers as they were: they still fall back to today's ids, now read from `reportFallback`.
