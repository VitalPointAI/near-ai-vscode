# Phase 74.1 Plan 05: Defaults in one place Summary

The model defaults are now Western passports by job in `AGENT_DEFAULTS.models`, and `resolveJobModel` picks a person's own value, then your organization's default, then the shipped preference: the first catalogue model the gate allows for the job. Today's ids live only in `AGENT_DEFAULTS.reportFallback`, used in report mode while no preferred model is in the catalogue and never under enforce.

## Task 2

Every model setting in package.json now defaults to empty, and its description says empty means your organization's default for the job, else the shipped one (placed before the project-choice sentence those descriptions must end with). `readJobSettings` gives a person's own value per job, or empty; `jobModelsFor` (`src/services/jobModels.ts`) resolves every run job through `resolveJobModel` and writes no setting. `DEFAULT_MODEL` is derived from `AGENT_DEFAULTS.reportFallback.standard`; `settings.ts` and `config.ts` hold no model id literal, and a scan test keeps every file under `src/` but `agentDefaults.ts` and `shippedPassports.ts` free of them (`cyberHandoff.ts` excepted until 74.1-10 removes its fallback).

## Deviations from Plan

- **Task 2, the readers (coordinator's decision, option a, 2026-11-25):** the plan's check says `readModelTiers`, `readSafetyModel` and `readAgentModels` return "" when unset. That would leave every caller except the run start (rewired by 74.1-08) without a model: the default chat model, Team Studio, the Tools page, Compare Models and chat attachments. The readers instead fall back to `AGENT_DEFAULTS.reportFallback` when unset; the amended check proves an unset setting reads as the report-fallback id, never "", and a person's value is read exactly. The person's own values without a fallback come from the new `readJobSettings`, which `jobModelsFor` uses. 74.1-08 still rewires the run start.

- `agentDefaults.test.ts` and `live.test.ts` read `AGENT_DEFAULTS.reportFallback` where they read `AGENT_DEFAULTS.tiers`, because `tiers` is replaced (the package defaults are unchanged in Task 1).
