# Phase 74.1 Plan 03: The use of every request Summary

Agent runs, sub-agents, unattended and relay runs, staff projects, Team Studio AI and chat attachments now reach the gate as what they are; a risk acceptance scoped to one project covers that project only.

## What changed

- `sessionRouteFrom` builds `useOf` from the runtime's context, the runtime's project facts and the caller's own facts (an object or a function), and takes an optional `parent` whose use the child starts at.
- `GateHost.runtimeFor` gives each runtime in a folder `project { id, kind? }` (`projectFactsOf`), and its route policy names that project (lifting 41 D-54 for this purpose).
- `agentSession.ts`: the run route passes `use: { tools: true }`; the sub-agent route passes `use: { tools: true, context: 'sub-agent' }` and its parent. Both changed on their existing lines; the file keeps 2,708 lines.
- `chat.ts` `attachmentRoute` (exported, changed in place; 1,517 lines kept), `chatParticipant.ts` `participantRoute`, `teamStudioPanel.ts` `teamStudioRoute` (`writesFiles`).

## Deviations from Plan

- **Project kind and exercise:** the plan reads the project kind and exercise attribute from Phase 41's project layer, which has no on-disk source on `main` (Phase 32.1 adds it). The host reads the kind from the project file instead; the exercise attribute stays unset until that source exists. Hand-off: when 32.1 lands, `projectFactsOf` reads `exercise` from the verified project layer.
- **Attachments:** the plan says attachments keep the chat's use; the chat panel's use is agent work (every send is an agent run with tools), so the attachment route says `inherited: 'T2'`.
- My 74.1-02 test of `useOf` now expects the runtime's context in it (the behaviour this plan adds).
