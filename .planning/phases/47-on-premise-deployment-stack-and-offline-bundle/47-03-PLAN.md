<objective>
Pin every third-party image the vendored charts render, list our own rebuilt and released images, and give every vendored chart a release descriptor and a values file holding only the settings that decide which images render (D-12, D-20, D-52). Theia Cloud is the tracer: three charts whose images are all ours, injected with the reserved unpublished digest until the deploy-images job publishes them.

Purpose: the gate PR (47-04) writes one register entry per `images[]` name; those names and the set of images must be final now, so later plans never add a discovered resource (which would be a gate change). Later plans extend these values files but must keep the image-determining settings recorded here.

Output: a complete `deploy/bundle/images.lock.json`; 13 release descriptors and values files; site globals extended with `storageProvider`.

Part of the gate PR with 47-01, 47-02 and 47-04; this plan touches no gate file.

Context budget: kept as one plan of 3 tasks because its 30 files are small and alike (a descriptor and a values file per chart, each a few lines, and one lock file); the cost is in resolving digests with a scratch script, not in the files. Stop and commit after each task once the render test passes: after Task 1 (Theia Cloud releases, `built` and `release` sections), and after Task 2 (platform charts); a fresh context can then resume at Task 3 from the committed lock.
</objective>
