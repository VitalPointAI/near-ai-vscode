Per D-77. Edit only these entries. Each gets `reviewer` `Claude (agent review; owner to confirm)` and `reviewedAt` the execution date. `where` does not change: the checker derives it.

- `tool:grype`:
  - `component` `offline-bundle` and `scope` `runtime`, because it now runs on a site's import host, as cosign does.
  - `purpose` adds that the bundle build scans every image's SBOM, and that sites rescan offline from the bundle's SBOMs (47-29), besides the CI scans.
  - `controls` add `ra-05.02` and `cm-04`.
  - `airGap` becomes `needs-mirror:the vulnerability database, downloaded on the connected build host and shipped in the signed bundle or a signed database file`.
  - `fit` becomes `pass-with-conditions`. The conditions:
    - The database is fetched only on the connected build host, from Anchore's listing at grype.anchore.io, with the listing's checksum verified, and reaches sites only inside the signed bundle or as a file signed with your organization's key.
    - At sites grype runs with database auto-update, age validation and application update checks off, against a private cache, and reports the database's build date.
    - Scans are report-only; the site change board decides.
    - Go cryptography in grype is not FIPS-validated and protects nothing here.
- `tool:syft`: `purpose` adds the CycloneDX SBOMs of every image in each offline bundle, made on the connected build host (47-29). It stays `build` and `pass`.
- `tool:rke2`: `controls` add `au-08`, `au-08.01`, `sc-45` and `cp-09`. Two new conditions:
  - Every node and the import host run chrony from the site's own OS repository, configured only with the site's on-site authoritative time source (a GNSS-disciplined NTP appliance or a stratum-1 server). The node install refuses a clock that is unsynchronised, on its local clock, or beyond `time.maxClockErrorMs` (D-71, 47-22).
  - The server token, which any etcd restore needs, and the secrets-encryption configuration are escrowed on custody media held by two key custodians apart from the backups; `escrow-node.sh check` finds a stale escrow after a rotation (D-73, 47-25).
- `chart:longhorn`: `controls` add `cp-09`; a condition: the `longhorn-crypto` key, which any backup restore needs once the cluster is gone, is escrowed with the RKE2 keys and checked (47-25).
- `chart:opensearch`: `controls` add `cp-09` and `cp-10`; a condition: `audit-*` and `logs-*` are snapshotted on a schedule to a filesystem repository on an encrypted volume, without the security index, with a tested restore (47-24). Multi-node sites need the snapshot volume as ReadWriteMany on the encrypted class, confirmed on Phase 48's lab-full rig.
- `tool:softhsm2`: a condition (owner decision a, D-80): it holds the development site signing key and the lab seal through the same PKCS#11 path the production HSM uses; the production preflight refuses it (47-16). Scope stays `test`.
- `chart:openbao`: `controls` add `cp-09`; a condition: Raft snapshots on a schedule by a job whose token reads only `sys/storage/raft/snapshot`, onto an encrypted volume; a snapshot restores only with the HSM or the Shamir shares (47-24).

`compliance/ci/TOOLS.md`: under Grype 0.122.1, add "The vulnerability database for the bundle and sites". It covers:
- how the bundle build fetches it: `grype db list -o json` for the archive address and checksum, the download verified against that checksum, then `grype db import` into a private cache;
- how a site rescans: `GRYPE_DB_AUTO_UPDATE=false`, `GRYPE_DB_VALIDATE_AGE=false` (the report shows the database age instead), `GRYPE_CHECK_FOR_APP_UPDATE=false` and `GRYPE_DB_CACHE_DIR` set to a private folder;
- that `grype.anchore.io` is reached only from the connected build host.
