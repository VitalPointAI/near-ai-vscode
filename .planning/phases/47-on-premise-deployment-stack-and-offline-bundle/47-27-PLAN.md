Recovery groups, in this order (D-73):

| Order | Group id | What | Backups it relies on |
|---|---|---|---|
| stage 0 | `platform` | nodes; RKE2, by etcd restore with the escrowed token or by a fresh install; the registry rebuilt from the last verified bundle | `etcd` |
| 1 | `secrets` | the HSM and OpenBao | `openbao-raft` |
| 2 | `identity` | Keycloak and its Postgres | `postgres-dump`, `longhorn` |
| 3 | `registry` | the registry's own service; admission back to Deny | none (rebuilt from the bundle) |
| gate | `audit-pipeline` | OpenSearch and Fluent Bit running before people return | none |
| 4 | `sessions` | Theia Cloud sessions and workspace volumes | `longhorn` |
| 5 | `hubs` | the sync hubs | `longhorn` |
| 6 | `audit` | historical audit data from snapshots | `opensearch-snapshot` |

Schedule sources:
- `etcd`: `etcd-snapshot-schedule-cron` in `deploy/rke2/config.yaml`;
- `openbao-raft`: CronJob `openbao-raft-snapshot` in the rendered openbao release (47-24);
- `postgres-dump`: CronJob `sterling-postgres-dump` in the rendered sterling-postgres release;
- `longhorn`: RecurringJob `sterling-daily-backup` in the rendered sterling-storage release;
- `opensearch-snapshot`: the creation cron in ConfigMap `opensearch-snapshot-policy` of the rendered opensearch release (47-24).

Record format `sterling-restore-test/1`, top level:
- `format`, `site`, `bundleVersion`, `scenario` (`verify`, `lab-full-site` or `component`);
- `startedAt`, `finishedAt` (ISO UTC);
- `operator`, and optionally `witness`;
- `steps`, `findings` (list of text), `correctiveActions` (list of text).

Each step:
- `group` (a group id), `component`, `kind` (`verify`, `restore` or `manual`);
- `backupTakenAt`, `startedAt`, `finishedAt`;
- `result` (`pass`, `fail` or `not-run`), and `check` (what was compared);
- `achievedRpoMinutes`: `startedAt` minus `backupTakenAt`, or null;
- `achievedRtoMinutes`: `finishedAt` minus `startedAt`;
- `rpoTargetMinutes`: the site's `recovery.rpoMinutes`;
- `met`: whether the step met the RPO.

At the top level of the record: `rtoTargetMinutes` (the site's `recovery.rtoMinutes`), `achievedRtoMinutes` (from the first restore step's start to the last step's end, for scenario `lab-full-site` only; null for component drills) and `rtoMet`.
- `notes`.

Scratch work happens only in the release's own namespace, labelled `sterling-drill=scratch`, from images in the site registry by digest. Admission (Kyverno), Pod Security restricted and the egress policies all apply to it, so the drill never needs an exception.
