- `deploy/bundle/lib/cosign.mjs`: small wrappers that spawn the cosign binary (path from `COSIGN` or PATH) with the exact S1 flags: `signBlob(file, key)`, `verifyBlob(file, sigFile, publicKey)`, `signImage(ref, key)`, `verifyImage(ref, publicKey)`; offline flags only (no transparency log, no keyless). The key password comes from `COSIGN_PASSWORD` in the environment, never an argument.
- `deploy/bundle/signed-file.mjs`: CLI `sign <file> --key <key>` and `verify <file> --public-key <pub>`; exports `signFile` and `verifySignedFile(file, publicKey, { cosign })` returning `{ ok, reason }`. This is the one check for every signed file (D-49).
- `deploy/bundle/lib/manifest.mjs`: `writeManifest`, `readManifest` (`JSON.parse` only), `sha256File`, and `compareItems(manifestItems, storeItems)` returning plain problem strings for a missing item, an extra item, or a digest mismatch.
- `deploy/bundle/build.mjs` (connected side): `--out <dir> --key <cosign key> --staging-registry <host:port> [--images <name,...>] [--files <path,...>]` for this task; copies each selected `images` lock entry by digest into the staging registry (a local Zot the operator runs), signs each staged digest with the key (your organization's signature is what admission trusts), adds the images with their signatures and the files to a fresh hauler store, saves `store.tar.zst`, writes `manifest.json` with every item digest and the archive SHA-256, and signs the manifest with `signFile`.
- `deploy/bundle/check.mjs` (site, offline): `--bundle <dir> --public-key <pub>`; export `checkBundle({ dir, publicKey, cosign, listStore })`: 1) `verifySignedFile` on `manifest.json`; 2) the archive SHA-256 equals the manifest; 3) load the archive into a temporary hauler store (never the registry) and `compareItems` against the store listing. Any failure returns `{ ok: false, problems }` and nothing else happens.
- `deploy/bundle/import.mjs` (site): `--bundle <dir> --public-key <pub> --registry <host:port> --out <install dir>`; runs `checkBundle` first and stops on any problem with exit 1; only then copies images and signatures into the site registry (credentials from the file named by `--registry-auth`), copies file items into `--out`, and finally runs `verifyImage` on every image digest in the site registry, failing if a signature did not arrive (Pitfall 16).
Tracer run under the lock: two local Zot containers (staging with network; target started with no network), a test key pair, build a bundle of the cert-manager controller image and one small file, check it, import it into the target from a container that shares only the target's network namespace, and `cosign verify` the imported digest. Record commands and outputs in the SUMMARY.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Removable media to import host | The bundle crosses the air gap |
| Import host to site registry | Images and signatures written to the registry |
| Signing key on the build host | Your organization's private key |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-47-18 | Tampering | bundle in transit | critical | mitigate | Manifest signed with the organization key; public key from install media, never from the bundle; archive and every item digest compared before any load |
| T-47-19 | Spoofing | a bundle signed with another key | high | mitigate | verifySignedFile with the out-of-band public key only; refusal tested |
| T-47-20 | Information disclosure | signing key password | high | mitigate | Read from COSIGN_PASSWORD in the environment, never an argument or a file in the bundle |
| T-47-21 | Tampering | signatures dropped in transit | high | mitigate | Import verifies every imported digest's signature in the site registry and fails if one is missing (Pitfall 16) |
| T-47-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed; cosign and hauler are pinned binaries |
</threat_model>
