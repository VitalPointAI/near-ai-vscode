<objective>
Time for air-gapped sites (AU-8, AU-8(1), SC-45; D-71 in `47-COMPLIANCE-CONTEXT.md`). Certificates, WebAuthn, the signed site export's refusal of future times, the 10-minute hold on future-dated replica entries, etcd and audit correlation all depend on clocks. A disconnected site has no internet time, so it needs an on-site authoritative source, and the install must prove each node follows it. Per D-70 (the owner's direction of 2026-11-24), the obligation is delivered as code and tests wherever possible.

Purpose: a node with a wrong or free-running clock never joins the cluster, and the site's time settings are code, not a manual step.

Output: `deploy/bundle/lib/clock.mjs` (settings check, chrony.conf, node clock files, the chronyc verdict, the import host check), `deploy/rke2/check-time.sh`, the time check in `install-node.sh`, the `time` site settings, fixtures captured from a real chronyd, and `deploy/test/time.test.mjs`. 47-16 (wave 7) wires the settings check and the import host check into the install preflight and writes the clock files with the other node files.

Facts to build on (D-71 discovery): `chronyc -c tracking` prints one comma-separated line whose fields are, in order, reference id (hex), reference name, stratum, reference time, system time offset in seconds (negative means the clock is fast), last offset, RMS offset, frequency, residual frequency, skew, root delay, root dispersion, update interval, leap status (`Normal`, `Insert second`, `Delete second` or `Not synchronised`). chrony's own bound on the clock error is the absolute system time offset plus the root dispersion plus half the root delay. A reference id of `7F7F0101` is chrony's local clock (the `local` directive), never an authoritative source. Nodes have no Node.js (install-node.sh header), so the node check is POSIX sh with awk; the import host check is Node. The lab VM (`deploy/lab/vm.sh`, 47-05) has no network route, so its source is the KVM PTP clock: `modprobe ptp_kvm` in the guest, then `refclock PHC /dev/ptp0 poll 2`.

Shell rules: TMPDIR in the session scratchpad; every test run under `systemd-run --user --scope -q -p MemoryMax=4G -p MemorySwapMax=0 choom -n 1000 -- timeout 300`; the lab VM under `vm.sh`'s own heavy-run lock, one heavy run at a time. Node built-ins only.

Per D-71. Site settings: add `time` to `deploy/values/site.example.yaml` with `servers: []`, `refclocks: []`, `nts: false`, `maxClockErrorMs: 1000`, plus a note:
- the site must provide an on-site authoritative source, either a GNSS-disciplined NTP appliance or a stratum-1 server on the site network, two or more recommended, never an internet pool;
- `servers` are host names or IP addresses;
- `refclocks` are chrony reference clocks attached to a node, allowed only as `PHC /dev/ptpN`, `SHM N` or `SOCK /run/...`, with an optional `poll N`; the lab uses the KVM PTP clock;
- `nts` turns on Network Time Security for every server, trusting the site CA;
- `maxClockErrorMs` is the largest clock error bound a node or the import host may have (AU-8(1), set by your organization).

In `deploy/test/fixtures/site.ci.yaml` set `servers` to `time1.site.example` and `time2.site.example`. Do not add `time` to `REQUIRED_SITE_SETTINGS` in render.mjs: "at least one of two lists" is a rule `checkTimeSettings` enforces, and 47-16's preflight reports it.

`deploy/bundle/lib/clock.mjs` (Node built-ins only), exports:
- `checkTimeSettings(site)` returns plain problem strings: both lists empty (the message names the on-site source the site must provide); a server that is not a host name or IP address; a refclock outside the allow-list; `maxClockErrorMs` not a positive integer.
- `chronyConf(site)` returns the chrony.conf text, and throws with the `checkTimeSettings` problems if there are any. The text holds:
  - a header comment saying it is generated from the site file;
  - one `server <address> iburst` line per server, with ` nts` added when `nts` is true;
  - `minsources 2` when there are two or more sources;
  - one `refclock <spec>` line per refclock;
  - `driftfile /var/lib/chrony/drift`, `makestep 1 3`, `rtcsync`, `cmdport 0`;
  - `ntstrustedcerts /etc/rancher/rke2/site-ca.crt` only when `nts` is true;
  - no `pool` line and no `allow` line (nodes are clients only).
- `writeClockFiles(site, outDir)` writes `chrony.conf` and `clock.env` (one line `MAX_CLOCK_ERROR_MS=<n>`), and copies `deploy/rke2/check-time.sh` beside them.
- `parseTracking(line)` returns `{ refId, refName, stratum, offsetSeconds, rootDelaySeconds, rootDispersionSeconds, leap }`.
- `clockProblems(tracking, { maxClockErrorMs })` refuses, with plain reasons: leap status `Not synchronised`; reference id `7F7F0101`; stratum 0 or 16 and above; and an error bound (absolute offset plus root dispersion plus half the root delay, in milliseconds) above the limit. Each reason gives the measured bound.
- `checkHostClock({ run, maxClockErrorMs })` runs `chronyc -c tracking` through the injected `run` (default spawnSync, no shell) and returns problems; a missing chronyc is a problem that says to install chrony from the site's own OS repository.

A CLI `node deploy/bundle/lib/clock.mjs --site <site file> --out <dir>` writes the node clock files, and `--check-host --site <site file>` checks this host and exits 1 on any problem.

`deploy/rke2/check-time.sh <folder>` (POSIX sh, `set -eu`, exit 2 on bad arguments):
1. Read `MAX_CLOCK_ERROR_MS` from `<folder>/clock.env`; refuse a value that is not digits.
2. Fail with the OS-repository message when `chronyc` is missing.
3. Wait with `chronyc waitsync 60 0 0 1` (up to about a minute; ignore its status).
4. Read `chronyc -c tracking` and apply the same four rules as `clockProblems` with awk, printing the reference name, stratum and bound in milliseconds.
5. Exit 1 with the reason on a refusal, 0 otherwise.

`install-node.sh`:
- add `chrony.conf`, `clock.env` and `check-time.sh` to the files that must be in the node folder;
- after the file checks and before any change to the node (the etcd user, the RPM, the RKE2 tarball), install `chrony.conf` to `/etc/chrony.conf` with mode 0644, then `systemctl enable chronyd` and `systemctl restart chronyd`, then run `sh "$DIR/check-time.sh" "$DIR"` and stop with its message when it fails;
- update the header comment to list the three files.

Lab end to end (under the VM's lock):

2. Write a node folder as 47-05 did, adding the clock files from a copy of the CI site whose `time` is `refclocks: ["PHC /dev/ptp0 poll 2"]` and `servers: []`.
3. Refusal path first, on a fresh VM: replace the folder's `chrony.conf` with one naming only `192.0.2.1` (unreachable). `install-node.sh` must stop at the time check, and `/usr/local/bin/rke2` must not exist afterwards.

5. Capture `chronyc -c tracking` from the guest in both states into the scratchpad for Task 2's fixtures, and capture one line after `chronyc local stratum 10` in a separate test config with no sources.
6. `vm.sh down`.

| Site file to node configuration | The operator's settings become /etc/chrony.conf |
