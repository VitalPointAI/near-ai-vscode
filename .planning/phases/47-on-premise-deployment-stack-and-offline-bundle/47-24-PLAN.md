- The opensearch chart (3.10.0) and the openbao chart (0.30.8) both have `extraObjects` (templated), and opensearch.yaml already uses it for `opensearch-retention-policy`.
- The openbao chart's own `snapshotAgent` is not used: it needs a separate S3 image and S3 storage.
- 47-13 enabled `auth/kubernetes` in `apply.mjs` for cert-manager. This plan adds only its role on that mount and never re-creates or reconfigures it. 48.1-14 adds `audit-archive` and 47-33 adds `offsite-manifest` the same way (48.1 hand-off H-09).
- `deploy/values/opensearch.yaml` is shared with 48.1-16, which removes delete from the `audit-*` retention and adds the `audit-archiver` role. - OpenSearch's snapshot-management API is `_plugins/_sm/policies/<name>`; a filesystem repository needs `path.repo` on every node.
- A site with more than one OpenSearch node needs a shared (ReadWriteMany) snapshot volume. Longhorn serves RWX through its share manager; whether RWX works on the encrypted class is checked on Phase 48's lab-full rig and recorded as a condition until then.

The OpenSearch API objects are applied by 47-16's apply step from the ConfigMaps (47-16 is amended for this). This plan only renders them and proves them in a container.

|----------|-------------|
| Snapshot job to OpenBao | A Kubernetes service account becomes an OpenBao token |
| Snapshot volumes to the backup target | Raft and audit snapshots leave the node through Longhorn backups |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-47-85 | Elevation of privilege | snapshot job token | high | mitigate | Policy grants only read on sys/storage/raft/snapshot; role bound to one service account and namespace; 5-minute TTL; test-enforced |
