<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| project folder -> store | anyone with the folder (git checkout, a restored image, a copy) can delete, truncate or replace files |
| other windows and processes -> store | concurrent writers on one install |
| outside the machine -> store | entries from other people arrive as untrusted bytes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-31-35 | Tampering | rolled-back or truncated store folder | high | mitigate | signed marks in SecretStorage per (stream, writer) and roster head; rolled-back and mark-unverified refusals (Task 2) |
| T-31-36 | Tampering | interleaved or lost appends from two windows | medium | mitigate | register lock plus withFileLock, two-process test (Task 3) |
| T-31-37 | Tampering | symbolic link redirecting writes outside the project | medium | mitigate | refuse a link anywhere on the path (Task 1) |
| T-31-38 | Denial of service | oversized blob, hostile foreign update | medium | mitigate | blob size refusal (Task 2); injected decode check holds a refused entry back from the fold (Task 4) |
| T-31-39 | Information disclosure | store committed to git or holding secrets | medium | mitigate | self-ignoring .gitignore (Task 1); only sealed entries, blobs and signed grants are stored (prohibition P-31-18) |
| T-31-SC | Tampering | npm installs | high | mitigate | No package is installed in this plan |
