<objective>
The memory-capped decode worker (D-05 as refined by D-43): a second line of defence behind the pure skim of 31-03, so a decoder bug or an accepted but large update can never take the extension host down.

Purpose: owner decision 3 of 2026-11-19 requires decoding of updates from outside the machine in a memory-capped worker that the replica store runs before an entry reaches the fold. The store plan (31-13) provides the hook and the project host (31-18) wires this worker into it.
Output: `decodeWorker.ts`, `decodeHost.ts`, a test helper worker, the release-content entry, a test file, and the first SECURITY.md subsection of the new multi-user section.

Branch: `feat/phase-31-10-decode-worker` (WP-R2), merged into `feat/phase-31-staff-roster` after wave 4.

File ownership in wave 4: these six files only. This plan creates the `## Multi-user staff projects (preview)` heading in SECURITY.md; later plans each add one subsection under it, one plan per wave.

Recorded planning choice: the decode check never changes the fold's input on its own. The store keeps every verified entry; when the worker refuses an entry from outside, the store holds that entry back from the fold and lists it (31-13), which is visible and local rather than silently different. The pure fold's own skim refuses hostile bytes in any case, so honest machines agree.
</objective>
