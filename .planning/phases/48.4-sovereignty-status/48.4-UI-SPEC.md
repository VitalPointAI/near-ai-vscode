# Phase 48.4 - UI Design Contract

> Visual and interaction contract for the sovereignty badge and card of Sterling Sovereign AI (SovAI): the status bar item in the Sterling workbench and in the desktop extension, the card it opens (header, four group cards, fourteen rows, the row detail with its facts, mitigations and supplier lines, the footer), the desktop card, the Compliance view's new Sovereignty filter and the links both ways, every state of D-28, the air-gapped, disconnected and Restricted Mode behaviour, and the WCAG 2.2 AA behaviour. Produced by gsd-ui-researcher on 2026-11-25 for `/gsd-ui-phase 48.4`, to be checked by gsd-ui-checker and approved by the owner (48.4-17, D-46). Plans 48.4-10, 48.4-11, 48.4-12 and 48.4-13 build to it once it says `status: approved` on main.

Sources read: 48.4-CONTEXT.md (D-01 to D-49, SVS-01 to SVS-10, owner items O1 to O6), 48.4-HANDOFFS.md (H-01 to H-22), plans 48.4-01, 05, 11, 12, 13 and 17 in full, `.planning/research/sovereignty-status/RESEARCH.md` (sections 3 to 8 in full), the approved house references `74.3-UI-SPEC.md` and `48.2-UI-SPEC.md` (on main) and `74.1-UI-SPEC.md` (`origin/docs/phase-74.1-ui-spec`, 20b7b1a8), the 48.2 sketch, and the code on main at 46358ef9: `src/services/gateStatusBar.ts` (`nearAi.gate`, left, priority 49), `src/services/team/teamStatusBar.ts` (`nearAi.team`, left, 50), `workbench/extension/src/browser/session-identity-frontend-module.ts` (Theia status bar entry pattern, left, 100), `sterling-compliance-module.ts` and `sterling-compliance.css` (the state colours, the `sterling.compliance.open` command), `sterling-documentation-module.ts` and `workbench/tools/build-sterling-documentation.mjs` (the bundled documentation pages), `docs-site/docusaurus.config.js`. Codicon names were checked against `@vscode/codicons` 0.0.45 `dist/codicon.css`, the version `workbench/package-lock.json` resolves.

Sketch for the owner's review (not shipped, not committed): a self-contained HTML file in the coordinator's scratchpad (`48.4-sovereignty-sketch.html`), with a light and dark switch, no external request and fictional site data. It shows both status bars in every badge state, the workbench card at a site with three rows open (Where AI runs, Which laws apply to outside services with the supplier's jurisdiction line, Who can switch it off with the supplier's control line and its mitigations), the Compliance view with the Sovereignty filter and the way back, and the states (air-gapped site, no site declaration, declaration did not verify, live updates paused, a Not verified row, loading, the desktop card). Icons are inline SVG stand-ins for the codicons named here.

The Sterling design language (`.planning/design/STERLING-DESIGN-LANGUAGE.md`) is not used (owner, 2026-11-24). This phase uses the original rounded-card theme with lifted cards, as 74.3, 48.2 and 74.1 do: plain theme surfaces, 12px cards with a soft two-layer shadow, 8px notices, state words with a 3px bar. No gradients, no hero banner, no large rounded pills, no emoji, no illustration, no coloured header band.

## Spacing Scale

Every margin, padding and gap in the new surfaces is one of 4, 8, 16, 24, 32 or 48 px. There is no 12px step.

| Token | Value | Usage |
|---|---|---|
| xs | 4px | Icon to text gap; gap between facts on a facts line (vertical); gap between a row's lines; gap between mitigation items; gap between a `dt` and its `dd` |
| sm | 8px | Row button padding (8px all round); notice padding (8px 16px); gap between notices; gap between the header's lines; badge inline-start padding after the bar; detail block gap; the supplier box padding (8px 16px) |
| md | 16px | Card padding; gap between cards; facts line horizontal gap; page inline padding under 680px container width; the detail's inline-start indent from the row's text (16px past the chevron column) |
| lg | 24px | Card padding from 870px container width up; space above the footer |
| xl | 32px | Page top padding; page inline padding from 680px up; the detail's inline-start offset from the card edge (8px row padding + 16px chevron + 8px gap) |
| 2xl | 48px | Page bottom padding |

Exceptions: none in the spacing scale. Fixed sizes and named non-spacing values follow.

| Item | Value |
|---|---|
| Buttons (See the controls, Check sovereignty again, Open the sovereignty card at this row) | 32px minimum height, padding 4px 16px; Theia and VS Code secondary button styles |
| Row button | at least 32px high (the content sets it; never a fixed height) |
| Minimum target | 24px by 24px everywhere (WCAG 2.5.8); links inside the detail get 4px vertical padding to reach it |
| Icon size | 16px (codicon default) |
| Page width | `max-width: 960px`, centred; nothing scrolls sideways from 320px up |

Named exceptions (not spacing tokens): 1px borders and dividers; the 2px focus outline with 2px offset; the 3px inline-start bar on state badges and notices (48.2 precedent). Radii: 12px cards (header card, group cards); 8px notices and the supplier box; 5px row buttons, buttons and selects. Shadow offsets and blurs (1, 2, 4, 8, 12 and 24px) are shadow geometry, listed under "Elevation".

### Checkboxes (owner, 2026-11-25)

The card, the badge and the filter have no checkbox: the card is read-only and the filter is a select. If a later edit adds one to any surface of this phase, it follows the owner's rule from 74.1 exactly: the box to the left of its label, centred vertically on the label's first line, an 8px gap, the whole row one `label` wrapping its `input`, each row at least 24px high, the box 16px by 16px:

```css
.sterling-sovereignty label:has(> input[type=checkbox]) { display: flex; align-items: center; gap: 8px; min-height: 24px; }
.sterling-sovereignty input[type=checkbox] { flex: none; width: 16px; height: 16px; margin: 0; }
.sterling-sovereignty label:has(> input[type=checkbox]) > input[type=checkbox] { align-self: flex-start; margin-top: calc((1lh - 16px) / 2); }
```

### Times

As 74.3 "Times" (owner-confirmed 2026-11-24): "25 Nov 2026 14:02 UTC", built from `Intl.DateTimeFormat('en-CA', { day: '2-digit', month: 'short', year: 'numeric', hour: '2-digit', minute: '2-digit', hourCycle: 'h23', timeZoneName: 'short' }).formatToParts(date)` joined in that order. Dates alone (a declaration's date, a recorded date) read "2 Nov 2026" and are formatted in UTC, so the desktop never reads a time zone to decide a fact (D-32: the zone appears only in a displayed time, never as an input to a judgement). Each time is a `time` element whose `datetime` holds the ISO value. Ages follow the time in brackets: "25 Nov 2026 12:01 UTC (2 hours ago)", with 48.2's age words.

## Copywriting Contract

Rules for every sentence: plain short words; the product is "SovAI" ("Sterling Sovereign AI" in long form); "your organization", never a provider name in front of "organization"; NEAR AI appears only as a provider ("NEAR AI Cloud", "NEAR AI private hardware"); no em-dash; straight apostrophes (the same strings feed both editions and their tests); never "compliant", "certified" or "accredited" as a claim; none of the phrases the 48.4-01 copy lint refuses (D-35), which this file deliberately does not spell out, so that 48.4-17's check finds none here; "Sovereignty" only as the badge and card name, always followed by a state word or "card"; never "Sovereign" as a verdict, "sovereignty score", "SEAL" or "sovereign region"; none of the glossary's restricted words on main screens ("attestation", "attested", "endpoint", "TEE", "passport", "tier", "hub", "profile", "issuer"); "Private" only for verified private hardware or this computer; dimension ids D1 to D14 never on screen; SA-400 and other control ids only in the detail's criterion block; no node, session or user counts and no capacity figure (48 D-09: a hardware disagreement says the numbers differ, never what they are); no sentence tells a person to update anything. Every button is a verb plus a noun. Placeholders in braces are filled by code. Example names, sites and times are fictional.

Where the words live: row titles, reasons, the badge, the allowed line, facts words, detail sentences, supplier and mitigation words in `src/domain/sovereignty/words.ts` (48.4-05), read by the lens and carried in the view; the card's own words (titles, scope, notices, footer, buttons, announcements, filter words) in `SOVEREIGNTY_TEXT` (`workbench/extension/src/common/sterling-sovereignty-view.ts`) for the workbench and in `CARD_TEXT` in `words.ts` for the desktop, kept equal by a test (P7).

## Security rules for the UI (checked in tests)

1. The browser and the desktop page script compute no state: they render the view (48.4-11 "never computes": the module imports no lens or engine code).
2. All view text is set with `textContent`; links are https only, to cyber.gc.ca or canada.ca for sources and to the documentation page for "How sovereignty is judged"; the desktop page keeps the extension's content security policy (T-48.4-36).
3. Paused means Unknown freshness everywhere until the next answer (T-48.4-33).
4. Nothing reads as Met without positive evidence (D-41); a planned mitigation never changes a row (D-47); "Not verified" never shows the state it would have outside the detail.
5. The desktop reads no locale, time zone or address (D-32, "no inference" test); dates are formatted in UTC.
6. No personal data beyond the declaration's `declaredBy` name and role; screening is a reference; the supplier's individual shareholder is never named.
