# Phase 33.1 Plan 17: Action-bound step-up Summary

A passkey confirmation signs exactly one action: the backend makes a nonce for each pending action, the nonce travels through the identity provider only inside the step-up's return path, the return request's own token is the only one ever bound, and the engine's one append path refuses any person-key kind that is not signed by the person signer, or that comes without its action id when it is a 33.1 kind.

## Registry as built (workbench/extension/src/node/staff/person-signer.ts)

| State | Enters by | Leaves by |
|---|---|---|
| pending | `beginAction(payload, summary)`: random action id, request id (to the browser) and nonce (into the step-up address only); stores SHA-256 of the payload and the summary; cancels every earlier action not yet resumed | bound (bindStepUp); expired at `min(PENDING_ACTION_MS = 120 s, the step-up window)` after it began; cancelled by a later beginAction |
| bound | `bindStepUp(nonce, token)` on the return route only: acr equals `STERLING_STEPUP_ACR`, auth_time later than the start and used by no other action, sub equals the sub the session became active with | resumed; expired at the window (`STERLING_STEPUP_MAX_AGE_SECONDS`) after the bind; cancelled by a later beginAction |
| resumed | `resumeAction(requestId, payload)` with the same payload: the action id handed out once, in one synchronous step | expired at the window after the bind |

`authorize(actionId)` is true only for a resumed, unexpired action whose bound auth_time is the latest sign-in's. `personSigner(keyService, publicKey, actions?)` refuses any action id `authorize` does not pass with KeyService's step-up sentence and fix, and signs bytes with no action id as 33-23 built it. Nothing in the registry is written to disk, the key store or a log; a backend restart drops every action.

Routes (`session-identity-backend-module.ts`, `ActionStepUpContribution`): `GET /sterling/step-up/:nonce` serves `actionSummaryPage` (the kind's fixed line from `ACTION_LINES`, then every value as a labelled, quoted field, dates formatted by the backend, the Continue link `stepUpUrl('/sterling/step-up/<nonce>/return', acr)`); `GET /sterling/step-up/:nonce/return` serves `actionReturnPage`, which binds the request's forwarded token only when it equals the token the person check accepted. Both pages: `no-store`, a CSP with `default-src 'none'` and `frame-ancestors 'none'`, no referrer.
