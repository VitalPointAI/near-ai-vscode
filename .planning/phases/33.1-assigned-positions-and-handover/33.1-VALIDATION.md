# Phase 33.1 validation

Use synthetic people, positions, devices, signing keys and work areas in isolated fixtures. Run focused checks after each task. Run the full affected host, extension and browser checks once at the phase boundary.

| Requirement | Acceptance evidence |
| --- | --- |
| POST-02, POST-03 | A signed authorized posting binds the person, position and effective period. Stale heads, expired delegation and scope expansion fail. Historic views retain the prior holder. |
| POST-04, POST-05 | The ordered assignee can prove their device, report for duty or report unable. Expired proof preserves the posting. Only the authorized recipient of the report sees the reason. |
| POST-06 | Two clients converge after handover, reconnect and replay. The holder and key epoch switch together. A stale outgoing protected action is refused and a changed roster forces restaging. |
| POST-07 | Acting and temporary postings preserve one effective holder. A dual-hatted person can switch positions. Each request and approval uses the active position and respects separation of duties. |
| POST-08 | Migration preserves effective grants and invitation flows. Protected workspace content clears on relief. Unscoped presence or private personnel detail never crosses the visibility boundary. |
