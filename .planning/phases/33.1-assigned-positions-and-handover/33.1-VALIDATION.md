# Phase 33.1: Validation Strategy

> Per-phase validation contract for feedback sampling during execution, for 24 plans in 12 waves. Codex's first version (2026-11-23) is replaced by this one for the native re-plan (33.1-CONTEXT.md, D-06 to D-25). Every test uses fictional people, positions, devices, keys and work areas in temporary stores and disposable containers.

`nyquist_compliant` stays false: every task has an automated check written first, but plan 12's container and Playwright run takes up to 2400 s, above the per-task latency target, and the wave 0 box stays open because each test file is created by its own task (tests first) rather than in a separate wave.

## Sampling Rate

- **After every task commit:** the task's own `<automated>` command.
- **After every wave:** every new test file of the wave, `copyLint.test.js`, `architecture.test.js`, `replicaBoundaries.test.js`, and the hub files when the wave touched `hub/`.
- **Blocking in every wave that touches them:** authorization (who may post, report, decide, delegate), the personnel privacy boundary, key changes at handover, migration parity, and the person-key rule.
- **Before `/gsd-verify-work`:** plan 12's full suites and container run green once.
- **Browser checks (D-08):** blocking only for the passkey on Report for duty, a relieved workspace losing its actions, and the private unable reason; the rest are diagnostic.
