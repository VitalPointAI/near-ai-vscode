<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Workspace/context → preflight | Potentially sensitive user data is classified before provider or network dispatch. |
| Preflight → provider/tool adapter | A dispatch token authorizes only the exact evaluated scope and provider boundary. |
| User override → policy gate | An explicit override can relax one decision but must not bypass emergency stop or audit requirements. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-04 | Information disclosure | privacy preflight | critical | mitigate | Classify/redact before dispatch, omit raw content from records, and test credential/private-file payloads. |
| T-04-05 | Tampering | sovereignty override | critical | mitigate | Bind one-time overrides to request scope/provider/path, consume once, and reject forged or replayed tokens. |
| T-04-06 | Elevation of privilege | policy gate | high | mitigate | Combine capability policy with privacy policy and make emergency stop a hard deny for every action. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; retain the phase package-legitimacy gate if an executor proposes a dependency. |
</threat_model>
