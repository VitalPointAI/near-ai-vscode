<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Agent/tool request → approval UI | Untrusted action details become a user decision surface. |
| Approval decision → dispatch | A decision authorizes only the exact preview scope and validity window. |
| Audit/resume store → restart | Durable records can influence future execution and must be non-executable by default. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-10 | Spoofing | approval decision | critical | mitigate | Bind decisions to request/preview IDs, scope, policy version, and expiry; reject stale or forged approvals. |
| T-04-11 | Elevation of privilege | resume path | critical | mitigate | Resume display state only; require fresh preflight, budget, and approval before dispatch, with no command replay. |
| T-04-12 | Information disclosure | audit/export | high | mitigate | Allowlist operational fields, redact secrets, bound records, and test export against credential/private-prompt fixtures. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; retain the phase package-legitimacy gate if an executor proposes a dependency. |
</threat_model>
