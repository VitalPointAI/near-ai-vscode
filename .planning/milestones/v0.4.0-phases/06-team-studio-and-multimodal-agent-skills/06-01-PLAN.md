<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Webview ↔ team-studio host | Untrusted form messages request operations; the host owns IDs, normalized contracts, storage, preview, and binding. |
| Global team library ↔ project workspace | A reusable version is copied by immutable reference into one explicit project binding; credentials and private workspace data do not cross. |
| Project binding ↔ agent orchestrator | A selected member contract becomes role/capability/provider/approval constraints for routing and deployment. |
| Imported/exported team package ↔ local storage | External JSON can tamper with authority, sensitive strings, versions, or limits before normalization. |

## Least-Privilege Constraints

- The team library stores only bounded non-sensitive composition metadata; it has no SecretStorage reader, prompt store, raw-context store, arbitrary path, or command executor.
- Stable IDs and immutable version numbers are authoritative; display names and imported labels cannot select credentials or override project scope.
- The webview may request list/preview/bind/import/export operations but cannot supply authoritative counts, cost, privacy decisions, approvals, or project attribution.
- Project invocation reuses `ProjectInitialization`, `PolicyGate`, `ApprovalService`, emergency stop, and profile attribution; team binding cannot bypass a fresh policy decision.
- Archive/delete operations affect library availability only and never remove project credentials, wallet files, or NEAR credential files.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-06-01 | Tampering | imported member contract | critical | mitigate | Versioned allowlists, bounded normalization, sensitive-field rejection, invalid-record isolation, and negative fixtures block added authority. |
| T-06-02 | Elevation of privilege | team bind/invoke | critical | mitigate | Require stable team/version IDs, explicit project binding, accepted-team rehydration, capability checks, policy gate, and fresh approval before dispatch. |
| T-06-03 | Information disclosure | team ledger/export/webview | high | mitigate | Store and emit only allowlisted operational facts; test credentials, prompts, context, commands, paths, and profile secrets are absent. |
| T-06-04 | Spoofing | display name/version selection | high | mitigate | Stable IDs, immutable version snapshots, project-bound references, and host-side lookup prevent labels from selecting another team or project. |
| T-06-05 | Denial of service | global team import/history | medium | mitigate | Bound team count, member count, version count, strings, package size, and atomic writes; reject malformed oversized packages before persistence. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; any executor-proposed dependency must pass the package-legitimacy gate before adoption. |

</threat_model>
