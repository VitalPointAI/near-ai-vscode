<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Workspace project identity → SecretStorage key namespace | A non-secret project scope selects which credential slot may be read. |
| SecretStorage → provider factory | Credential material is read only for the explicit active project/profile tuple. |
| Extension host → webview/status | Only allowlisted profile metadata and validation state cross the UI boundary. |
| Legacy global credential slot → migration adapter | Existing credentials are available only to an explicit, current-project import flow. |

## Least-Privilege Constraints

- The provider factory may read one credential slot for the active project/profile and may not enumerate or probe other slots.
- Profile metadata is not authority: stable profile IDs and the current project scope are required for every secret operation.
- No webview, workspace file, activity record, analytics DTO, log, error, or export receives API-key or refresh-token material.
- Legacy global secrets are migration-only inputs; the normal request path has no legacy fallback.
- No code path may access, alter, archive, or delete files under `~/.near-credentials`; NEAR credential files are outside this feature's storage boundary.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-05-01 | Elevation of privilege | scoped auth/provider factory | critical | mitigate | Require the explicit project/profile tuple, read one SecretStorage slot, require validated active state, and test cross-project/profile denial. |
| T-05-02 | Information disclosure | SecretStorage/webview/diagnostics | critical | mitigate | Keep key and refresh-token material in SecretStorage only; use metadata allowlists, redacted errors, and negative protocol/serialization tests. |
| T-05-03 | Spoofing | profile selection | high | mitigate | Stable IDs are authoritative, names are display-only, profile metadata is revalidated, and selection cannot be supplied by untrusted analytics/UI fields. |
| T-05-04 | Tampering | profile ledger and legacy migration | high | mitigate | Versioned bounded atomic persistence, explicit migration, stale-validation invalidation, malformed-record rejection, and no legacy dispatch fallback. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; retain the package-legitimacy gate if an executor proposes a dependency. |
</threat_model>
