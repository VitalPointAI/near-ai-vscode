<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Provider/session result → activity/audit ledgers | Usage and cost metadata becomes durable local operational data. |
| Activity/audit/reputation stores → analytics host | Bounded records are recomputed into attribution-aware summaries. |
| Analytics host → webview/export | User-visible and exported DTOs cross an untrusted presentation boundary. |
| Profile switch → in-flight request/approval | A later selection must not mutate the attribution or authorization of work already previewed/dispatched. |

## Least-Privilege Constraints

- Attribution is a host-derived snapshot of stable project/profile identifiers; the webview cannot choose the owner of a cost event.
- Analytics reads bounded ActivityStore/AuditStore/ReputationStore records and emits allowlisted DTOs only; it never asks SecretStorage for a credential.
- Profile display names and IDs are labels for filtering, not authorization selectors or secret lookup inputs in the analytics layer.
- Exports contain non-sensitive organization/project attribution and cost facts only; raw prompts, context, commands, paths, API keys, and refresh tokens are excluded.
- A profile switch affects only future requests after validation; in-flight and historical events retain their original snapshot.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-05-05 | Tampering | analytics/webview filters | high | mitigate | Host-side recomputation, strict filter schemas, bounded pagination, and rejection of forged profile/project/cost fields prevent user-supplied attribution. |
| T-05-06 | Information disclosure | activity/audit/analytics/export | critical | mitigate | Allowlisted attribution DTOs, redaction, bounded persistence, legacy normalization, and negative export tests exclude credentials and private context. |
| T-05-07 | Repudiation | profile switching and lifecycle records | high | mitigate | Snapshot profile/project identity at request start and preserve it through approval, reconciliation, terminal events, reload, and audit timeline. |
| T-05-08 | Denial of service | cost attribution and reconciliation | medium | mitigate | Bound event/query/export sizes, preserve cancellation-aware provider behavior, and avoid unbounded reconciliation or analytics fan-out. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installation is planned; retain the package-legitimacy gate if an executor proposes a dependency. |
</threat_model>
