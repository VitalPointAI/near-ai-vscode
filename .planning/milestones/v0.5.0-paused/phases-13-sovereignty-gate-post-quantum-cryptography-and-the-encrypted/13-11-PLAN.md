## Decisions (Claude's discretion: wording and screens)

- **No KDF in activation (Pitfall 4):** activation only resolves the mode; the base is opened lazily on the first KB chat send, a status-bar click, or a KB command.
- **Create flow order (D-02):** empty folder -> passphrase twice -> kbId + identity (progress notification) -> phrase shown in a modal message with numbered words and no copy button -> 3 random word positions re-entered (3 attempts, then abort) -> export save dialog defaulting to `~/near-ai-kb-<fp8>.kbkey`, rejecting any path inside a workspace folder or the new base -> write, read back, compare fingerprint -> only then `KbLog.create`, `.planning/.near-ai/` (so the extension's activation event fires in the new folder), `KbModeStore.register` (webSearchFetch true, egress off) -> open the folder. An identity marker for an aborted kbId is harmless (the kbId is never used).
- **Locked screen copy:** `This knowledge base is locked: <reason>. Your key was not changed and no new key will be made.` with exactly the buttons `Retry` and `Restore from recovery export`.
- **Tamper copy:** `This knowledge base failed verification and is read-only up to the last verified point. <first failure summary>.` with `Show report`; the report is an untitled markdown document built from `reportSummary()` (kinds, files, segment ids, sequence numbers; never entry content) plus "Restore a good copy of .near-kb/log from a backup, then choose Retry." and, when every failure is a tail truncation against the high-water mark, `Accept this older copy` (recorded via `KbModeStore.acceptRollback`).
- **Unreconciled (another machine, genesis without record):** refuse turns; offer `Restore from recovery export`, which verifies the genesis owner fingerprint equals the restored identity, then registers the record from the genesis and adopts the path.
- **Read-only base:** chat turns are allowed with a notice (models are still gated); base writes are refused.
