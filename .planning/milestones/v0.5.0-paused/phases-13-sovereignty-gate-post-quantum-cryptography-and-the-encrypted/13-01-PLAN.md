## Decision records (one-way doors, adopted autonomously per owner instruction; review post hoc)

- **DR-13-01 Library (one-way for the bundle surface, costly to change):** `@noble/post-quantum` 0.7.1 exact pin with `@noble/curves` 2.4.0, `@noble/hashes` 2.4.0, `@scure/bip39` 2.4.0, bundled by esbuild to `vendor/pq/pq.cjs`. Self-audited, not constant-time (documented limitation). `age-encryption` not adopted (older noble pin, second copy, unneeded file format).
- **DR-13-02 Hybrid signature composition (one-way):** signature bytes = Ed25519(64 B) || ML-DSA-65(3,309 B) = 3,373 B, both over `M' = "near-ai-kb/sig/v1\0" || u32be(len(label)) || label || SHA-256(bytes)`; ML-DSA-65 also receives `context = utf8(label)`. Verification is AND. Suite `s1` hash is SHA-256 (the research prototype used SHA-512; regenerate any KAT with SHA-256).
- **DR-13-03 Key wrap record (one-way for existing wraps):** `alg: "xwing-v1"`; `{cipherText, sharedSecret} = ml_kem768_x25519.encapsulate(pk)`; KEK = HKDF-SHA-256(ikm=sharedSecret, salt="near-ai-kb/keywrap/v1", info=context, 32); AES-256-GCM(KEK, 12-byte random nonce, key, AAD=utf8(context)). Context string format is `${kbId}|${compartmentId}|${epoch}`.
- **DR-13-04 Security level (one-way per suite):** ML-DSA-65 (NIST category 3) to match ML-KEM-768 (assumption A1; the suite id lets new segments move later).
