## Decisions and assumptions

- **Gate policy (reversible behind the interface):** `SovereigntyPolicy = { mode: 'standard' } | { mode: 'tee-only' } | { mode: 'kb'; kbId: string }`. Standard: no wrapping. tee-only and kb: allow only catalog `privacyBoundary === 'tee'` from a client whose endpoint is the declared NEAR host `https://cloud-api.near.ai` (any path), or a model served by a client whose endpoint is loopback. kb additionally refuses ambiguous rows and runs the attestation cadence. tee-only keeps today's TEE labelling for ambiguous rows (no behaviour change for standard-project users beyond enforcing their own tee-only choice).
- **OQ7 resolved (assumption):** a catalog row with `attestationSupported: true`, a non-external provider type, and a `providerConfig.base_url` whose host is not under `near.ai` (live example `moonshotai/kimi-k2.6` via openrouter.ai) is marked `privacyAmbiguous: true` and refused in KB mode until the owner rules on it.
- **OQ5 resolved (assumption):** the loopback predicate classifies unix-socket endpoints (`unix:/abs/path` and `http+unix://` forms) as local per D-12; no unix-socket transport is added in this phase (profiles cannot be configured with one today), recorded for a follow-up.
- **A14 cadence (assumption, tunable constants):** verify the first response per model per session, then every 10th response or after 10 minutes.
- **A16 (assumption):** `localhost` is accepted as loopback alongside IP literals.
- **Rerank endpoint (assumption):** `rerank` posts `{ model, query, documents }` to `/rerank` (vLLM/Cohere-compatible shape, provider type vllm in the live catalog); Phase 14 confirms the live route before relying on it. `embed` posts `{ model, input }` to `/embeddings` (OpenAI-compatible).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extension host -> NEAR AI Cloud | prompts, attachments and embeddings leave the machine |
| extension host -> local runtime endpoint | a "local" endpoint might be on the LAN or remote |
| NEAR catalog -> gate | privacy flags come from the endpoint being gated |

| T-13-09 | Information disclosure | any NearAiClient model-calling method | critical | mitigate | TeeGatedClient gates all nine methods; reflection test fails on an unclassified method; behaviour tests assert zero requests on refusal (Task 2) |
| T-13-10 | Spoofing | custom baseUrl self-declaring TEE, LAN "local" runtime | high | mitigate | cloud allowed only for https://cloud-api.near.ai; local allowed only for loopback endpoints regardless of the model label (Task 1) |

| T-13-12 | Spoofing | mid-session attestation failure | high | mitigate | first-then-cadence verifyResponse in KB, 'failed' latches the model (Task 2) |
