## DR-13-07 Envelope freeze decision record (one-way; adopted autonomously per owner instruction, flagged for post-hoc owner review)

Adopted from RESEARCH.md Pattern 5 with the owner's open questions resolved by the research recommendations:

| Element | Frozen decision |
|---------|-----------------|
| Encoding | canonical JSON subset from src/kb/crypto/canonical.ts (UTF-8, keys sorted by UTF-16 code unit, no whitespace, safe integers only, no lone surrogates); hash the exact stored bytes and require re-canonicalisation to equal them |
| Suite | `s1` = { aead: aes-256-gcm, kdf: hkdf-sha256, sig: ed25519+ml-dsa-65, kem: x-wing, hash: sha-256 }, named in every header and the genesis |
| Genesis (`.near-kb/genesis.json`) | file = canonical `{ genesis, sig }` where genesis = `{ v: 1, kbId, createdAt, suite: 's1', owner: { ed25519, mlDsa65, xwing (base64), fingerprint }, compartments: [{ id }] }` and sig = base64 hybrid signature with label `genesis` over canonicalBytes(genesis); genesisHash = SHA-256 hex of canonicalBytes(genesis) |
| Compartment (OQ1/A5) | opaque random 128-bit id (32 lowercase hex) in cleartext headers and entries, field name `c` in entries and `compartment` in headers; the human label is stored only in an encrypted `compartment.define { id, label }` entry, the first entry of the first segment |
| Key epoch | integer >= 1; this phase writes epoch 1; `.near-kb/keyring/<compartment>/epoch-<n>.keywrap` holds the canonical KeyWrapRecord of CEK_n wrapped to the owner with context `${kbId}|${compartment}|${n}` |
| Segment file | bytes = magic `NKBS` (4) + format byte 0x01 + u32be headerLen + header bytes + u32be ctLen + ciphertext (includes the 16-byte GCM tag at the end) + u32be sigLen + hybrid signature; caps: header <= 64 KiB, ciphertext <= 64 MiB, entries <= 65,536 |
| Segment header | `{ v: 1, kb, compartment, epoch, author (fingerprint), seq: [first, last], count, prevSeg (segId of this author's previous segment, or the genesisHash for the first), heads ({} in Phase 13; version vector reserved for Phase 19), hlc: [[minWall, minCtr], [maxWall, maxCtr]], comp ('gzip' or 'none'), segId (random 128-bit hex), nonce (96-bit base64), ctHash (SHA-256 hex of ciphertext), suite: 's1' }` |
| Segment key and AAD | key = HKDF-SHA-256(CEK_epoch, salt = utf8(kbId), info = "near-ai-kb/seg/v1|" + segId, 32); AAD = canonicalBytes(header without ctHash) |
| Segment signature | hybrid signature with label `segment` over canonicalBytes(full header including ctHash), i.e. M' binds SHA-256(header bytes); one signature per sealed batch (per-segment, not a hash tree: 3,373 B, ~7 ms verify) |
| Entry | `{ v: 1, id, c, e, a, n, prev, hlc: [wallMs, counter], t, occ?, rep?, gr?, item?, body, payload? }`; id = SHA-256 hex of canonicalBytes(entry without id); prev = id of this author's previous entry, or genesisHash for the author's first entry; n starts at 1 and increments by 1 per author |
| occurredAt (`occ`) | `{ from: int ms UTC, to?: int ms UTC inclusive, prec: 'year' | 'month' | 'day' | 'hour' | 'minute' | 'second' | 'ms' }`; absent = unknown; "March 2026" = from 2026-03-01T00:00:00.000Z, to 2026-03-31T23:59:59.999Z, prec month |
| reportedAt (`rep`), gradedAt (`gr`) | optional int ms UTC; gradedAt only on grade entries (Phase 16); recordedAt is the HLC on every entry |
| Total order | (hlc.wallMs, hlc.counter, author, n); entries whose HLC wallMs is more than 5 minutes ahead of the local clock are rejected at append |
| Item ids | random 128-bit hex, never derived from content; `item = { id, kind: 'claim' | 'source' | 'attachment' }` |
| Item payload (D-13) | `payload = { nonce, ct }` (base64) = AES-256-GCM(itemKey, nonce, canonicalBytes(content), AAD = utf8("near-ai-kb/item/v1|" + kbId + "|" + c + "|" + item.id + "|" + t + "|" + a + "|" + n)); AAD uses author and n rather than the entry id, which is computed over the payload; item keys live outside the log in `.near-kb/keys/items.vault` (plan 13-09) |
| Tombstone (D-14, OQ2/A6) | `t: 'item.erase'`, body `{ by, at, reason }`, `item` set; the erased item's own entries keep their skeleton (id, c, e, a, n, prev, hlc, t, item, occ, rep, gr) so as-of views keep ordering; content, title and places exist only in the payload |
| Entry types in Phase 13 | `compartment.define`, `item.put`, `item.erase`; any other `t` is preserved in history as unknown, never dropped |
| Plaintext of a segment | canonicalBytes of the array of entry objects in append order, then gzip when comp is 'gzip' (default) |
| File naming and no-clobber | `log/<compartment>/<author first 8 hex>-<seqFirst zero-padded to 12>.seg`; write `<name>.tmp-<pid>-<random>` with flag 'wx' and mode 0600, fsync, `fs.link(tmp, final)` (EEXIST -> error), unlink tmp |
| Single writer | `.near-kb/.lock` = `{ pid, host, startedAt, heartbeatAt }`, heartbeat every 10 s, stale after 60 s; a second writer opens read-only |
| Git hygiene (OQ3/A4) | the log lives in the workspace `.near-kb/` (travels across WSL/code-server, can be committed as ciphertext); `.near-kb/.gitignore` contains `keys/` and `.lock` so erasable item keys never enter git history |
| Versioning | readers reject `v` above what they support with an `unknown-version` error (read-only); fields are only added via a `v` bump |
