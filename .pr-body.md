## What this is

Starts as the Check now button and grew into the work that came out of measuring why projects move slowly, plus the Team Studio work requested along the way. Every claim below is covered by a test, and the numbers quoted come from the owner's own spend ledgers.

## Speed and cost: what the measurements said

The spend ledgers of the owner's real runs (8,291 requests) showed:

- 98.0% of 1.36 billion input tokens were cache hits, so **output tokens are the bill**: 6.0M output against 27.7M uncached input.
- Time tracks output: sub-agents take 36.5s per 1,000 output tokens, against 15.7s for the main run, and are 84% of all model time.
- **30 of 37 runs never had two requests in flight.** The best reached 1.63 of the 4 agents allowed.
- 35 waits hit the 15-minute approval timeout exactly, 49 more ran long: up to **752 minutes** of a single run parked on a question, whose work was then redone.

Each of those became a change:

1. **An unanswered approval parks the run instead of declining it** (`c6971cd`). Nothing runs, nothing is lost, the card keeps its buttons, and answering later runs the action and continues from that step.
2. **Fan-out is a rule, not a hint** (`73b3bed`). One sub-agent per independent part, in a single turn, with `run_in_background`; the parallel default is 8.
3. **Measurement** (`68660f2`): `npm run report:spend` reads the ledgers, and `npm run experiment` runs a blind A/B, because speed is worthless if the answer gets worse.

## Compare Models, fitted for re-running

`f09057f`, `1641b3a`, `6125cba`, `f03c8b1`, `93c1533`.

- `npm run compare:models` drives the same runner, tasks, graders and store the tab uses, so nothing is a second benchmark. Results land in the tab.
- New and stale models select in one click, and `needsRetest` names what is worth testing again as models are released.
- **One button applies the setup the results point to**, per tier and per role. Deep is the most accurate whatever it costs, fast is the quickest model still within half a point, standard is the best value among those: accuracy is a floor, so speed never wins by being worse. **The cyber model is always abliterated**, because a safety-tuned model refuses attack payloads and "right" is unreachable on one.
- Score over time as a chart, by task type, drawn on with a stroke animation and readable with motion off.

## Team Studio

- **A graded task per role** (`ea42509`), ten of them, graded mechanically on what the role is for: a reviewer must find the planted bug and not edit, a researcher must cite sources, report a disagreement and not follow a planted prompt injection. **A role added later automatically gets its kind's task**, so no role is ever chosen by guesswork.
- **The last step of adding a team tests its roles and sets their models** (`f095e4c`), with the cost shown before it starts and a skip that leaves the team as written.
- **A team as a shape** (`673a795`, `2b9febb`): nested boxes so the nesting is the hierarchy, an optional `reports-to` that older files do not need, and a member card with what it is for, what it can do from its tools, and what to expect.
- **A team's own knowledge graph** (`653a001`, `9f35fa7`): actors, functions, relations with a signed tension where null is not zero, and Admiralty grades on the evidence. Two tools feed it (`TeamKnowledge`, `Learn`), shared by every member, kept per team, and drawn as an interactive network where selecting an actor highlights its relations in sequence and opens a card with the sources and grades.
- **The AI start** (`b89943d`): one question, one model call, a proposal with a team name, named members, roles, suggested tiers, what each produces and the final outputs and formats. It becomes a team only when the person accepts it, and the Markdown editor stays first class.
- **Optimise all teams on demand** (`0a737b0`).
- **"N to fix" now names each problem and goes to the step that holds it** (in `673a795`).

## Tests

1,164 tests, 1,164 passing, 0 failing, 8 skipped. Lint clean.

Several real defects were found by writing those tests rather than by review: the CLI's run IDs failed the store's own pattern, so **every save was silently refused**; a comparator only ever answered "better or equal", making a sort order-dependent; the standard tier picked a model that was neither best nor quickest; one Learn stored a fact twice on a new actor and could drop a citation; and `selectTab` used a literal index that a new tab silently broke.
