## What and why

Three defects in the cybersecurity sandbox and run engine, split out of #10 so they ship without the review-gate work that PR also carries.

1. **A payload gets its own deadline.** The runner every production `docker exec` used carried the version check's **three-second** timeout, so an exploit or access-proof command taking longer was killed and reported as a failed exploit. Exec now uses the sandbox's own `execTimeoutMs` (120 s), hoisted once per sandbox rather than rebuilt per command.

2. **Stop still works.** Raising that deadline would have raised the stop bound with it, because `exec` accepted a signal but never passed it to `execFile`. The runner now takes the signal and reports an abort as the stop control rather than a failed command.

3. **A stopped run keeps its findings.** The stopped, budget-exhausted and rate-limited exits returned before the loop that writes findings to the append-only ledger, so findings collected before the stop were absent from the chain and invisible to replay. One finaliser now runs on every exit path.

Also fixes the first planner call, which passed an empty remaining-checks list. `planPrompt` reads empty as "every check has run, reply done", so every run's opening plan was a wasted model call refused as an unknown tool.

**User-visible effect:** a long step now finishes instead of being cut off at three seconds, and stopping still interrupts it immediately. The CHANGELOG says so.

No version bump: this is a fix, and 0.4.14 shipped with #8.
